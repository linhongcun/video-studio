## 先看清量水规则 {#goal}

只有两个容量分别为**3升、5升**的壶，都没有刻度，开始都是空的。水源不限，也允许把水倒掉。怎样安排，才能让**5升壶内恰好有4升水**？3升壶里有没有水都可以。

每次只允许一种完整操作：[^source]

- 装满其中一壶，不能只从水源接入自己估计的一部分。
- 倒空其中一壶。
- 从一壶向另一壶倒水，直到**倒出者空了，或接收者满了**才停。

不能凭目测在中途停下，也不用第三个容器储水。图中的当前水量是根据已经完成的操作推算出来的，数字不代表壶上多出了刻度。

本文用“小壶”表示3升壶，“大壶”表示5升壶。状态`(小壶水量，大壶水量)`中的数字单位都是升，例如`(3,2)`表示小壶有3升、大壶有2升。

视频先从题意推导操作，再连续演示一条可行路线。完整状态模型和最少操作数的核验单独放在本文后部，不属于视频章节。

## 用容量差留下两升 {#two}

直接装满一壶，只会得到3升或5升，都不是4升。可利用的信息是两个已知容量：**5减3，可以留下确定的2升**。这个余量由“小壶装满”确定，不需要目测。

所以先做两步：

| 操作 | 完成后的状态 | 为什么能知道水量 |
|---|---|---|
| 1. 装满大壶 | `(0,5)` | 大壶装到容量边界5升 |
| 2. 大壶向小壶倒，直到小壶满 | `(3,2)` | 小壶接走3升，大壶剩5−3＝2升 |

第二步转移3升，两个壶的总水量始终是5升。**停止的原因是小壶满了**，大壶剩2升是由这个停点推出来的结果。

## 留两升，造一升空位 {#gap}

得到2升以后，再回到目标：大壶如果先装满5升，只要能准确倒走1升，就会剩4升。

怎样接走准确的1升？小壶容量是3升，如果里面已经放着刚才得到的2升，就只剩下`3−2＝1升`空位。它一装满，便能确定接走了1升。

这解释了为什么要保存那2升。现在的实际状态却是`(3,2)`：小壶已经满了，2升还在大壶中。要把它放到小壶，先得腾出位置：

| 操作 | 完成后的状态 | 为什么要这样做 |
|---|---|---|
| 3. 倒空小壶，大壶里的2升保留 | `(0,2)` | 给已知的2升腾出位置 |
| 4. 把大壶余水全部倒进小壶 | `(2,0)` | 小壶留下2升，形成1升空位 |

第四步转移2升，**因为倒出者大壶空了而停**。此时小壶只有2升，没有装满，仍然是合法停点；不能把它解释成“看水位到2升就停”。

现在两升水已经完整地转存到小壶，它的空位才真正成为确定的1升。前面的计划没有提前改变实际水量。

## 五升倒出一升，留下四升 {#four}

保留小壶里的2升，接着完成目标：

| 操作 | 完成后的状态 | 为什么能准确留下4升 |
|---|---|---|
| 5. 重新装满大壶 | `(2,5)` | 大壶有5升，小壶仍有2升 |
| 6. 大壶向小壶倒，直到小壶满 | `(3,4)` | 小壶只接得下1升，大壶剩5−1＝4升 |

最后一步转移1升，小壶从2升变成3升，大壶同时从5升变成4升。**触发停止的是小壶满了**，不是凭目测让大壶降到某条4升线。

把思路串起来，就是：

```text
5 − 3 = 2升余量
3 − 2 = 1升空位
5 − 1 = 4升结果
```

完整路线为：

```text
(0,0) → (0,5) → (3,2) → (0,2) → (2,0) → (2,5) → (3,4)
```

终态小壶有3升、大壶有4升，符合本题要求。两次装满大壶一共取水10升，倒空小壶排出3升，最后两壶合计7升：`0＋10−3＝7`。三次互倒分别转移3、2、1升，只改变水所在的壶，不改变两壶总水量。**大壶有4升与两壶合计4升，是不同目标。**

## 这条路线的六步怎样做完整核验 {#optimality}

上面已经给出六步可行路线。若进一步问“在这些规则下，有没有更少操作的办法”，就需要比较所有合法安排。这里每次完整装满、倒空或互倒记1步；优化的是操作次数，不是时间或用水量。

### 为什么有限状态包含了全部可能

设状态为`(a,b)`，分别记录小壶和大壶的水量。初始为`(0,0)`。装满得到整数容量，倒空得到0；互倒时，转移量是“倒出者现有水量”和“接收者剩余空间”中较小的一个。因此从整数水量出发，后续仍是整数。

所以所有可出现的状态都在`a＝0…3，b＝0…5`的24个整数对中。这不是用整数采样近似允许随意停手的连续问题；题目规定的完整操作本来就保留整数水量。

从任一状态枚举六种动作：装满小壶、装满大壶、倒空小壶、倒空大壶，以及两个方向的互倒。互倒的转移量分别是：

```text
小壶 → 大壶：t = min(a, 5 − b)，新状态(a − t, b + t)
大壶 → 小壶：t = min(b, 3 − a)，新状态(a + t, b − t)
```

给满壶继续加水、倒空空壶等操作不改变状态。删掉这类原地操作，不会破坏一条可行路线，只会减少无效步骤；它们不能帮助得到更短路线。

任一次有效操作完成时，至少有一壶为空或满。完整构图从初态可达16个边界状态，其余8个内部整数点不可达。这个可达子图共有58条非原地有向操作；若把全部24个整数状态都算进去，则有106条非原地操作，不能把两个范围的计数混用。

### 按操作数逐层比较

[本期数学核验程序](https://github.com/linhongcun/video-studio/blob/main/episodes-codex/water-jug/verify_math.py)从初态进行广度优先搜索（BFS）：第一层列出一次操作能到达的状态，下一层继续枚举全部合法动作，只保留尚未更早出现的状态。每条边都计1步，因此状态首次出现的层数就是最少操作数。

下面列出全部16个可达状态及其首次层数φ，也作为可单独审查的下界证书：

| 小壶水量a | 大壶水量b | 首次层数φ |
|---:|---:|---:|
| 0 | 0 | 0 |
| 0 | 1 | 6 |
| 0 | 2 | 3 |
| 0 | 3 | 2 |
| 0 | 4 | 7 |
| 0 | 5 | 1 |
| 1 | 0 | 5 |
| 1 | 5 | 4 |
| 2 | 0 | 4 |
| 2 | 5 | 5 |
| 3 | 0 | 1 |
| 3 | 1 | 7 |
| 3 | 2 | 2 |
| 3 | 3 | 3 |
| 3 | 4 | 6 |
| 3 | 5 | 2 |

目标是`b＝4`。可达目标只有`(3,4)`和`(0,4)`，首次层数分别是6和7；0到5层没有满足目标的状态。

也可以逐边检查，而不只相信算法名称。[完整核验报告](https://github.com/linhongcun/video-studio/blob/main/episodes-codex/water-jug/qa-math.json)中的58条可达合法操作都满足：

```text
φ(下一状态) ≤ φ(当前状态) + 1
即：1步 ≥ φ(下一状态) − φ(当前状态)
```

沿任意初态到目标的路线把这些不等式相加，中间状态的φ相互抵消：

```text
总步数 ≥ φ(终态) − φ(初态) ≥ 6 − 0 = 6
```

因此任何合法路线都至少需要6步；前文的六步可行路线又说明6步确实能做到，上界与下界相同。

程序还独立检查24个状态×6种动作共144个状态动作对：公式转移与“逐升模拟到合法停点”的另一实现全部一致，并用另一实现构图后的Floyd–Warshall结果交叉核对BFS距离。逐升模拟只是程序内部的独立核验方式，**没有给实际题目增加“每次倒1升就能停”的能力**。运行时间、源码SHA、水量账和证书均保留在上述报告中。

## 与LC365的“两壶合计四升”有什么区别 {#lc365}

本期目标是5升壶内有4升，所以到`(3,4)`就完成了，不需要把小壶再倒空。

实际读取的doocs第三方公开题面镜像，采用“两壶水量合计达到target”的表述。它的3升、5升、目标4升例子，在上述六步之后还做第七步：倒空小壶，从`(3,4)`变成`(0,4)`，此时合计才是4升。[^source]

在完整可达图中，合计4升的目标状态是`(0,4)`和`(3,1)`，两者首次层数都为7，所以这个不同目标的最少操作数是7。不能用本期的六步终态去满足它，也不能把它的第七步反过来当成本题的必要步骤。
