# 视觉与叙事

- 不可变Kafka style-v1，暖炭灰、橙色强调、冰蓝辅助；读取既有字体与Kafka身份。首镜为两个业务功能的事件接收列表，立即指出都需四条但各只收到两条，不额外套应用窗。
- 用同一组保留日志：orders，P0的E01/E03与P1的E02/E04。记录原位保持，沿读取路径移动的是副本。左右/上下布局稳定，不在镜间交换组身份。
- 三个独立对照：误用同组；两个业务各独立组；通知组内两个实例。05与08显式回共同前提：同四条保留记录，从分区开头读取。切换不是自动回退消费进度。
- 组框表示逻辑消费组，实例内列实际收到事件。P0/P1归属明确，稳定同组每个分区只给一个实例；通知组总集合为4时，不能让每个实例都显示4。积分组始终独立。
- 每镜先有对象，再让路径和事件副本解释动作；数字显示已收到事件数，不标已完成业务。不同分区没有全局业务顺序承诺。
- 结尾回收“不同业务各自完整订阅，用不同组；同一业务实例在组内分区分工”。正文后5秒同色参考资料简表，只显示原题及机构。
- 正式编码前检真实配音时序下的连续小样、跨镜与中间态；编码后再按实际MP4检查，记录无法执行的语音和设备能力。
