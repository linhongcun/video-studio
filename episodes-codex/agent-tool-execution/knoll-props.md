# EP.28 / A02 制作说明

唯一问题：模型提出的工具调用请求，怎样变成应用程序真正执行的订单查询？正文11镜22句，一次有权限查询、一次新用户新会话的权限拒绝，片尾用真实执行记录回扣。当前制作状态与实际帧数见README及最终QA，本文不预写通过。

首屏直接显示退款咨询功能和完整用户问题“帮我查一下，这单签收几天了？”，助手准备查询8124，订单系统尚未收到。标明暂停在调用请求刚生成这一刻，避免把正常交接画成系统故障。遮住技术题名仍能识别使用场景。

02回到开始，程序提供问题和工具说明。内部干净canvas固定模型左、咨询应用的程序中、订单系统右。03只有工具名和订单号，04在程序内检查后，05才向系统真正发请求。系统返回签收3天先到程序，06再以同一调用标识交回模型，07回到对话答复。原始资料不跨过程序，也不提前出现在请求中。

08明确另一次演示、新用户B、新会话，清空此前数据与本次请求计数。先收回稀疏全局定位再聚焦检查；09没有出站请求、系统计数为0，10仅应用生成的拒绝回到模型和新对话。两个情景不是同一请求发生两个相反结局。

术语首现按句首声学cue：02模型、03工具调用请求、04应用程序，至少完整显示63帧。配音冰糖、正常语速；每镜两句，真实整轨从0帧播放，字幕逐字相同。只复用共享装配、起音和混音，不复制算法。

正文代码只在03工具名/参数对应处；06仅视觉关联标记，不另加JSON大屏。深色页身引用共享主题；字幕和水印在机制层外，无装饰进度条。封面依covers.json的尺寸与4:3安全区实际渲染检查。
