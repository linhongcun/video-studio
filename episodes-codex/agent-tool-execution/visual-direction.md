# A02 视觉方向

先建立功能，再解释内部：首帧完整退款咨询和用户目标，遮住题名仍能认出在询问订单签收时间。助手“准备查询”只是一项待交接状态，标明停在请求刚生成，不显示故障。

02明确回到查询开始。内部机制使用干净深色canvas，模型左、咨询应用的程序中、订单系统右，各位置稳定。同一请求与同一订单实体在角色之间移动，不能复制两份同值交叉淡入。咨询应用边界与外部订单系统可辨，模型不是程序的另一个名字。

模型先得到问题及工具说明；调用请求只有工具名和参数。04检查工具/参数/当前用户读取权限依次发生，05才发真正HTTP请求。签收3天的事实必须在实际查询完成后出现，结果先回程序再回模型，07最后回到原用户对话。请求与结果使用同一调用关联标记，画面先中文后代码，不堆协议字段。

08清楚显示“另一次演示 · 新用户B · 新会话”，回到检查前提，清空成功事实及本次HTTP计数。稀疏全局请求→检查→执行→结果用来定位，随后聚焦权限拒绝。09应用拦截无出站调用，订单系统本次收到0次；10失败从应用生成，不能从订单系统返回。新对话没有上次的签收3天。

11兑现开头，强调调用请求≠执行结果：本例是自定义只读查询，实际执行由咨询应用程序负责。用刚才成功1次/权限拒绝0次的记录确认，不引入退款执行。

真实音轨后先检查01–03场景入口与回看、04–07完整执行返回、08–10重置与拒绝的无字幕连续过程。每项动作有开始/途中/到达/停留，状态在真实到达点改变。字幕与水印固定在机制层外，不添加与教学无关的持续进度条。
