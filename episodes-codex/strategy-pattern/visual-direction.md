# 策略模式：视觉主线与动作设计

## 本期问题

活动优惠八折改七五折，为什么要打开同时包含普通价、会员价的结算函数？同一笔原价100元的教学订单贯穿，最后让观众沿“调用方选择 → 结算接收函数 → 规则计算 → 返回金额”找到真实职责。

## 画面约定

- 深色干净1920×1080 canvas，背景与文字引用共享 `pageBg/pageInk`。首帧已有结算结构、标题与变更请求，没有片头、黑场、生活比喻、假应用窗口。
- 同一对象保持位置：07起调用方在左，结算居中，独立规则在右。算法身份由名称和位置共同表达；青色为当前被调用规则，金色为选择/改动，蓝色为输入或新客扩展，不用颜色单独承载意义。
- 只有03和14两处代码。03是旧函数内具体分支摘录；14显示 `demo/snapshots/after.py` 的真实结算核心（包含输入与结果校验）以及单参数 `select_rule("campaign")` 的调用。片中为核心摘录，完整程序与舍入、选择注册等在文章。
- 06第一句句首按共享声学起音显示“策略模式”首标签，其他镜头先用订单、规则和调用动作建立对象含义。
- 不加章节短横条、全片增长线或其他装饰进度条；顶部只保留静态当前章节和示例说明。

## 镜头因果

| 镜号 | 要看见的动作与结果 |
|---|---|
| 01 | 八折改七五折的变更请求在首帧上方固定出现，活动分支高亮，随后框出整个旧结算修改范围；请求不跨过其他规则文字。 |
| 02 | 明确回看最初版本；100元输入沿原价路径走到100元结果。 |
| 03 | 会员、活动分支随需求进入旧函数；各次重新选择，不把三次价格串成连续折扣。 |
| 04 | 三块原有算法从结算边界内逐个沿连续轨迹移到外部规则区，结算边界收拢并保留调用位置。 |
| 05 | 各条规则轮流接收相同100元并返回各自结果，回收共同输入/输出约定。 |
| 06 | 规则分开、统一委托线建立；本例函数实现，无大类图。 |
| 07 | 调用方选中会员并将函数引用交给结算，保留选择者。 |
| 08 | 100元先进入结算，再沿唯一选中路径送往会员，普通和活动保持未执行。 |
| 09 | 会员内显出100×90%=90，90元沿独立返回路线回到应付金额位置。移动标签在接收口外侧淡出，路径仍接入；落点更新后不保留“等待返回”叠字。 |
| 10 | 先清空上一结果并提示重置同一100元，改选活动，再得到80元。 |
| 11 | 活动计算体80%改75%时只标该规则；重新输入100，返回75。结算和会员不标修改。 |
| 12 | 对照旧函数与独立活动实现的本次修改范围；共同约定及选择/注册责任仍保留。 |
| 13 | 出现新客函数后，调用方才加入新可选项；两处新增明确高亮，随后单独计算100−10=90。四规则布局避开组标题。 |
| 14 | 先聚焦 `pricing(total_cents)`，再沿调用实参和函数参数追到实际选择。代码可暂停阅读。 |
| 15 | 先看简单稳定判断，再看算法分别变化；展示额外调用跳转，说明间接层成本。 |
| 16 | 回到同一稀疏结构回收选择、调用、返回，停在“选择在外，计算独立”。 |

## 时序与检查

`motion.ts` 根据真实 `storyboard.json` 的句首帧计算动作比例；根配音/装配负责这些真实边界。本期预演脚本记录是否临时时序、生产源码SHA、最终字幕参数与每个采样的绝对帧。临时placeholder只供早期构图，不可当真实配音验收。

关键检查包括规则拆出的中间态、输入只走选中路线、返回金额不叠字、换规则前明确重置、活动修改范围、新客注册前后，以及代码与完整示例一致。静态采样和连续片各有用途；最终编码仍需从实际MP4抽帧复核，不能以渲染成功替代观众是否理解。
