# 策略模式新手版：视觉主线

2026-10-25（北京时间）。同一件结算任务，怎样替换计算办法？13镜只保留会员九折与活动八折，原金额均为100元；两次独立结算分别得到90元和80元。

## 稳定身份与层次

- 深色1920×1080 canvas，沿用共享页身色。首帧直接给出同一结算怎样换算价办法的具体问题，无片头、黑场、比喻或假应用窗。
- 逐步引入原金额、结算、当前函数、应付结果。函数用名称和青色，输入为蓝色，结果为金色且带金额单位；不靠颜色单独传达含义。
- 选择在调用处明确展示，不常驻独立调用方大框。不并排铺三四套完整算法、契约和多类路径。未选办法只保留短名称。
- 先03建立会员函数与其输入输出，04第一句在声学起音窗口内命名策略模式，再出现活动函数；核心术语至少可读63帧。
- 05–06为第一处代码/概念布局，07–10为第二处固定代码布局。只展示本次核心调用，校验、类型、注册和完整实现进入文章。
- 金额画面用元；出现代码时明确10000分=100元，输出9000分=90元或8000分=80元。不能把100误当100分。

## 关键因果过程

01–02：原价相同，计算办法不同；旧写法把两条算法放在结算内，说明各自维护/替换的需要，不贬低简单稳定判断。

03–04：会员办法接收原价、返回应付价，随后命名策略并展示同样约定的活动办法。先有具体对象，再给名称。

05–06：外部选择会员函数并传入结算，此时应付结果为空。函数名称没有括号，不表示已经求得90元；画面区分办法与结果。

07：暂停金额运动，用同一会员函数展示member与本次pricing参数的对应。参数没有复制算法，也不是永久等于member。

08：高亮pricing(amount)才开始执行会员函数；从100元输入到90元结果，结果在调用后落定。

09–10：先口头说明换活动办法、从原价100元重新结算，清掉旧90元，再把参数换为campaign。第二次调用后才得到80元，不从90元叠加打折。

11：用已建立的对象回收选择、调用、计算，解释同一任务的可替换办法；不是仅把函数拆开就完成解释。

12–13：短句承接到取舍，分别说明独立变化的价值与拆分/阅读跳转成本，少量稳定判断可直接写。结尾兑现开头。
