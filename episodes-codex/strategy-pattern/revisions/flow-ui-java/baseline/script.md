# 《策略模式：结算怎样换一种算价办法？》

2026-10-25（北京时间），设计模式D01，制作issue #163。用户观看上一版后指出讲解偏向语言机制，仍需解释设计思想；本稿据此重写为11镜22句，以职责分工、变化隔离与共同约定为主线。时长由自然配音和动作停留决定，不靠加速压缩。

- 观众无需了解任何特定语言。本片只讲结算流程、定价策略、选择三种职责，不展示实现细节或语言写法。
- 唯一示例：同一原价100元的订单，会员九折90元、活动八折80元。只有两种策略，每次只选一种；重新结算时从原价100元开始，优惠不叠加。所有金额与折扣均标示例。
- 三个问题：01–02说明为何考虑拆开；03–08解释策略怎样独立、遵守共同约定、被选择和使用；09–11回收维护收益、替换边界与成本。
- 共同流程始终是读取原价→使用当前定价策略→显示应付。具体九折、八折留在各自策略中；选择环节位于共同流程外侧，仍需决定本次采用谁。
- 03先把会员、活动两个具体办法从共同流程分开；04第一句句首“策略模式”再解释同一任务、独立策略、共同约定与可替换关系，主术语标签按共享声学起音显示至少63帧。不能仅把独立办法命名就当作完整解释。
- 06演出按约定把定价交给当前策略，08解释为什么共同步骤能够保留，11回收三个职责；不能只展示100元变成90元或80元。
- 09的独立维护仅指本例、共同约定不变时的策略内部细节，不承诺结算永远不改或所有变化都能局部完成。10保留选择与协作的维护负担、间接关系的阅读成本及简单方案。
- 深色全屏canvas，无比喻、实物或假应用窗，不加装饰进度条。逐步引入一个共同流程骨架、一个当前策略和一个选择标记；另一策略只留名称，当前不展开其全部说明。
- 03、05、09先交代下一步方向，再启动新动作；不以观众“已经看懂”为前提。新稿需导演及独立编辑审读后才进入配音，旧版技术检查不能代替本次思想表达的复核。

### 02 mixed-pricing

frame：canvas
章节：同一任务，做法会变
画面：先建立共同步骤“读取原价→定价→显示应付”，再在定价这一步内部逐个显示会员九折、活动八折两套细节。维护会员定价的焦点必须进入整个流程边界，说明共同步骤与变化做法混在一起；不把两个简单判断本身画成故障。
旁白：如果两种定价细节都放在结算里，维护其中一种，就得进入这段共同流程。我们要分清，哪些步骤保持一致，哪些做法需要分别维护。
屏幕文字：读取原价→定价→显示应付；共同步骤；不同定价细节

### 03 separate-pricing

### 04 shared-contract

frame：canvas
章节：把变化独立成策略
画面：04首句“策略模式”声学起音时出现主标签；将会员定价、活动定价各自标为一种策略。第二句用相同形状的“接收原价→交回应付金额”分别对应两者，配合会员90元、活动80元的已知示例，突出共同的是任务与约定，不要求结果相同。
旁白：策略模式，把同一任务的不同做法独立起来，按共同约定替换使用。两种定价策略都接收原价、交回应付金额，会员九十元，活动八十元。
屏幕文字：策略模式；同一任务；接收原价→交回应付金额；结果可以不同

### 07 swap-strategy

frame：canvas
章节：先选策略，再让结算使用
画面：会员90元结果先有清楚停留，第一句说明将改选并从原价重算，随后清空上次结果。外侧选择标记由会员切为活动；共同流程位置、步骤和04约定均保持，只沿当前活动策略完成一次100元→80元。会员不执行，不把90元作为新输入。
旁白：会员这次得到九十元，接下来换成活动策略，重新从一百元算起。结算仍按原来的步骤走，活动策略交回八十元。

### 08 stable-collaboration

frame：canvas
章节：先选策略，再让结算使用

### 09 maintenance-boundary

frame：canvas
章节：独立维护的收益与成本
画面：第一句承接刚才的替换过程，交代转向分别维护；第二句先显示“本例：共同约定不变”的前提，再只圈定会员策略内部作为维护范围，活动策略和共同流程退为保留上下文。此处展示职责和范围，不增加折扣新版本或另一组金额，也不标全系统永远无需调整。
旁白：两种策略能替换了，再看它们怎样分别维护。共同约定不变时，本例的会员定价细节可以独立维护，不必把活动策略和共同流程一起改动。
屏幕文字：本例的维护范围；前提：共同约定不变；会员策略内部细节
