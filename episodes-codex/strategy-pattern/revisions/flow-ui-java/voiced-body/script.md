# 《策略模式：结算怎样换一种算价办法？》

2026-10-25（北京时间），设计模式D01，制作issue #163。用户决定保留既有100元订单/会员九折/活动八折案例，只调整讲解流程。本轮11镜22句，改01两句、05两句、06首句，其余17句沿用已验旁白；末尾另附静默Java关键代码卡供暂停。时长由自然配音和动作停留决定，不变速。

- 先用结算功能的交互示意建立场景，再展示为何分开定价细节、共同约定、角色结构与委托、维护边界；不换成支付或购物车例子。
- 同一原价100元的示例订单，会员九折90元、活动八折80元。每次只选一种；改选时从原价100元重算，优惠不叠加。结算UI为教学示意，不执行真实交易。
- 01在可识别的结算页演示优惠选择和应付金额，02转入该功能背后的结算程序。03–04保留独立定价及“接收原价、交回应付金额”的共同约定。
- 05用同一业务对象展开角色结构：选择方对应Client，结算Checkout对应上下文，PricingStrategy对应抽象定价约定，MemberPricing/CampaignPricing对应两种具体策略。中文职责是正文，英文/Java名称仅作映射，不逐行讲语法。
- 06先选择会员，再跟随共同结算流程委托、收到90元并继续；07原样改选活动，从100元得到80元。选择、计算、返回、使用的先后不可颠倒。
- 09只说明共同约定不变时的本例维护范围；10保留选择与协作成本及简单方案；11回收思想。静默代码卡显示同一模型的Java关键节选，提示暂停，不覆盖未结束的旁白字幕；完整可运行实现由demo-java提供。
- 首现“策略模式”仍位于04第一句句首，以共享声学起音为唯一严格cue，完整保留至少63帧。其他角色标签随已建立的业务对象逐步对应，不冒充词内ASR对齐。
- 03、05、09主要章节先有口头方向，再展开新细节。深色教学canvas；功能UI直接服务本例，不套无关应用壳、无比喻、无装饰进度条，不添加新业务支线。
