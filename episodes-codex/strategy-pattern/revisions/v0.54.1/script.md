# 《策略模式：优惠规则变了，为什么总要改结算？》

2026-10-24（北京时间），设计模式D01，制作issue #163。用户观看v0.52.0后认为整体问题不大，但章节切换缺少口头衔接；本次仅修04/11/15入口，先承接与交代方向、再启动新动作，原版记录保留。16镜32句，一期一个模式。目标约两分半，实际以冰糖自然配音和动作停留为准，不变速压缩。

- 唯一主线：同一100元示例订单，结算内的普通/会员/活动计算拆成可替换函数；外部选择→统一调用→结果返回；活动八折改七五折只改该规则，选择与注册仍有自己的责任。
- 所有数字为教学示例；原价100元、会员九折90元、活动八折80元，调整为七五折75元，新客减10元90元。各次选择独立演示，优惠不叠加。实际代码用整数分，百分比按示例约定向下取整到分，非法金额和未知选择拒绝。
- 三个问题融入一条因果过程，先对象后术语；“策略模式”首词在06第一句，按共享声学起音显示首标签，至少停留63帧。
- 深色全屏canvas，无比喻、实物或假窗口；不加装饰进度条。最多两处代码：03的旧分支、14的新实现。其余以规则实际拆出、输入沿唯一路径运动、返回值改变和修改范围解释。
- 完整可运行实现、验证、货币舍入、优惠叠加、策略与状态区别放配套文章。来源见research.md；没有普遍性能收益或“消灭所有条件”的承诺。
