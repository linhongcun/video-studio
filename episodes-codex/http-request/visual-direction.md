# HTTP请求技术细节版：动态表达设计

唯一连续对象是`https://shop.example/products/42`商品页；目标是让观众看清“找到地址→建连接→取资源→画页面”，其中建连接展开TCP与TLS。总览采用四段；顶部导航显示找地址、TCP建连、TLS安全、HTTP交换、页面渲染五个子阶段，并用“建连接”括组TCP与TLS，对应同一套四段叙事。只有01、15是真网页；03是同一URL的全屏canvas拆解视图，机制图、报文节选、总览和结构树同样使用干净canvas。深色页身、教学示意、示例数据；无持续装饰进度条。

每镜两句，以真实句首声学cue启动关键标签，句内动作按明确阶段推进，不伪造逐词时间。导航在五个子阶段中标记当前位置，并以TCP/TLS的括组对应四段全局，局部细讲让其他段缩退，跨章节先承接再动作；总览需有可读停留。

## 逐镜动作与准确性约束

| 镜号 / slug | 主要动作 | 需要保留的因果与边界 |
|---|---|---|
| 01 hook | 地址输入并回车，商品页空白仍在加载 | 首帧就是实际使用场景；不先播放片头 |
| 02 overview | 同一页缩为上下文，四段过程依次显现 | TCP与TLS共同归入“建连接”；主线条件是无可用缓存/连接、HTTPS over HTTP/1.1 |
| 03 url | 在同一URL的全屏canvas拆解卡上依次突出域名、路径、HTTPS默认443 | 端口不是DNS结果；路径不并入主机名 |
| 04 dns | shop.example查询后返回203.0.113.10，再与443组成目标 | DNS返回在查询抵达之后；示例IP不伪称真实解析结果 |
| 05 tcp | 固定浏览器在左、服务端在右，各自建立序号上下文 | 显示TCP为可靠、有序字节流；示例1000/5000属于不同发送方向，不是公共计数器 |
| 06 syn | SYN seq=1000左到右运动，抵达后服务端记下1000 | 发送与收到分开；客户端已发SYN，服务端未建立；包不是抽象装饰箭头 |
| 07 synack | 服务端发SYN+ACK seq=5000 ack=1001，沿右到左回传 | 第一句保留双方原序号；第二句用1000+1=1001解释确认号，+1绑定客户端SYN，不能画成任意数据长度 |
| 08 ack | 客户端收到第二次后建立并发ACK seq=1001 ack=5001 | 客户端先已建立；最后ACK抵达服务端后，服务端才已建立；纯ACK不把seq再加一 |
| 09 why-third | 明确标“解释回看”，回到服务端刚发第二次后的等待 | 只回看同一次ACK；服务端5000先“待确认”、到达后“已确认”，没有第四次报文，也不改变原运行结果 |
| 10 tls | TCP缩成已完成底层，验证shop.example证书，再建立流量密钥和受保护的数据 | 不把证书直接当加密密钥；TCP没有自动变为加密协议；抽象职责不冒充完整TLS报文序列 |
| 11 request | URL路径与域名分别落到GET路径与Host，随后请求到服务端 | canvas明确HTTP/1.1示意与TLS解密后的教学明文；只两行关键字段，不做无关代码卡 |
| 12 response | 请求被处理后，响应从服务端右侧返回左侧浏览器 | 状态行、类型、正文逐项出现；200是本次GET成功，响应节选不冒充完整线上字节 |
| 13 resources | HTML解析发现样式/图片引用，继而派生请求并返回资源 | 同源请求可复用原连接，主线按HTTP/1.1先后展示；不重复三次握手，不提前画HTTP/2并发流 |
| 14 parse | 标题/价格/按钮成为DOM节点；第二句把CSSOM规则绑定相应节点 | 结构身份与原网页一致，按钮不能变成无关联内容；规则与结构参与样式计算，还未等于布局完成 |
| 15 paint | 原商品页先布局轮廓，再绘制文字和按钮，图片最后补齐 | 显示位置与大小由布局确定、像素由绘制产生；图片预留空间，不能先声称所有资源已到齐 |
| 16 variants | 回四段总览，分别演缓存/连接旁路，再切HTTP/2与HTTP/3边界 | 缓存旁路与连接旁路跳过的步骤不同；HTTP/2并发保留单连接；HTTP/3独立标QUIC/UDP，不接入TCP三次握手 |
| 17 recap | 四段全局回收，完整商品页成为结果，TCP只点亮建连接局部 | 回答开头：握手完成TCP建连，后续仍有TLS/HTTP/绘制；不追加新失败分支 |

## 连续动态复核重点

必须实际看无字幕连续片与中间态，不以源码或端点静帧替代：04地址/端口组合；06–08三个方向报文的发送、途中与抵达；08→09回看标记和状态重置；10→11安全职责转HTTP；11→12请求后响应的方向；13发现资源再请求；14→15同一按钮/标题/图片映射；16退出主线再进入协议边界；17回收四段。

报文字段以独立可读文字放在运动路径旁，抵达后留结果，不让路径穿过数字或字段。5000、1000及其确认号保持所属端的色彩和位置身份，避免动画中加一公式遮挡原值。移动报文不经过导航、状态或字幕区；不以无因果的闪烁代替收到报文后状态变化。

成片复核另检查实际编码文件中的字段、方向、标签起音、阅读停留和深色商品页。检查结果由执行者记录；本设计文档不预记动画、配音或成片已通过。
