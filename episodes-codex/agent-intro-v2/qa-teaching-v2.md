## V1根因诊断与本轮纠正目标

主任务转交的用户观看反馈：开头像流水账、铺垫多，看不出要讲什么。以下是结合原稿作出的编辑诊断，不伪称本代理进行了用户访谈或全片听辨。

1. 原开头的冲突不成立。用户问“能不能申请”，回答“可以申请”但没有执行退款是正常的任务边界，不能拿它制造“已经办好没有”的悬念。原开头由此引导了真正退款的期待，正文却只读并反复声明未退款，承诺与内容错位。
2. 概念出现太晚。V1前7镜约60秒才进入正片首次查询；脚本到第14镜、约109秒才首次命名智能体。模型通识、能力范围和边界解释占据入口，观众先承受信息，再等待主题。
3. 流程顺序替代了因果。请求、执行、返回即使分别正确，观众仍需知道“这次返回解决了什么、还缺什么、因此为什么选这个动作”。重复报步骤不能自动回答下一步怎么选。
4. 次要问题持续分散主线。固定工作流比较、模型基础、只读范围和业务完成边界各自成为段落；原本可以随动作交代或移文章的内容，与核心问题竞争注意力。
5. 本代理V1将事实及状态一致性扩大为“教学通过”，遗漏了主题前置、悬念是否真实和承诺是否兑现的编辑检查。早期检查证据保留，但不能作为用户已经看懂的证明。

V2唯一承诺锁定为：**用同一笔咨询解释，AI智能体怎样根据返回结果选择下一步。**“什么是智能体”由此机制自然落地，不扩成另一段概念通识。

## 可判定的编辑闸门

下列是本轮审核标准，不是已经测量的观众理解数据。首2/5/15秒须在真实音轨预演中逐项验收。

| 时点/范围 | 必须能从画面与旁白读出的内容 | 阻断条件 |
|---|---|---|
| 首2秒 | 主题是AI智能体，问题是下一步怎样选；首帧主体题名存在，首句直接进入主题。 | 只出现退款场景或泛泛AI文案，要靠后面解释才能猜到本期主题。 |
| 首5秒 | 同单目标明确，具体悬念是“查资料为何换成问用户”；预览不把使用未知的原因提前讲完。 | 重复范围、开场介绍或边界声明；查了几次被当成主要冲突；已把整条因果答案提前说完。 |
| 首15秒 | 正片已开始第一次查询，观众知道“缺本单事实，所以先查订单”；模型提出请求、程序执行的实际动作已经进入。 | 仍在介绍模型/术语/范围，或只用开头快剪预览冒充正片已推进。 |
| 全片 | 每次选择都有本轮信息依据：缺规则→查询规则；规则要求未使用而使用未知→问用户；有用户补充→按当前资料给建议。 | 只说“然后/接下来”而缺少选择理由；新增工作流比较或怎样真正退款的第二主线。 |
| 每镜 | 必须补上一个必要环节：当前问题、缺什么、选什么、谁执行、返回什么、下一选择为何改变、最后如何回应开头。 | 删除后因果仍完整，镜头只重复范围、定义、总结或状态声明；为凑镜数保留。 |
| 末尾 | 直接回答开头：查询结果没有补上使用情况，所以模型换成询问；补充回来后才按当前资料给建议。 | 用“没有退款”作主结论，或以泛泛“智能体很强/会用工具”收尾。 |
