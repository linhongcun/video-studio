# 单哈希核心修订：画面方向

使用抽象元素A/B/C/D与八个位，直接讲解标记算法；无商品、数据库、查库、同步或业务外壳。八格自左至右始终为位置0—7，格内位值与格外位置分别标识。哈希区只有一个输入元素、一个固定计算框、一条活动到位路径，主线不画扇出。

A写3，B也写3；标记在路径抵达后才改变，重复置1不变2。D查询7读0而排除，C查询3读1却没有加入，用同一份标记解释不对称结果。演示中加入过的A/B列表仅为教学回看，独立于位数组，不冒充Bloom保存了成员名单。

错误删除明确带错误操作标签：清除共享位3后，真实成员B被错排除；镜尾恢复位值和演示成员。两位置对照另起一份空数组，依次重建A的3/2与B的3/1；只有重建完成才允许C检查3/5，得到本次排除。每次计算与读写串行呈现，无常驻双路扇出。结尾撤去对照，回到主线单位置标记，收束0/1结论与空间、元素数量、位置次数的取舍，不声称次数越多越好。

动画只用实际选中句级音轨包络控制事件，不用墙钟或CSS动画。真实分镜到位后，须测每一步运动/抵达/停留窗口，独立看连续过程和中间帧。实际DOM审计记录文字、位值与位置glyph、元素glyph、单条活动路径geometry和解释成员文字；自报Scene状态不作为独立通过依据。
