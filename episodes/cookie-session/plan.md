# 第四期 plan：网站怎么记住你已经登录？（Cookie 和 Session）

- 系列：EP.04；接第一期的 HTTP 请求，讲 HTTP 本身"记不住人"
- 受众：零基础初学者；口吻用科普口吻，不写面试话术
- 规格：1920×1080，30fps，时长 120–160 秒；配音用 MiMo「冰糖」，句间停顿 0.28 秒；响度 −16 LUFS；BGM 用 Wallpaper，比人声低 12 dB
- 发版：新增一期，版本号 v0.8.0；草稿阶段的 PR 不升版本
- 贯穿比喻：存包处的手牌。手牌就是 Cookie（存在浏览器里），柜台里存着的东西就是 Session（存在服务器上）

## 章节（6 章）
1. 开场：HTTP 是无状态的，每次请求都像第一次见面。刚登录完，点下一页又不认识你了
2. 发手牌：登录成功后，服务器在响应里用 Set-Cookie 发给浏览器一张手牌，里面是一串会话 ID
3. 每次都带上：之后浏览器访问同一个网站，会自动在请求里带上 Cookie，服务器看手牌认人
4. 柜台里存什么：Session 存在服务器上，用会话 ID 找到"你是谁、登录到什么时候"；手牌本身只是一串编号，不装你的密码
5. 手牌被偷怎么办：会话劫持。HttpOnly 让网页脚本读不到 Cookie，Secure 让它只走 HTTPS（接第二期），SameSite 限制别的网站发起的请求带上它；还要讲过期和退出登录
6. 回顾：串起整条流程，并点一句：有些网站用 Token 代替 Session，思路一样，都是"凭证带在身上"

## 准确性要求
- Cookie 由服务器通过 Set-Cookie 响应头设置，由浏览器按域名和路径自动带上；不能写成"网站从你电脑里读文件"
- Session 不一定存在内存里，也可能放在数据库或 Redis 里；只说"存在服务器那边"
- 只有会话 ID 的 Cookie，本身不含密码；但被偷了就能冒充你，这一点要讲清楚
- SameSite：有的浏览器在没写这个属性时，默认按 Lax 处理，但不是所有浏览器都这样，不能写成"所有浏览器默认 Lax"
- 第三方 Cookie 的政策这几年一直在变，片中不碰；文章里如果提到，必须写明日期和来源
- 不写没有来源的统计数字；资料优先用 2020 年以后的，更早的标「仅参考」（RFC 6265 等现行标准标「现行标准」）
