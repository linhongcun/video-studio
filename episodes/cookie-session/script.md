# 脚本 v2（定稿）：《网站怎么记住你已经登录？》

- 依据：`/workspace/nolan-backup/cookie-session/plan.md`
- 结构：6 章（记不住人、发手牌、每次都带上、柜台里存什么、手牌被偷、回顾）；旁白合计 536 字，按第三期实测比例（557 字 / 131.2 秒）折算约 126 秒
- 字数按汉字和英文字母/数字计（不含标点和空格）
- 贯穿比喻：存包处的手牌。手牌是 Cookie，存在浏览器里；柜台里存的东西是 Session，存在服务器上
- 准确性：Cookie 由服务器用 Set-Cookie 设置、浏览器自动带上；手牌里只有编号、没有密码，但被偷了照样能冒充；不写“所有浏览器默认 Lax”；不碰第三方 Cookie 政策

## 第 1 章 HTTP 记不住人
- 旁白：你刚登录完一个网站，点开下一页，它照样知道你是谁。可 HTTP 本身是无状态的：每一次请求，对服务器来说都像第一次见面，它记不住上一次是谁来过。要是每点一页都得重新输一次密码，谁也受不了。那网站是怎么认出你的？答案就在存包处。
- 字数：100 字
- 画面提示：浏览器卡片里登录框打勾，跳到下一页；服务器卡片头顶冒出问号“你是谁？”，连续几次请求箭头都配同一个问号；转场到一个存包柜台。

## 第 2 章 登录后发手牌
- 旁白：在存包处寄存东西，柜台会给你一张手牌。登录也一样：密码验证通过后，服务器在响应里加一行 Set-Cookie，交给浏览器一张手牌。手牌上只写着一串编号，叫会话 ID，浏览器把它收好，这就是 Cookie。
- 字数：88 字
- 画面提示：服务器卡片验证密码打勾；响应箭头上挂着一张手牌，标签 `Set-Cookie`；手牌上只有一串编号 `sid=7f3a…`；手牌落进浏览器的口袋，标“Cookie”。

## 第 3 章 每次都带上
- 旁白：之后再访问这个网站，浏览器会自动在每个请求里带上这张手牌，不用你动手。服务器看一眼编号，就知道是你。关掉页面再回来，只要手牌还在、没过期，它也还认得你。手牌只会交给发它的那个网站，别的网站拿不到。
- 字数：87 字
- 画面提示：每支请求箭头都带着同一张手牌飞向服务器，服务器亮绿灯“认出你了”；旁边另一个网站的服务器卡片伸手，手牌没有飞过去，打叉。

## 第 4 章 柜台里存什么
- 旁白：真正的东西存在柜台里，也就是服务器那边的 Session。它按编号记着：这是谁，登录到什么时候。手牌本身只是一串编号，不装你的密码。可柜台只认手牌不认人，谁拿着它，谁就能取走东西。
- 字数：79 字
- 画面提示：存包柜一格格打开，编号 `7f3a…` 那格里是“用户：小明 / 登录到：今晚 12 点”的卡片；手牌特写，只有编号，画一把带叉的钥匙表示“没有密码”；一只陌生的手拿着同一张手牌，柜台照样亮绿灯。

## 第 5 章 手牌被偷怎么办
- 旁白：所以要护好手牌。加上 HttpOnly，网页里的脚本就读不到它；加上 Secure，它只走 HTTPS，路上看不见；SameSite 限制别的网站发起的请求带上它。再给手牌定好有效期，退出登录时柜台作废这个编号，偷到的手牌也就没用了。
- 字数：103 字
- 画面提示：小偷图标伸手抓手牌，手牌依次套上三层防护，每层一个标签：`HttpOnly`（脚本的手被挡住）、`Secure`（手牌进入带锁的 HTTPS 通道，接第二期）、`SameSite`（别的网站的箭头被拦下）；最后手牌上的倒计时走完，柜台盖“已作废”章，小偷手里的手牌变灰。

## 第 6 章 回顾
- 旁白：串起来看：登录成功，服务器发一张手牌；浏览器收好，每次请求自动带上；服务器凭编号，在柜台里找到你。有些网站用 Token 代替 Session，思路是一样的：凭证带在身上，网站凭它认人。
- 字数：79 字
- 画面提示：一张总图依次点亮：登录 → `Set-Cookie` 发手牌 → 请求带手牌 → 柜台按编号取出“你是谁”；最后手牌变成一张写着 Token 的通行证，并排一句“凭证带在身上”，定格片名。
