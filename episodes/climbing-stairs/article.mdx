## 先看题目要返回什么 {#problem}

LeetCode第70题给出一个正整数 `n`，表示楼梯总共有多少阶。每次只能上 **1阶或2阶**，要恰好到达第 `n` 阶，不能越过终点。返回的是**不同走法的数量**，不是把具体路径逐一列出来。题目范围是 `1 <= n <= 45`。[^problem]

<SourceQuote sourceId="A1" supports="每次只能走一阶或两阶，目标是统计不同的登顶方法；末步分类由本文据此推导。" translation="每次可以爬1阶或2阶。共有多少种不同的方法能够爬到顶部？" />

三阶是最小而清楚的教学例子：

| 走法 | 每步上多少阶 | 合计 |
|---|---|---:|
| 1 | 1、1、1 | 3 |
| 2 | 1、2 | 3 |
| 3 | 2、1 | 3 |

`[1,2]` 和 `[2,1]` 的顺序不同，算两种走法。因而输入 `n=3`，返回 `3`。单步上3阶不允许；到第3阶后继续上也不属于答案。

## 按最后一步分成两类 {#last-step}

先不急着写程序。看任意一种到达第三阶的走法，它的最后一步只能是下面两种情况：

| 最后一步 | 最后一步之前在哪里 | 前面的走法 | 接上最后一步后 |
|---|---|---|---|
| 上1阶 | 第2阶 | `[1,1]`、`[2]` | `[1,1,1]`、`[2,1]` |
| 上2阶 | 第1阶 | `[1]` | `[1,2]` |

第一组有2种，第二组有1种，所以共有 `2+1=3` 种。这个相加不是猜出来的：

- **不会重复：**两组最后一步的长度不同，同一条完整走法不可能同时属于两组。
- **不会遗漏：**每步只允许1阶或2阶，因此每条合法走法都必然属于其中一组。
- **数量对应：**到达前一位置的每种走法，接上确定的最后一步，恰好得到这一组的一种完整走法；去掉末步又能恢复原来的走法。

把“到第 `k` 阶的方法数”记作 `ways(k)`，就得到：

`ways(k) = ways(k - 1) + ways(k - 2)`，适用于 `k >= 3`。

起点直接数清：到第1阶只有 `[1]`，所以 `ways(1)=1`；到第2阶有 `[1,1]`、`[2]`，所以 `ways(2)=2`。本实现不需要定义 `ways(0)`，也不接受题目范围之外的 `n=0` 输入。

### 从两个起点算到六阶

| 要算哪一阶 | 从哪两个已知结果得到 | 方法数 |
|---:|---|---:|
| 1 | 直接数 `[1]` | 1 |
| 2 | 直接数 `[1,1]`、`[2]` | 2 |
| 3 | 第1阶1种 + 第2阶2种 | 3 |
| 4 | 第2阶2种 + 第3阶3种 | 5 |
| 5 | 第3阶3种 + 第4阶5种 | 8 |
| 6 | 第4阶5种 + 第5阶8种 | 13 |

现在才回到第6阶：最后上1阶时，前面到第5阶，共8种；最后上2阶时，前面到第4阶，共5种。两组不重不漏，因此答案是 `8+5=13`。

## 为什么只记前两个数 {#rolling}

从较小问题的已知结果，逐步得到更大问题的结果，这里使用的是**动态规划**。本题每次只依赖前两阶的计数，因此算下一项时，不需要继续保存更早的所有计数。

例如准备计算第6阶时，变量的身份必须清楚：

| 时刻 | `prev` | `curr` | 正在计算 |
|---|---|---|---|
| 更新前 | 第4阶方法数5 | 第5阶方法数8 | 第6阶 |
| 先算右侧 | 仍是5 | 仍是8 | 新值 `5+8=13` |
| 整体更新后 | 第5阶方法数8 | 第6阶方法数13 | 第6阶已完成 |

这里变量的名字只是标签，关键是每一轮对应哪一阶。设本轮要算第 `step` 阶，更新前 `prev=ways(step-2)`、`curr=ways(step-1)`；更新后分别变为 `ways(step-1)` 和 `ways(step)`，下一轮仍满足同样的关系。

视频在同一座楼梯的各阶旁显示已算方法数，让观众追踪每个计数对应哪一阶；这些历史计数是教学留痕，**不是要求程序把整张表存下来**。阶编号与方法数的“种”分开标识，淡化旧计数时仍保留真实台阶。程序也无需枚举所有路径；只保存方法数即可。

只用两项是这道题的依赖关系带来的空间优化。其他动态规划问题可能依赖更早的结果、更宽的范围或多维状态，不能一律压缩成两个数。

## 把滚动更新写进程序 {#code}

`n` 为1或2时直接返回相应起点；其余从第3阶开始，一直算到第 `n` 阶。

```python
class Solution:
    def climbStairs(self, n: int) -> int:
        if n <= 2:
            return n

        prev, curr = 1, 2
        for step in range(3, n + 1):
            prev, curr = curr, prev + curr

        return curr
```

这份程序与视频完整代码卡、制作目录中的 `solution.py` 和 `solution.json` 逐字同源。

Python在执行 `prev, curr = curr, prev + curr` 时，先求出右侧的两个值，再赋给左侧目标。[^assignment] 因而第二个右值仍使用更新前的 `prev` 和 `curr`。不能先执行 `prev = curr`，再执行 `curr = prev + curr`；后者会把旧的 `prev` 覆盖掉，例如本应 `5+8=13`，却错误地得到 `8+8=16`。

在第 `n` 阶算完后，`curr` 正好是 `ways(n)`。时间复杂度为 `O(n)`，按本题有限整数范围、整数运算视为常数时间的常用分析，额外空间为 `O(1)`。这里保存的是固定数量的变量，不是路径列表或随阶数增长的计数数组。

### 核对结果

`n=1、2、3、4、5、6` 的答案依次为 `1、2、3、5、8、13`。独立验证对题目全部 `n=1..45` 使用组合计数作基准：若一条走法包含 `k` 个两阶步，则还有 `n-2k` 个一阶步，总步数是 `n-k`，只需从这些位置中选出 `k` 个放两阶步。因此方法数是：

`sum(comb(n-k, k) for k in range(n//2+1))`

它按“两阶步有几个、出现在哪些位置”计数，与程序的前两项相加实现独立；实际执行结果与适用范围见制作调研记录，不把有限输入验证代替上面的分组证明。
