# EP.20 UUID与Redis取舍讲解

### 16 options

frame：canvas
画面：直接介绍随机UUID，不先出现雪花名称或方案总览。两个节点先后生成较大和较小的有效UUIDv4示例，显示本地发号与低碰撞；第二句把相同编号的前缀映射到MySQL InnoDB主键索引的不同叶页；第三句只在示意页已满时演页分裂，并提示随机插入的缓存局部性代价。
旁白：UUID 的随机版本，各节点就能在本地生成，碰撞概率很低。但它不递增，直接用作 MySQL 主键，插入位置会比较分散。这会影响索引页的缓存利用，还可能增加页分裂。
屏幕文字：按句界和句首UUID实测起音渐进出现；前缀和页容量均为教学示意。
出处：R6、R10、R11、R12。

### 17 redis

frame：canvas
画面：先演共同计数器1000→1001→1002，返回两节点；第二句显示旧主1002但异步复制尚未到达、从节点1000，旧主故障停发后从节点升主，再次加一重发1001。第三句切到事先可靠预留号段的治理方案示意，旧号段1001—1200，独立可靠记录上界1200，旧主停发/隔离；新主越过整个旧号段后下一号1201。第四句强调上界记录和停止旧主的条件，不把任意加固定数说成保证。末句才出现雪花算法名称并接回原07详解。
旁白：Redis 自增，让各节点从同一个计数器取号，正常时编号递增。但复制是异步的，主从切换后，计数可能回退，造成重复发号。一个处理思路是跳号，越过旧主可能用过的整个号段。前提是号段上界有可靠记录，且旧主已停止发号。接下来，详细看雪花算法。
屏幕文字：按句界和Redis实测句首起音渐进出现；跳号为满足明确前提的示例方案，非Redis内置保证。
出处：R7、R8、R9、R13；跳号安全前提是基于异步丢写事实的设计推导。
