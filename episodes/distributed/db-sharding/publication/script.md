# EP.19《订单太多，一个数据库装不下怎么办？》

2026-10-24按用户持续授权及本批重制目标制作，关联issue #71。

- 一条主线：集中写入和增长 → 按用户拆分 → 分片键决定路由。画面新术语只保留分库分表、分片键。
- 全屏深色canvas，直接呈现订单记录、逻辑库与数据路径；不用驿站、物理服务器或假应用窗，不靠常驻密集面板。
- 示例订单7042/7044属于用户42并去A，7043属于17并去B，7045属于86并去C。本期固定教学映射，不代表具体产品哈希算法或实际性能。规则改变、扩容搬迁不在主线。
- 条件：不同处理资源且分布合适时才可能分担压力；不是拆成多个表名就自动提速，不保证均衡，不以本例解释所有下单卡顿。
- 两个术语均位于独立句首，按共享声学起音挂词；没有ASR时不伪造逐字对齐。
- 片尾接EP.20《两个订单，怎么撞成同一个号了？》。
