# Redis 跳表：怎样跳过一段，找到插入位置？

EP40 / 工程算法03，issue #301；EA07保留为策划索引，不是发布第七期。

- 唯一问题：怎样少走几步，仍准确找到55的插入位置并接好链接。
- 两层最简例子：底层10/20/30/40/50/60/70/80，上层仅40/70。单个活动游标；先比较再前进，会超过则在原节点下降。
- 55本例固定高度2，先新节点后继、再改上一节点；底层完成再接上层。固定合法高度不是Redis随机抽样回放。
- 全屏深色canvas，算法对象直接参与，无业务UI/浏览器壳/无关比喻。跳表编码示意，不冒充默认8成员Redis实际内存。
- 核心术语按对象与动作引入：链表、跳表、层高；前驱/字典/span/复杂度与产品编码细节主要留文章。
- 10镜20句，时长服从实际配音与可读动作，不加快语速。默认含原始题名/可选连续原文参考资料附录，无完整代码尾卡。

### 01 goal

frame：canvas
画面：第一帧有序底层10/20/30/40/50/60/70/80、起点和待插55；只画一层，目标立即可见。只解释节点沿向前链接，不显示上层、随机或排行榜界面。第二句真实起音后才出现链表正式标签。
旁白：要插入五十五，怎样少走几步，还能找到正确位置？链表中的节点从小到大排列，每个只链接到下一个，我们先沿链接查找。
屏幕文字：插入55：能少走几步吗？；节点有序，只沿链接向前。

### 02 linear

frame：canvas
画面：单个游标从起点逐个比较10/20/30/40/50后前进；第二句比较60大于55，不进入60，停在50并标出50到60这一条链接。六个逻辑候选均来自linearSearch.events，不作为生产性能测量。
旁白：先逐个比较，十、二十、三十、四十、五十都比五十五小，可以继续向前。下一个六十大了，就停在五十；新节点应该接在五十和六十之间。
屏幕文字：逐个查找；停在50；目标位置：50与60之间。

### 03 sparse

### 04 upper

### 07 height

frame：canvas
画面：承接已定位位置，出现待接入新55的两层链接槽，明确本例固定合法层高2，不声称真实Redis随机抽样结果。旧50→60和上40→70保持，未接入的新节点不能遮住旧边或看似已接入。前驱位置只作解释，不是多路新查询。

### 08 splice-bottom
