每打开一个网页，浏览器、网络和服务器之间都要配合完成一连串步骤。把它们**按顺序、分层次**串起来，你就能看懂一次访问的全貌，也能理解网页为什么有时快、有时慢。下面按 8 步，从头到尾走一遍。

## 8 步走完一次访问

### 1. URL 解析 {#url}

{/* 配图：https://example.com:443/index.html 被切成协议、域名、端口、路径四块 */}

- 浏览器先判断输入的是不是合法 URL。是，就拆成**协议**（https）、**域名**（example.com）、**端口**（默认 443）、**路径**（/index.html）；不是，就当作关键词交给默认搜索引擎。
- 如果这个域名在 **HSTS**（HTTP 严格传输安全）名单里，浏览器会把 `http://` 直接改成 `https://`，不会先发一次明文请求。[^hsts]

### 2. 缓存检查 {#cache}

{/* 配图：缓存抽屉里抽出带倒计时的文件，绿色对勾“强缓存命中” */}

- 浏览器先看本地有没有这个资源的缓存，并且是否还“新鲜”。判断依据是上次响应里的 `Cache-Control: max-age=…`（优先）或 `Expires`。[^cache]
- 新鲜就是**命中强缓存**：直接使用，**完全不发请求**（开发者工具里显示 `from memory cache` 或 `from disk cache`）。
- 过期了也不一定重新下载，后面第 7 步的**协商缓存**会再问一次服务器。

### 3. DNS 解析 {#dns}

{/* 配图：本地三层缓存依次“未命中”；右侧 DNS 树 根 → com → example.com */}

- 目标：把域名换成 IP 地址。
- 查找顺序：**浏览器 DNS 缓存 → 操作系统缓存和 hosts 文件 → 递归解析器**（通常由运营商或公共 DNS 提供）。
- 递归解析器本地也没有时，依次询问**根服务器 → 顶级域（.com）服务器 → 权威服务器**，拿到 IP 后返回给浏览器，并按 TTL 缓存。[^dns]
- 关键词：浏览器到递归解析器是**递归查询**（“你帮我查到底”）；递归解析器到各级服务器是**迭代查询**（“你告诉我下一步问谁”）。

### 4. 建立连接 {#connect}

{/* 配图：SYN / SYN+ACK / ACK 时序图；锁图标标注“证书校验、密钥协商” */}

- **TCP 三次握手**：客户端发 `SYN`，服务器回 `SYN+ACK`，客户端再回 `ACK`。双方借此交换并确认各自的初始序列号，确认彼此都能收发。[^tcp]
- **TLS 握手**（HTTPS 才有）：协商协议版本和加密算法，服务器出示**证书**，浏览器校验证书链和域名，双方通过密钥交换算出**会话密钥**，之后的数据都用它对称加密。TLS 1.3 把完整握手压缩到 1 个往返。[^tls]
- 版本差异一句话：HTTP/1.1 默认长连接（keep-alive）；HTTP/2 在一条 TCP 连接上**多路复用**；HTTP/3 改用基于 UDP 的 **QUIC**，把传输和加密握手合在一起。[^h2h3]

### 5. 发送 HTTP 请求 {#request}

{/* 配图：第一期的信封，依次亮起请求行和几个请求头 */}

请求由**请求行、请求头、空行、请求体**组成。[^http]

```http
GET /index.html HTTP/1.1
Host: example.com
Accept: text/html
Cookie: session=abc123
If-None-Match: "v1-5f3a"
```

- `Host`：要访问哪个站点（一台服务器上可以有多个网站）。
- `Cookie`：带上之前服务器通过 `Set-Cookie` 存下的信息，比如登录态。
- `If-None-Match`：带上缓存里的 `ETag`，用于协商缓存。
- `GET` 请求一般没有请求体；`POST` 提交表单或 JSON 时才有。

### 6. 服务器处理 {#server}

{/* 配图：信封穿过 CDN、负载均衡、反向代理三道门，落进服务器 */}

- **CDN 其实在 DNS 阶段就介入了**：站点域名通常通过 CNAME 指向 CDN，DNS 返回的是离你最近的**边缘节点**的 IP。边缘节点命中缓存就直接返回，请求**不会到达源站**；没命中才回源。
- 回源或没用 CDN 时，请求一般先经过**负载均衡**（分摊到多台机器）和**反向代理**（如 Nginx，做转发、限流、TLS 卸载），再到应用服务器。
- 到了应用服务器，要么读取**静态文件**，要么执行业务逻辑、查数据库，**动态生成** HTML 或 JSON。

### 7. 返回响应 {#response}

{/* 配图：响应包依次翻牌 200 / 301 / 404 / 500；放大 304 指回缓存抽屉 */}

响应由**状态行、响应头、空行、响应体**组成。

```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Cache-Control: max-age=3600
ETag: "v1-5f3a"
Set-Cookie: session=abc123; HttpOnly; Secure

<!doctype html><html>…</html>
```

- 常见状态码：**200** 成功；**301** 永久重定向、**302** 临时重定向；**304** 未修改；**404** 找不到资源；**500** 服务器内部错误。[^status]
- **协商缓存**：强缓存过期后，浏览器带上 `If-None-Match`（对应 `ETag`）或 `If-Modified-Since`（对应 `Last-Modified`）去问服务器。资源没变，服务器返回 **304 且没有响应体**，浏览器继续用本地缓存。[^cache]
- 重要响应头：`Content-Type` 告诉浏览器怎么解析内容；`Cache-Control` 决定能缓存多久；`Set-Cookie` 让浏览器存下 Cookie。

### 8. 浏览器渲染 {#render}

{/* 配图：渲染流水线 DOM → CSSOM → 渲染树 → 布局 → 绘制 → 合成；<script> 方块挡路，加 defer 后让开 */}

1. 解析 HTML，构建 **DOM 树**；解析 CSS，构建 **CSSOM 树**。
2. 两者合并成**渲染树**，只包含要显示的节点（`display: none` 的不在里面）。
3. **布局**（Layout，也叫回流 / 重排）：计算每个节点的位置和大小。
4. **绘制**（Paint）：把文字、颜色、边框、阴影等画成像素。
5. **合成**（Composite）：把不同图层按顺序合成，显示到屏幕上。[^render]

再补充几个关键细节：

- **CSS 不阻塞 DOM 解析，但会阻塞渲染**：CSSOM 没建好，浏览器不会绘制页面；CSS 还会**阻塞后面 JS 的执行**，因为脚本可能读取样式。所以 CSS 放 `<head>`，尽早加载。[^render]
- 遇到普通 `<script>`，HTML 解析会**暂停**，等脚本下载并执行完再继续；用 `defer` 或 `async` 可以避免阻塞（区别见下面的“深入一问”）。[^script]
- 图片、CSS、JS 等**子资源**会各自再走一遍请求流程（多数能命中缓存或复用连接）。
- 连接不是页面一展示完就断：HTTP/1.1 默认长连接，后续请求复用同一条连接，空闲一段时间后才关闭，TCP 通过**四次挥手**断开。[^http]

## 深入一问

**1. TCP 握手为什么是三次，不是两次？**
三次握手能让双方都确认“自己能发、对方能收”，并同步双方的初始序列号。更关键的是，它能防止**已经失效的旧连接请求**突然到达服务器，被误当成新连接建立起来、白白占用资源。两次握手时服务器收到 SYN 就建立连接，没法识别这种旧请求。[^tcp]

**2. 强缓存和协商缓存有什么区别？**
强缓存看 `Cache-Control` / `Expires`，命中时**不发请求**；协商缓存看 `ETag` / `Last-Modified`，**要发请求**问服务器，资源没变就返回 304、不带响应体。顺序是先查强缓存，过期了再走协商缓存。[^cache]

**3. DNS 用 UDP 还是 TCP？**
大多数查询用 **UDP 53 端口**，因为报文小、无需握手、速度快。响应过大被截断时，会改用 **TCP** 重试；主从服务器之间的区域传送也用 TCP。现在的规范要求 DNS 实现必须同时支持 TCP。[^dnstcp]

**4. 重排和重绘有什么区别？**
**重排**（回流）是元素的几何信息变了，比如宽高、位置，需要重新布局；**重绘**是只有外观变了，比如颜色，不影响布局。重排一定会导致重绘，重绘不一定导致重排。优化办法：批量修改样式，动画尽量用 `transform` 和 `opacity`，它们通常只触发合成。[^render]

**5. `defer` 和 `async` 有什么区别？**
两者都让脚本**并行下载**、不阻塞 HTML 解析。区别在执行时机：`async` 下载完**立即执行**，多个脚本之间**不保证顺序**；`defer` 等 HTML **解析完成后**、`DOMContentLoaded` 之前**按顺序执行**。依赖 DOM 或彼此有依赖的脚本用 `defer`，独立的统计脚本用 `async`。[^script]

**6. HTTPS 是怎么保证安全的？**
三点：**加密**（会话密钥对称加密，别人看不懂）、**完整性**（消息认证，内容被篡改会被发现）、**身份认证**（服务器证书由受信任的 CA 签发，浏览器校验证书链和域名，防止冒充）。非对称的密钥交换只在握手时用，用来安全地协商出对称会话密钥。[^tls]

**7. 301 和 302 有什么区别？**
301 是**永久**重定向，浏览器和搜索引擎会记住新地址；302 是**临时**重定向，下次还会访问原地址。[^status]

**8. 四次挥手为什么比握手多一次？**
TCP 是全双工的，两个方向要分别关闭。服务器收到客户端的 FIN 后，可能还有数据没发完，所以先回 ACK，等数据发完再发自己的 FIN，这两步不能合并。[^tcp]

## 易错点

- **强缓存命中时根本不发请求**，并不是“服务器返回 304”。304 是协商缓存。
- **304 没有响应体**，浏览器用的是本地那份。
- **DNS 不是只用 UDP**，响应过大和区域传送会用 TCP。
- **HTTP/3 不跑在 TCP 上**，它基于 UDP 上的 QUIC。
- **渲染树不包含 `display: none` 的元素**，但包含 `visibility: hidden` 的元素。
- **`async` 不保证执行顺序**，`defer` 保证。
- **CSS 不阻塞 DOM 解析，但阻塞渲染和后续 JS 执行**，并不是“CSS 不阻塞任何东西”。
- **用了 CDN 的站点，请求不一定到源站**，边缘节点命中就直接返回。

## 速记口诀

> **解析查缓存，DNS 找地址；握手建连接，请求到服务；响应看状态，渲染出页面。**

对应 8 步：URL 解析、缓存检查 → DNS 解析 → TCP/TLS 握手 → 发送请求、服务器处理 → 返回响应 → 浏览器渲染。

想亲眼看看？打开浏览器开发者工具的“网络”（Network）面板，刷新页面，点开第一条请求，看它的 Timing 分段：DNS Lookup、Initial connection、SSL、Waiting、Content Download，正好对应上面的第 3 到第 7 步。
