# 《策略模式：结算怎样换一种算价办法？》

2026-10-25（北京时间），设计模式D01，制作issue #163。本稿根据用户“策略没有解释清楚、内容复杂、新手难以接受”的反馈重写理解路径，替代旧16镜稿的制作方向。13镜26句，时长由真实自然配音和必要动作停留决定，不沿用旧镜数或为压时长加速。

- 观众前置：懂简单函数调用和if；不预设懂函数可以作为参数。片中必须直接补齐“传入函数本身→参数接住该函数→调用参数才执行→返回金额”。
- 三个问题：01–02建立为何考虑拆开；03–11讲清策略是什么、怎样选择和使用；12–13判断何时值得用。
- 唯一示例：同一原价100元的订单，会员九折90元、活动八折80元。仅这两种策略，优惠不叠加，每次都从原价重新计算。普通价只作输入基线；不讲七五折改价、新客、注册表、其他模式或复杂项目阅读。
- 元的图解先建立意义。真正代码沿用现有示例的整数分：10000分=100元；会员9000分=90元；活动8000分=80元。字幕与旁白逐字一致。代码是核心逻辑摘录，完整校验和舍入规则留在配套文章。
- 先在03建立具体会员函数，04第一句句首“策略模式”才出现主术语标签，至少显示63帧。口播不念英文代码标识符，用“会员函数”“活动函数”“算价参数”，画面必须明确member、campaign、pricing的对应。
- 正文仅两处代码布局：05–06同一调用处；07起在固定区域加入最小结算逻辑，08–11沿用该区域，不另开完整代码或类型/异常/选择函数窗口。02旧判断用白话条件图，不展示第三处源码。
- 全程深色canvas，无比喻、实物或假应用窗，不加装饰进度条。原金额、当前办法、结算和返回结果逐步引入；不常驻独立“调用方”大框。函数始终是名称，金额始终带单位，两者不得互相变形。
- 章节入口03、05、12先口头交代方向，再启动新细节；不以“已经看懂”作为旁白前提。资料基线见research.md，理解路径和参考拆解见docs/strategy-beginner-reference.md；旧稿技术/机器检查不作为新手已理解的证据。
