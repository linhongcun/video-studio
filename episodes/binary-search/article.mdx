## 先看清要找什么 {#problem}

LeetCode第704题给出一个**已经按升序排列、没有重复值的整数数组**，以及一个目标值。我们要判断目标是否在数组里：找到就返回它在原数组中的下标，找不到返回`-1`。题目要求`O(log n)`时间复杂度。[^problem]

本片自行选取的教学示例是：

```text
数值： 1  3  5  7  9 11 13 15
下标： 0  1  2  3  4  5  6  7
目标：13
```

下标从0开始，因此13在下标6，答案是`6`。答案既不是目标值13，也不是“第7个”这个从1开始数的位置。Python序列的正常非负下标同样从0开始。[^sequence]

这里“已经有序”是输入条件，程序不需要先排序。若把无序输入先排序，再返回排序后的下标，会改变原题要求的位置含义；排序本身的开销也不能藏进`O(log n)`查找成本。

## 为什么能排除一半 {#halve}

既然数字已经从小到大排列，就可以利用一次比较排除一整段候选。这种每次选取中点、缩小候选区间的方法叫**二分查找**。

本期只使用闭区间版本：`left`和`right`都指向仍需检查的候选，范围记为`[left,right]`。最初是`[0,7]`，包含原数组的全部8个位置。中点下标这样计算：

`mid = left + (right - left) // 2`

`//`是向下取整的整数除法，所以偶数个候选时取中间靠左的一格。[^division] 初始中点为下标3，值是7。

### 从7小于13，到整个左半段都不可能

7小于目标13。关键并非只有7不匹配：因为数组升序，7左边的1、3、5也都小于13。因此下标0..3这一整段都不可能是答案。

把`left`移到`mid+1`，即下标4；`right`仍是7，候选只剩`[4,7]`。原数组中的数字和下标都保留，动画里的变淡仅表示已经排除。

接着用同一规则继续：

| 轮次 | 比较前候选范围 | 中点下标 | 中点值与目标 | 动作 |
|---:|---|---:|---|---|
| 1 | 0..7 | 3 | 7 < 13 | left变为4 |
| 2 | 4..7 | 5 | 11 < 13 | left变为6 |
| 3 | 6..7 | 6 | 13 = 13 | 返回原下标6 |

这里只访问了三个中点，不需要逐个检查数组中的其他数字。“三次”指三轮中点查找；程序里的相等与大小判断可能执行不止三个布尔比较。

### 为什么不会错过答案

每轮开始时都保持一个条件：**如果目标存在，它的下标仍在当前候选范围内**。

- 中点值小于目标：中点及其左侧候选都不可能匹配，保留`[mid+1,right]`。
- 中点值大于目标：中点及其右侧候选都不可能匹配，保留`[left,mid-1]`。
- 中点值等于目标：直接返回中点下标。

每次排除都有升序关系作依据，而且包含已经比较过的中点。这样既保留可能的答案，也让候选范围严格缩短。只有“取中点”而没有安全排除的依据，并不能构成正确的二分查找。

## 找不到时怎样结束 {#missing}

找到的情景已经结束。现在**换成目标8，从全部候选重新开始另一轮查找**；不要沿用上一轮找13时剩下的区间。

| 轮次 | 比较前候选范围 | 中点下标 | 中点值与目标 | 动作 |
|---:|---|---:|---|---|
| 1 | 0..7 | 3 | 7 < 8 | left变为4，剩4..7 |
| 2 | 4..7 | 5 | 11 > 8 | right变为4，只剩下标4 |
| 3 | 4..4 | 4 | 9 > 8 | right变为3，范围为空 |

第三轮前`left == right == 4`，最后一格仍有可能匹配，因此必须比较，循环条件应写`left <= right`。比较9与8之后，右边界移到3，左边界仍是4，出现`left > right`。这时闭区间没有任何下标，查找结束，返回`-1`。

`-1`是题目约定的“没有找到”，不应再用它去访问`nums[-1]`。Python的负下标会访问末尾元素，这是另一层语义，不能把“未找到”误变成取最后一个值。[^sequence]

### 两个容易写错的边界

`left = mid + 1`和`right = mid - 1`都跨过已比较的中点。若闭区间版本把左边界写成`left = mid`，只剩两格时可能重复得到同一个中点，范围不再缩短。

同样，不能直接把另一种半开区间写法里的`left < right`或`right = mid`拼进来。它们各自需要不同的不变式和结束处理；本片只讲这一套闭区间约定。

## 写成完整 Python 程序 {#code}

下面程序可以直接用于本题的Python提交，与视频片尾显示源使用同一份完整实现。

```python
class Solution:
    def search(self, nums: list[int], target: int) -> int:
        left, right = 0, len(nums) - 1

        while left <= right:
            mid = left + (right - left) // 2
            if nums[mid] == target:
                return mid
            if nums[mid] < target:
                left = mid + 1
            else:
                right = mid - 1

        return -1
```

每轮先检查区间是否非空，再计算并访问中点。成功时直接返回原下标；循环结束时统一返回`-1`。输入数组不被修改，也没有创建切片。

### 时间和空间

若当前有`m`个候选，未命中后最多保留`floor(m/2)`个。范围逐轮至多减半，所以查找轮数为`O(log n)`；每轮只进行常数次的下标运算和比较。按题目整数范围与常见单位成本模型计，时间复杂度为`O(log n)`。

迭代程序只维护左右边界和中点等固定数量变量，额外空间为`O(1)`，不包含题目给定的输入数组。程序没有递归调用栈，也不把数组复制成越来越小的子数组。

### 边界与验证范围

- 单元素数组：相等返回0，不相等返回-1；最后一格不能跳过。
- 两个元素：可以命中左端或右端，也可以返回-1，每次未命中都必须缩短范围。
- 目标小于最小值、大于最大值或落在两值之间，都能以空区间结束。
- 官方输入至少有一个元素。该实现对空数组也会直接返回-1，这是额外健壮性，不把它说成官方必测条件。
