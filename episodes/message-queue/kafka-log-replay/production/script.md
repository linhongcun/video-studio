# Kafka日志重放：消息读过了，为什么还能重读？

唯一问题：原日志与消费组恢复进度怎样共同支持重新读取，何时已经不能重读。

画面约定：沿Kafka style-v1，不可变配色，保持P0的E01/订单7042/offset0、E03/订单7044/offset1原位；P1含E02/E04，已处理且两组提交均为2，只作背景。开头是订单通知排查功能的重读目标，02明确回看首次读取前，非无解释倒退。通知组三实例稳定N1/P0、N2/P1、N3无分区；积分组S1/P0+P1。只对P0展开动作。按poll返回/应用完成/commit分别改变状态，不把position当成commit或业务状态。

固定传统consumer group、Kafka Java 4.4.0语义、enable.auto.commit=false、max.poll.records=1；逐条读取的教学模型，非Broker实测。重放先停通知整组（含idle成员），重置仅P0的已提交下一条位置，重启后才恢复读取位置。P1与points组不随reset变化。retention示意删除整个满足条件且已实际清理的旧封闭segment(0/1)，不按单条到点立即删除、不重编号。完整操作条件/参数和reset到已删范围时的处理留文章；不画CLI重置0成功取回已删记录。
