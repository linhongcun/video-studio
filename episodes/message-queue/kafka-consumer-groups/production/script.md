# 多个消费者：分工处理，还是每人一份？

本片唯一回答：Kafka里，消费组与组内实例怎样决定同一批事件的读取归属。

画面约定：Kafka style-v1 暖炭灰/橙/冰蓝；纯机制canvas，首镜为通知与积分功能的事件接收列表。四个虚构订单事件E01–E04，P0=E01/E03，P1=E02/E04；传统消费组、稳定分配。读取副本沿路径移动，原日志一直保留。不同情景先显式重置到相同数据与开头，非同一笔业务的连续重复执行。

旁白不读eventId/offset/group英文。完整配置、重平衡与保留条件在文章，视频以简明标识保留必要前提；不暗示收到等于业务成功。参考资料在正文后无旁白5秒，原题与机构列表。

旁白：四笔订单都已提交，通知服务和积分服务，都需要收到每一笔订单事件。可通知只收到两条，积分也只收到两条，另外两条去哪了？

### 03 shared

旁白：两个服务各有一个消费者，负责读取事件。但它们用了同一个消费组，也就是共同分工的一组消费者。

### 04 wrong-read

旁白：在稳定分配下，通知读零号分区，积分读一号分区。所以各自只收到两条；同一个消费组里，不是每个实例都收到一份。

### 05 reset

### 06 notify-read

旁白：通知组只有一个实例，两个分区都分给它。它依次读取两个分区，四条订单事件就都收到了。

### 07 points-read

旁白：积分组也有自己的读取进度，同样读取这两个分区。通知组读过的记录仍然保留，积分组也能收到完整的四条。

旁白：第一个通知实例收到两条，第二个收到另外两条，组内合起来仍是四条。积分组的订阅不受影响，它依然能收到完整的四条。
