# MQ08视觉方向

本片沿共享Kafka style-v1的暖炭灰、橙、冰蓝及真实Kafka标记。新15镜按重试预算/同目录恢复/退出处置/双边界四章推进，不复制上期镜数或物理动作。先建立同一P0内E01@0和后续E02@1，再就地引入notify:E01状态、名额、到期门和DLQ。

原日志左固定，保留两条记录；中间是本机状态/三个名额；右边随当前动作显示业务调用或死信日志。原进度与业务结果分开；IN_FLIGHT崩溃显示未知，不当成明确失败。暂停是本地交付门，别画退回Broker、删除源记录、把消息搬到DLQ或普通Topic自动延时。

每次门按到期且有余额→先保存+1/进行中→调用展开。写成但尚未调用便退出也占一个名额，图中“已用”指预留预算，不宣称准确完成次数。04持续poll用于维护活跃与网络，不触发handler。05–06进程A→B，后续DLQ窗口B→C；producer当前Future/观察值不跨进程继承，物理DLQ日志与持久journal分别保持。

07成功、08失败从第三次未开始共同点明确reset；09永久从0名额reset；10用文字定位回到耗尽路径；13目标失败和14崩溃窗从DLQ发送前reset。右上/顶部路径标明当前情景，不用密集总表。结论标题/脚注随model阶段守卫，不先宣告完成。

11 send返回、日志已追加、成功metadata、本机DLQ_CONFIRMED四步分开；12另起原commit请求，成功回调后才resume；13最终报错保留pending/原0。14日志可能已有E01@0，新进程没有旧Future，重发可得E01@1。

15是明确概念回顾，画稀疏分支而非把成功也接入DLQ：业务成功→原commit；临时失败且余名额→等到期；永久拒绝/预算满→待处置→DLQ确认→原commit。未解决分支不伪造业务成功或清空重复记录。
