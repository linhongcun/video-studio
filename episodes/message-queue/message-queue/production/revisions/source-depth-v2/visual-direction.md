# MQ01 source-depth-v2 visual direction

保持不可变Kafka style-v1，纯机制canvas与真实功能语义的订单教学页分开。旧封面由root发布时保留，当前D不生成/复制封面图片。

唯一视觉因果：任务字段→值字节→本地缓冲→P0日志位置0/下一写1→Fetch从0→解码文本→客户端下一读1→应用解析字段→通知业务执行/另存结果→页面查询。所有对象沿E01/订单7042对应。

03–06只突出存储所需结构，09–11只突出读取/应用业务结构，不同时满屏显示三种位置值。源记录追加后保持原位，读取只运输副本。05运输期间日志空占位细行隐藏，避免移动标签覆盖旧文字；04移动路径保持y512，避开底部说明。09先只展示解码文本，position先变1、poll返回，再出现应用字段卡，不能以JSON解析作为客户端position推进原因。10的调用箭头在消费者内部，不从Kafka再发一次读取箭头。

字节预览来自模型实际UTF-8值内容，不是完整Kafka日志字节布局；编号是分区逻辑offset，不是物理地址。存储画面不把append做成每条立即fsync。仅第一次业务任务定义时显示应用task字段，不由Broker解释task执行程序。

无字幕预演从Main的hideSubtitles:true产生；data-model-state对应实际同源快照，data-travel-record独立标记运输体，日志/读取位置/业务状态分别有可审DOM属性。自身和独立QA按实际声轨阶段查看中间态与跨镜，不以静态端点代替动态。
