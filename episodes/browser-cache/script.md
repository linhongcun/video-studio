# EP.07 重制版 script.md

- 系列：浏览器与网络
- 标题：同一个网页，第二次打开为什么快这么多？
- 主线：同一个网页第一次等好几秒、第二次一下全显示 → 第一次从网上下载标志、商品图、脚本、样式 → 浏览器在电脑上存一份，叫浏览器缓存 → 第二次直接用电脑里的文件 → 开发者工具看见「(disk cache)」 → 直接用也有期限 → 第一次下载时服务器用 Cache-Control 说明有效期 → 看见 3600 秒、一小时的设置 → 一小时内直接用，普通情况下连请求都不发 → 有效期由网站按文件变化频率决定 → 过期先问网站，没换继续用，换了下载新的再存 → 回到开场 → 一句回顾 → 讨论题 → 下期预告。
- 目标：20 镜，约 2:49；每镜旁白 31–39 字，每镜 7.5–9.3 秒、225–279 帧；只跟同一个网页和同一份商店标志推进。
- 时长估算：沿用 EP.06 重制版口径，即 EP.05 配音实测语速（cdn-v1/words.json：4.54 字/秒），句间停 0.35 秒，镜间停 0.70 秒。本稿旁白 689 字、27 句，逐镜按「字数÷4.54＋0.35×（句数−1）＋0.70」估算，每镜取整到 0.1 秒后合计 168.1 秒（2:48），30 帧/秒，共 5043 帧。句数以句号、问号、叹号为界；逗号处连读，不另加固定停顿。镜间停顿计入镜尾，不另插黑场；最终以整轨重配实测为准。
- 画面约定：只有实际网页、地址栏及网页上的开发者工具使用 browser；表格、计时条、说明文字均使用 canvas，全屏干净底色，不加浏览器外壳、不写网址。实际网页固定为 `shop.example`：页顶抽象圆弧商店标志，下方两张「示例商品一」「示例商品二」卡片，各有商品图与「立即购买」按钮。商品图是实际加载的抽象彩色纹样图片，不含实物或设备图标；标志、图片、按钮的位置全片固定。只呈现软件界面，不画任何实物、设备外形或设备图标。表格不用包裹形文件图标；加载完成的先后不代表下载必须串行。全片的「第二次打开／再打开」都是新开标签页、在地址栏输入网址打开，不用刷新（画面和旁白均不出现「刷新」）。全片不使用比喻。每镜四行顺序固定为 frame、画面、旁白、屏幕文字；屏幕文字列出叠字与本镜重点，固定网页文案按此处沿用。

## 公开出处

以下为公开来源及本稿使用位置；链接与章节已于 2026-10-21 11:12（北京时间）在线核对。

1. MDN《HTTP caching》：[原文](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching)。Private caches 用于镜 4–7、17–18：浏览器缓存只供这一个浏览器使用，不是网站替所有人共用的一份；本片用「你电脑里」说明位置，不承诺跨浏览器共享。Fresh and stale based on age 用于镜 8–14、17–18：有效期内可直接使用，超期后成为过期内容。Validation 用于镜 14–16：过期不等于立刻丢弃，向服务器确认；未变可继续用，已变获取新内容。本片只讲确认的结果，不展开确认的编码机制。
2. MDN《Cache-Control》：[原文](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cache-Control)。用于镜 9–13：`max-age=N` 表示响应生成后 N 秒内新鲜，不是每次打开都重新计时。镜 11–14 的「存下后」采用本例传输很短、存下时年龄近零的简化；不是规定从写入电脑才统一开始计时。
3. RFC 9111《HTTP Caching》：[原文](https://www.rfc-editor.org/rfc/rfc9111.html)。§4.2 Freshness 用于镜 8–14、17–18；§4.3 Validation 用于镜 14–16（镜 15 的确认以首次响应带 ETag、Last-Modified 为前提，§4.3.1）；§4.2 中年龄达到有效期即过期，用于镜 14 在 60 分钟变橙；§5.2.2.1 max-age 用于镜 9–13。镜 12 的「不发请求」限普通情况；§5.2.2.4 的 no-cache 例外留给文章，不进入画面和旁白。本片未讨论其他例外，也不把确认文件变没变说成每次都要重新下载整份。
4. Chrome DevTools《Network features reference》：[原文](https://developer.chrome.com/docs/devtools/network/reference)。Disable cache 一节用于镜 6–7：重复访问时，文件可以由浏览器缓存提供，工具里能看到相应记录；镜 7 展示大小栏 `(disk cache)`。演示保留正常缓存行为，不在画面展开禁用操作。镜 10 使用同一工具查看第一次下载的响应头，仅显示任务指定的一行。
5. Chrome DevTools 官方简体中文词库 [zh.json](https://github.com/ChromeDevTools/devtools-frontend/blob/main/front_end/core/i18n/locales/zh.json) 与源码 [NetworkDataGridNode.ts](https://github.com/ChromeDevTools/devtools-frontend/blob/main/front_end/panels/network/NetworkDataGridNode.ts)：用于镜 7。源码中大小栏文字 `diskCache: '(disk cache)'`；zh.json 中 `panels/network/NetworkDataGridNode.ts | diskCache` 的译文仍为 `(disk cache)`（同文件 memoryCache 译为「（内存缓存）」，悬停说明 servedFromDiskCacheResourceSizeS 译为「通过磁盘缓存提供，资源大小：{PH1}」），故画面用英文原文、半角括号，中文标注解释为磁盘缓存。2026-10-21 11:35（北京时间）核对 main 分支。
6. RFC 2606 §2：[原文](https://www.rfc-editor.org/rfc/rfc2606.html#section-2)。用于镜 1、2、6–10、12、15–19 所有实际网页地址栏：`.example` 是保留的示例域名；画面中的 `shop.example` 不是现实商店，也不是实测站点。
