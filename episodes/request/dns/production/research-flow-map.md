| [RFC 9499（2024）](https://www.rfc-editor.org/rfc/rfc9499.html) | §4 Referrals、§5 TTL、§6 Stub resolver / Iterative mode / Recursive mode / Recursive resolver / Authoritative server | 递归解析器可查自身缓存，或替客户端向其他服务器查询；转介把下一处查询信息返回询问者；本例解析器自己继续查询，客户端不直接问根/TLD。缓存回答是通常行为，不能说所有递归实现必然缓存。TTL是通常可缓存的最长时间，可能提前移除；不宣称每次都必须重新从根开始。 |
| [RFC 1034（1987，仅参考）](https://www.rfc-editor.org/rfc/rfc1034.html#section-5.3.3) | §5.3.1、§5.3.2缓存过期、§5.3.3算法四步与4a/4b | 先查本地信息；选择服务器并发送查询；答案返回并可缓存；收到更好的转介后重新选择服务器继续。固定解析器中心的往返边据此设计，根/TLD不画成把客户端请求向下转发的链。省略别名、错误恢复等超出本期原范围的路径。 |
| [RFC 2606（1999，仅参考）](https://www.rfc-editor.org/rfc/rfc2606.html#section-2) | §2保留的文档示例域名 | `shop.example`是教学保留域名，图不是真实公网解析输出。 |
| [RFC 5737（2010，仅参考）](https://www.rfc-editor.org/rfc/rfc5737.txt) | §3–4 | `203.0.113.10`属于文档示例地址块，不声称是可公开连接的真实网站地址。HTML访问429后实际改读官方TXT。 |
