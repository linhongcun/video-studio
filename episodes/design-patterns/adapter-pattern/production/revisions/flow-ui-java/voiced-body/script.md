# 《适配器模式：接口对不上，怎样接入新服务？》

2026-10-25（北京时间），设计模式D03，制作issue #165。root与独立编辑审读已通过本稿叙事/概念门；真实配音、动态、成片和上线另行验证。本稿12镜24句，正文讲思想与职责，不逐行讲Java语法，最后独立5秒Java关键节选供暂停。

## 贯穿案例与时间视角

- 商家在订单17的详情点击“发送发货提醒”，收件人`buyer17@shop.example`、正文“订单17已发货”。SDK为本项目教学模拟，不作真实外发、不推断真实厂商架构。订单、地址、消息和Q17均为示例。
- 01先演一次产品操作，显示“已受理·等待送达回执·Q17”。02首句“接这个服务前”转到开发接入前的视角，03–04解释职责和结构，不在正在运行的请求中临时创建适配器。05明确“再回看刚才那一次提交”，进入同一次调用的机制回放；不重新点击/不另发一条，08同一Q17回到原页面。
- 业务目标仅为提交提醒并取得受理结果，不承诺消息送达。原服务接受请求与后续消息处理分开，`QUEUED/Q17`在本例映射`ACCEPTED/Q17`，不是已送达。
- 四角色：业务方ShipmentReminder依赖目标通知约定Notifier；NotificationAdapter履行该约定、持有VendorSdk；先转入参、真实委托，再转回参。Target是结构契约，不是运行中转节点，实际请求由业务方直接到适配器再到服务。
- 仅一条受理主链。09的拒绝/未知是规则说明，不改写Q17主线或重置发第二条；技术异常/超时不能假报已受理，也不能当作确定拒绝。更多异常、第二服务与回执查询留图文。
- 目标约定不变时，服务使用细节可以集中在适配器；创建、接线、配置仍要调整，不宣称系统零变更，不靠改名补出已有服务没有的能力。
- 正式首现cue只有04第一句句首“适配器模式”，按共享真实起音引入至少63帧。其余结构/状态按真实句级区间展开，不伪造内部词级时间。03/05/09先口头承接再启动新章节动作。
- 片尾Java节选来自`remotion/src/java-card.json`，与实际编译的`demo-java/AdapterDemo.java`同源；四角色名对应结构，明确暂停/节选，完整程序在图文。保留自然语速，不靠加速压内容。
