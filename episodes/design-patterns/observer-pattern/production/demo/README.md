# 可选实现与行为验证

视频只讲设计职责。这里提供一种 Python 落地方式，供图文附录复查，不把函数、参数或类写法当作观察者模式的定义。

从仓库根运行：

```sh
python3 episodes-codex/observer-pattern/demo/verify.py
```

本例约定：单进程、单线程；订阅时不补发历史；同一观察者不重复登记；状态确实改变后，按通知开始时的订阅名单快照，同步依登记顺序通知。取消对后续事件生效。接收者异常直接向外传播并停止剩余通知，已经改变的订单状态不回滚；无自动重试。禁止接收通知时再次修改来源状态，未实现并发、持久化和跨进程传递。这些都是本例选择，不是观察者模式统一保证。

摘要负责显示最新接收状态；变化记录按收到的通知追加订单号与新状态。贯穿故事使用十七号订单：待付款→已付款时摘要和变化记录均收到；随后取消摘要，已付款→已发货时只有变化记录收到，记录中依次保留“订单17 已付款”“订单17 已发货”。摘要保留最后接收的已付款，并应在画面注明已取消订阅/停止刷新，不能暗示它仍是实时状态。报告中的记录条数只是已收到事件数，不是订单数量或成交数量。

`verified-results.json`由实际运行生成，另验证零订阅、无变化不发、同步顺序、通知中取消、异常和重入拒绝。此证据说明一种实现的行为，不能证明设计思想已教清，也不能证明观众理解。
