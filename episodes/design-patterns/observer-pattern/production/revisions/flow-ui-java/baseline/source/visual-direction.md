# D02 观察者模式：视觉与连续性约定

本说明服务最终12镜24句、五章，不改变脚本。具体帧点由配音后的冻结分镜和`motion.ts`定义；本文不虚构尚未取得的时间。视频不展示代码、语言语法、密集类图、实物比喻、假应用外壳或装饰进度条。

## 要让动作解释的关系

变化来源是订单；观察者是已订阅的订单摘要和变化记录。来源维护当前接收者名单，名单从属于来源，不能画成额外的调度服务。共同通知约定是“订单号＋新状态”，作为连线或数据注解，不画成一个会执行业务的新actor。

画面位置保持稳定：来源左侧，名单在来源内部/紧邻来源，摘要右上，变化记录右下。登记箭头朝来源，通知路径从来源朝当前接收者；不把路径方向互换。来源青蓝，当前通知/响应青绿；退出后摘要降低亮度并明示停止接收，不能只凭颜色解释。

01先展示使用场景：商家处理订单17，付款后摘要需更新、记录需留痕。第一帧即有主体，不黑屏，不让观众先读一张内部框图猜用途。教学示例明确标注。

02直接方案展示来源内部两个具体通知安排。03先用口头转向，再逐一登记接收者，使名单形成。04在真实起音引入“观察者模式”，把摘要和变化记录明确对应为观察者；不能只在总标题写术语。

首次通知与第二次通知是同一订单连续经历的两次变化，不是两个情景重置。05到06不能硬切回待付款，也不能在05提前把两个响应都完成。摘要先处理完，记录才收到，箭头不可同时扇出。通知交代已发生的事实，不画成摘要/记录命令来源付款或发货。

取消不删除历史：08把摘要从当前名单移除，撤掉其后续通知路径，原摘要位置仍在，标注“已停止接收/最后收到”。09来源继续变成已发货，摘要不更新；既能看出未收到，又不会把旧值当成当前源状态。变化记录保留上一条后新增第二条，不替换上一条，也不重复累计。

## 章节、术语与标签

五章分别为`why`01–02、`subscribe`03–04、`notify`05–07、`unsubscribe`08–09、`boundary`10–12。03/05/08/10先承接和说方向，再启动该章新动作。章节标题只是辅助，不代替口头衔接。

三个首现cue均由共享声学起音计算：03第二句“订阅”、04第一句“观察者模式”、08第二句“取消订阅”。标签在规定窗口内入场，完整可见至少63帧；不靠猜内部词时间声称词级对齐。对象和动作先建立，再给术语；不把所有术语放在首屏。

主要展示优先级为当前执行动作、它影响的对象、最小上下文。标题、当前名单与说明不能遮住数据令牌或落点。待处理/已收到/已停止接收的提示必须与同一帧主体状态一致；维护收益仅在共同约定不变前提下成立。

## 关键连续小样与最终媒体审查

预演至少覆盖03名单形成、05→06先改状态再依次通知、08→09取消后再次变化的连续过程，包含入场、移动中间态、到达前后与停留。关闭旁白字幕复核，实际composition props和产物中必须真正无字幕；静帧和调用参数不足以证明这一项。

正式MP4另查看首次状态更新前后、两次各自接收前后、取消前后、第二次只沿剩余路径送达、片尾历史值和当前值；核对编码实际结果与预演，不以文案正确或渲染成功替代动态表达。记录实际执行者/时间点与范围，不冒称全片人工听辨、逐字ASR或新手理解实验。

文章采用响应式SVG解释职责和取消后的最终状态，名单不是独立actor。语言实现属于文章可选拓展；图文不承接视频未解释完的核心定义、因果或适用边界。
