# 第三期 plan：输入网址后，怎么找到服务器？（DNS）

- 系列：EP.03，接第一期《一次 HTTP 请求是如何完成的？》的第一步
- 受众：零基础初学者；口吻和前两期一致，用科普口吻，不写面试话术
- 规格：1920×1080，30fps，时长 120–160 秒；旁白用 MiMo「冰糖」，句间停顿 0.28 秒；响度 −16 LUFS；BGM 用 Wallpaper，比人声低 12 dB
- 发版：新增一期，版本号 v0.7.0；草稿阶段的 PR 不升版本
- 贯穿比喻：查电话簿。知道名字（域名），要查到号码（IP 地址）才能打过去

## 章节（6 章）
1. 开场：浏览器只认 IP 地址，人只记得住名字，于是需要一本电话簿
2. 先翻自己的小本子：浏览器缓存、系统缓存、hosts 文件。命中就直接返回，画面上要表现出“快”
3. 请教查号台：递归解析器，比如运营商 DNS，或 1.1.1.1、8.8.8.8 这类公共 DNS，由它替你跑腿
4. 一层层往上问：根服务器只告诉你 .com 该去问谁，.com 的服务器告诉你 example.com 归谁管，权威服务器给出最终的 IP。画成一条往返路线
5. 记下来，下次更快：TTL 和各级缓存；改了 DNS 记录，为什么要等一阵才生效
6. 回顾：用一张图串起完整路线，接回第一期“拿到 IP，再建立连接、发出请求”

## 准确性要求
- 根服务器有 13 个名字（a 到 m），但每个名字背后都是遍布全球的多台机器，使用任播技术。不能写成“全世界只有 13 台服务器”
- 递归解析器负责逐级查询；它和各级服务器之间是“迭代查询”。术语只点到为止
- DNS 查询通常走 UDP 53 端口，回应过大时改用 TCP；DoH/DoT（加密 DNS）最多一句带过，不展开
- 不写具体的毫秒数、服务器数量这类统计数字，除非有标注日期的来源
- 资料来源要看日期，优先 2020 年以后；更早的标「仅参考」，不能作为依据
