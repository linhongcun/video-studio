- 文章提醒：以下只进文章，不进本片旁白或画面。
  - Redis 名字，以及用 EXPIRE 设过期时间、用 DEL 删除，逐字依据见公开出处第 2、3 条；TTL 文档第 4 条只用于说明剩余时间，不演示工具命令。
  - 为什么删除缓存、不直接改缓存里的值：删除可以重复做，结果一样；并发时直接改值可能把旧值写回。依据为公开出处第 6 条 NSDI'13 原句 "We choose to delete cached data instead of updating it because deletes are idempotent."
  - **先改库再删缓存也还留一个很小的窗口（Deming 必改 2）**：一个读请求在改价之前发现缓存里没有，从数据库读到旧价 199；这时后台把数据库改成 169 并删除缓存；这个读请求之后才把 199 存回缓存，旧价就又留在缓存里，直到过期时间到点。所以先改数据库、再删除缓存只是大大缩小出错的机会，不能保证缓存和数据库时时相同，过期时间正是兜这种情况的底。依据：公开出处第 6 条 stale set 原句 "A stale set occurs when a web server sets a value in memcache that does not reflect the latest value that should be cached. This can occur when concurrent updates to memcache get reordered."，以及第 1 条 AWS TTL 一节 "This approach catches application bugs, ... Eventually, the cache key will auto-expire and get refreshed."。论文用租约（lease）解决这一问题，文章只点名、不展开。
  - 删除没成功时重试，以及先删缓存还是先改数据库的顺序问题（Nolan 审定：只放文章），延迟双删、消息队列重试、binlog 订阅、主从延迟、最终一致、缓存淘汰、旁路缓存 Cache-Aside 名字，都只放文章；这些写成减少出错窗口的办法，不说成能根除问题。文章不得出现绝对承诺式的一致性说法。
  - X-Cache 不是标准字段，很多 CDN 也用 X-Cache（那里指 CDN 缓存）；本片只沿用 EP.08 的网站自设标记，不增列公开出处。
  - 讨论题参考答案：不适合，付款时要读数据库里的权威价格，商品页展示允许旧几分钟。依据为公开出处第 1 条 AWS online checkout 原句。答案只放文章，镜 19 不给答案。
  - 提醒读者先开开发者工具再打开网页，避免漏掉工具打开前的请求。
