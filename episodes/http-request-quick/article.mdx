每天你都会在浏览器里打开几十个网页，而每打开一个页面，背后都至少有一次 HTTP 请求。HTTP 是一种“请求—响应”协议：浏览器问一句，服务器答一句。下面按视频的五个章节，把这一问一答拆开来看。

> 为了聚焦主线，本文不展开域名解析（DNS）、建立连接（TCP）和加密（TLS）这些网络细节，只讲 HTTP 这一层。

## 1. 按下回车之后 {#ask}

{/* 配图：浏览器地址栏里输入 https://example.com，光标停在末尾，旁边一个问号 */}

你在地址栏输入 `https://example.com/index.html`，按下回车。从这一刻起，浏览器要做的事很明确：向这个网址背后的服务器要一份内容。它“要”的方式，就是发一个 HTTP 请求。

## 2. 浏览器发出请求 {#request}

{/* 配图：信封形状的数据包，三行标签依次是 GET、/index.html、Headers */}

一个 HTTP 请求就是一段有固定格式的文本，最少包括三样东西：

- **请求方法**：想做什么。打开网页用的是 `GET`，意思是“把这个资源给我”。
- **路径**：要哪个资源，比如 `/index.html`。
- **请求头**：附加信息，比如要访问哪个网站（`Host`）、能接受什么格式的内容（`Accept`）。

一个最小的请求长这样：

```http
GET /index.html HTTP/1.1
Host: example.com
Accept: text/html
```

第一行叫请求行，写着方法、路径和协议版本；下面每一行是一个请求头。请求头之后是一个空行，`GET` 请求通常到这里就结束了，没有请求体。

## 3. 服务器处理请求 {#server}

{/* 配图：服务器机柜指示灯闪烁，左边从文件夹里抽出 HTML 文件，右边齿轮转动生成内容 */}

服务器收到请求后，先看方法和路径，弄清楚对方要什么。接下来通常有两种做法：

- **直接找文件**：路径对应硬盘上一个现成的文件，比如 `index.html`，读出来就行。这叫静态内容。
- **现场生成**：交给程序处理，比如查数据库、拼出当前用户的页面，再生成 HTML。这叫动态内容。

不管哪种，最后都要把结果装进一个响应里发回去。

## 4. 服务器返回响应 {#response}

{/* 配图：响应包上亮起绿色的 200 OK，下面展开一小段 HTML，沿虚线飞回浏览器 */}

响应同样是固定格式的文本，分三部分：状态行、响应头和响应体。

```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Content-Length: 73

<html><head><title>Hello</title></head><body><h1>Hello</h1></body></html>
```

- **状态码** `200 OK` 表示请求成功。你可能也见过 `404 Not Found`，意思是找不到这个资源。
- **响应头** `Content-Type: text/html` 告诉浏览器，后面的内容是 HTML。
- **响应体**就是空行之后的部分，这里是网页的 HTML 源码。

## 5. 浏览器画出页面 {#render}

{/* 配图：HTML 代码在浏览器里展开成有标题、图片、按钮的网页；底部两条箭头，请求向右，响应向左 */}

浏览器拿到 HTML 后开始解析，把标签变成页面上的标题、段落和按钮，最后画到屏幕上。如果 HTML 里还引用了图片、CSS 或 JavaScript，浏览器会为每一个再发一次请求，所以打开一个网页往往会有很多次一问一答。

## 小结

- HTTP 是请求—响应协议：浏览器发请求，服务器回响应。
- 请求的核心是**方法、路径、请求头**，打开网页用 `GET`。
- 响应的核心是**状态码、响应头、响应体**，`200 OK` 表示成功，响应体常常是 HTML。
- 浏览器解析 HTML，把页面渲染出来。

想动手看看？打开浏览器的开发者工具，切到“网络”（Network）面板，刷新一下页面，就能看到每一次请求和响应的完整内容。
