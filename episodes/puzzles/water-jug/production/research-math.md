# P03 量水：模型、六步路线与精确核验

核验日期：2026-10-25（北京时间）。目标仅为**5升壶内恰有4升**，另一个3升壶可以留水。视频讲清六步方法、两升余量与一升空位，最少操作数及相关变体只在文章讨论。

## 模型与六种操作

两个无刻度容器容量为3升、5升，初始为空；外部水源无限，并允许把水倒掉。用`(a,b)`表示3升壶、5升壶内的水量。每次只能：装满其中一壶，倒空其中一壶，或向另一壶倒到倒出者空/接收者满。不能目测任意中间刻度停止，也不能用第三个储水容器。

每次完整操作记1步，优化的是操作次数，不是耗时或用水量。六种状态转移为：

| 操作 | 结果 | 外部流量 |
|---|---|---|
| 装满3升壶 | `(3,b)` | 取水`3−a` |
| 装满5升壶 | `(a,5)` | 取水`5−b` |
| 倒空3升壶 | `(0,b)` | 排水`a` |
| 倒空5升壶 | `(a,0)` | 排水`b` |
| 3升壶倒入5升壶 | `t=min(a,5−b)`，结果`(a−t,b+t)` | 外部流量0，壶间转移`t` |
| 5升壶倒入3升壶 | `t=min(b,3−a)`，结果`(a+t,b−t)` | 外部流量0，壶间转移`t` |

向已满壶加水、倒空空壶或没有可倒空间的互倒，不改变状态。删掉这些原地操作不会破坏可达性或减少真正需要的最少步数；程序保留它们的独立核对，但最短路图不加入无效自环。

## 六步路线与水量账

| 步 | 操作 | 操作前 | 操作后 | 本次取水 | 本次排水 | 壶间转移 | 合法停止依据 |
|---|---|---|---|---:|---:|---:|---|
| 0 | 初始 | — | `(0,0)` | 0 | 0 | 0 | 两壶为空 |
| 1 | 装满5升壶 | `(0,0)` | `(0,5)` | 5 | 0 | 0 | 5升壶满 |
| 2 | 大壶倒入小壶 | `(0,5)` | `(3,2)` | 0 | 0 | 3 | 3升壶满 |
| 3 | 倒空3升壶 | `(3,2)` | `(0,2)` | 0 | 3 | 0 | 3升壶空；大壶2升保留 |
| 4 | 把大壶余水倒入小壶 | `(0,2)` | `(2,0)` | 0 | 0 | 2 | 5升壶已经倒空；小壶未满也必须停止 |
| 5 | 再装满5升壶 | `(2,0)` | `(2,5)` | 5 | 0 | 0 | 大壶满，小壶2升保留 |
| 6 | 大壶倒入小壶 | `(2,5)` | `(3,4)` | 0 | 0 | 1 | 小壶只剩1升空间，倒满即停 |

最后不是目测“大壶降到4升”停手，而是利用小壶已有2升、容量3升，只能再接收1升，自动使大壶从5升剩4升。第4步则因为倒出者空而停，不是因为接收者满；两种合法停点都实际用到。

全程互倒量依次为3、2、1升。累计取水10升、倒掉3升，终态3＋4＝7升；每一步都满足：

```text
两壶水量的增加 = 本次外部取水 − 本次外部排水
初始0 + 累计取水10 − 累计排水3 = 终态总水7
```

互倒时外部流入和流出都为0，总水量不变。不能把3升壶中的2升在第5步重置，也不能在第6步只更新大壶而不增加小壶水量。

## 完整状态图为何只有有限个状态

从整数0出发，装满、倒空和两个整数的最小值转移都保留整数水量，因此**所有可能出现的真实状态**都包含在`a=0…3,b=0…5`的24个整数对中；这里没有用整数采样去近似允许任意停手的连续问题。

任一次完整操作之后，至少一壶为空或满，所以中间的8个点`a∈{1,2},b∈{1,2,3,4}`不可达。程序从空壶出发穷尽六种操作，恰好到达其余16个边界状态，得到58条非原地有向操作。24个语法状态上的非原地操作总数是106；58专指从初态可达的16个状态，不混用两种统计。

广度优先搜索逐层得到：

| 已用操作数 | 首次出现的全部状态 |
|---:|---|
| 0 | `(0,0)` |
| 1 | `(0,5)`、`(3,0)` |
| 2 | `(0,3)`、`(3,2)`、`(3,5)` |
| 3 | `(0,2)`、`(3,3)` |
| 4 | `(1,5)`、`(2,0)` |
| 5 | `(1,0)`、`(2,5)` |
| 6 | `(0,1)`、`(3,4)` |
| 7 | `(0,4)`、`(3,1)` |

每个新层枚举上一层全部合法下一步，并排除已经更早出现的状态。单步费用都为1，因此先出现的层数就是最少操作数：0到5层没有大壶4升，6层第一次出现`(3,4)`，上面的六步路线达到它。所以本模型的单壶目标最少6步。

## 可单独检查的下界证书

[qa-math.json](qa-math.json)保留16个状态的整数势值φ（等于上表层数）。初态φ＝0，两个“大壶4升”目标的势值分别为6和7；全部58条可达合法操作都满足：

```text
φ(下一状态) ≤ φ(当前状态) + 1
```

沿任意路线逐项相加，中间状态抵消，得到操作数至少为终点势值减去0。任一单壶目标的势值至少6，所以任何允许的路线都至少6步；六步可行路线又给出上界，合起来就是最少6步。这个证书可直接逐边核查，不必仅凭“算法运行说6”接受结论。

## 与“两壶合计4升”的相关变体区分

本期终态`(3,4)`满足大壶4升，但两壶合计7升。若另要求两壶合计4升，必须继续倒空小壶，成为`(0,4)`；本路线因此需要7步。

完整图里，合计4升的可达状态是`(0,4)`和`(3,1)`，两者首次都在第7层出现，所以那个不同目标的最少步数也是7，而不是6。公开题面镜像的七步例子与此相符。视频只讲本期目标，相关变体仅在文章澄清，不引入GCD通式或额外解法支线。

## 独立程序检查与执行范围

复现：

```sh
python3 episodes-codex/water-jug/verify_math.py --output episodes-codex/water-jug/qa-math.json
```

程序先将24个整数状态、全部6种动作共144个状态动作对逐一检查。公式转移与另一套“按一升反复模拟到停点”的实现完全一致；后者只是核验内部的独立算法，**不是允许真实操作按一升任意停止**。每次转移同时核验容量、合法停点、流入流出与总水量。

随后在独立实现构建的图上运行Floyd–Warshall，与BFS到全部24个语法状态的距离逐一比较，包含8个不可达状态；最后输出16个势值和58条逐边不等式结果、完整六步路线、变体第7步及累计水账。最短前驱图还确认当前动作计数下单壶目标只有一条六步最短操作序列。

实际执行时间、脚本SHA和通过状态见`qa-math.json`。本检查是本模型的完整有限状态核验，不是随机抽样；不检查生产动画、配音、字幕、正式MP4或网页，也不把有限模型的结论推广到任意容积、任意操作或计时目标。
