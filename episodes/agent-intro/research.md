# A01 / EP.22《AI 能回答问题，怎么才能真正帮你办事？》资料核验

访问日期：2026-10-24（北京时间）。本次实际联网打开下列官方正文，核对网页日期与相关段落；不以搜索摘要、项目旧稿或聊天记忆替代公开来源。本文件核验概念与教学设定，不代表已运行真实模型、订单系统或退款实验。

## 本期范围

用同一笔合成退款咨询建立四层认识：生成回答、提出调用请求、应用执行与返回、根据结果选择下一步。只查询订单和示例政策，询问缺失信息后形成申请建议；不接真实退款接口，不创建工单。首次术语为模型、工具、智能体。代码实现、RAG、MCP、Skills、记忆与持久恢复留后续，不用其细节填满入门片。

“Agent”并无本片可以断言的唯一公认定义。本期采用一种实用架构区分：固定工作流的路径由预写代码组织；智能体允许模型在应用提供的能力与限制内动态选择。两者可以组合，固定流程也能有模型调用、条件分支和重试。

### R1 OpenAI：Unrolling the Codex agent loop

- 链接：[官方工程正文](https://openai.com/index/unrolling-the-codex-agent-loop/)
- 页面日期：2026-01-23；作者Michael Bolin。
- 实际阅读：The agent loop，尤其用户输入、模型生成工具请求、执行后追加输出、再次调用模型，以及用户追问和回合结束的段落。
- 支持主张：模型输出可以是回复或工具调用请求；运行系统执行请求并把结果回送模型；多次迭代可以出现在一轮对话内；模型也可能向用户询问信息。
- 短引：“requests a tool call”。
- 用在：04–16镜，文章roles/loop两章。
- 边界：这是Codex harness的具体工程讲解，不推导所有Agent都使用同一API、同一停止信号或同一架构。本片展示泛化后的可观察信息流，不复刻其代码或隐藏推理。

### R2 OpenAI：Function calling

- 链接：[当前官方指南](https://developers.openai.com/api/docs/guides/function-calling)
- 页面日期：动态文档，正文未标统一首发或更新日期；以本次访问为准。
- 实际阅读：How it works中的Tools、Tool calls、Tool call outputs定义，以及The tool calling flow的五步流程；Handling function calls的执行和返回要求。
- 支持主张：模型生成请求，应用侧代码执行，并把输出与调用关联后交回模型；随后可以得到最终回复，也可以继续调用。工具调用本身不意味着它已经执行。
- 短引：“Execute code on the application side”。

- 边界：本片按应用执行的只读函数展示；托管工具也可能由服务侧运行环境执行，不能因此把外部查询描绘成模型参数内部自动更新。检查订单编号和当前用户读取权限是本例应用设计，不声称模型生成调用就已经获得授权。接口和模型支持细节按制作时当前文档核对，不照抄旧教程。
