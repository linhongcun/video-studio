# 两数之和：为什么要先查，再记录？

兑现的问题：选两个不同下标，让两个值相加等于目标；怎样一次遍历找到下标对，并避免把同一格用两次？

默认观众没见过原题。01–02先建立整数数组、目标、不同下标、唯一答案与返回下标对，03才引入哈希表。教学输入为本片自造示例；官方题意与事实核验由research.md记录。干净全屏canvas，值和下标身份稳定，无比喻、假应用窗或装饰进度条。四章自然承接：problem为01–02，lookup为03–07，distinct为08–10，code为11–12；正文一处关键代码画面；末尾独立完整Python代码卡150帧，提示暂停，无字幕与旁白。术语只绑定真实句首起音，不声称句内逐词时序。

### 01 problem
旁白：给你一个整数数组，目标是九，要选出两个数，让它们相加等于九。但必须选两个不同下标，同一格不能用两次。

### 02 output
旁白：下标从零开始，三和六分别在零和三，所以返回这两个下标。题目保证恰好一组答案，两个下标按什么顺序返回都可以。
画面：同一排数组，3和6连到下标0和3；先显示3+6=9，再显示返回[0,3]；“返回下标，不是数值”，第二句补[3,0]也可及“恰好一组答案”；尚未讲算法。

### 03 lookup
旁白：题意清楚了，再看怎样知道当前的数需要和谁配对。哈希表按数值记录已经走过的下标，每次先查目标减去当前值，没查到才记录当前值。
画面：第一句以当前3和目标9建立需要6；第二句句首出现“哈希表”，建立“数值→先前下标”映射区域及空状态；箭头直接从需要6指向按值查询口，不逐行扫表；展示“先查 → 未记录才记 / 已记录就返回”的稀疏动作关系。

### 04 first
旁白：先看下标零的三，它需要六，但表里还没有任何记录。查询没有命中，再把数值三和下标零记进去。
画面：输入[3,8,11,6,15]，目标9，表初始为空；先算9−3=6，按值查询6后明确反馈“6未记录”；第二句才出现映射3→0，表内数值列和下标列严格区分。

### 05 second
旁白：走到下标一的八，它需要一，表里没有一。先收到未记录的结果，再存下八和它的下标一。
画面：表开始仅3→0，当前8；先9−8=1、直接查询1、反馈“1未记录”；随后新映射8→1出现，3→0保持固定位置，没有移动或覆盖。

### 06 negative
旁白：接着是下标二的十一，它需要负二，负数也可以正常查询。负二没有记录，再存下十一和下标二。
画面：表开始3→0、8→1；9−11=−2，查询口完整显示−2且标“负数合法”；明确未记录后才增加11→2；不把负数画为错误或非法下标。

### 07 found
旁白：来到下标三的六，它需要三，这次查到了数值三对应的下标零。直接返回下标零和三，查找结束，后面的十五不用访问。
画面：表开始稳定3→0、8→1、11→2；9−6=3，直接按键3命中第一条并返回0；随后连接数组下标0与3、输出[0,3]；15保留未访问状态，当前6不写入表，命中后没有任何insert。

### 08 reset
旁白：刚才找到了答案，接着换一个输入，看看为什么同一格不会用两次。现在数组是三、八、三，目标改成六，表也重新清空。
画面：第一句保留主例返回[0,3]；第二句明确“新输入 · [3,8,3] · 目标6”，换成三格数组并清空全部旧记录；新下标0/1/2，不把两个示例误接成同一次遍历。

### 09 duplicate-first
旁白：第一个三需要另一个三，但查询时表是空的，所以不能立刻配对。查询结束后，才记录这个三来自下标零。
画面：新例当前下标0值3，6−3=3；空表直接查询3并明确未记录，错误的[0,0]以禁止同格的小标示解释；第二句才增加3→0，本格保持已访问而不是已配对。

### 10 duplicate-found
旁白：再看八，需要负二，仍没记录，存下八和下标一。最后的三查到先前的三，返回下标零和二。
画面：第一句按6−8=−2→查询→未记录→8→1的顺序动作，表原3→0固定；第二句当前移至下标2值3，6−3=3→查询命中3→0→返回[0,2]；两个3留在不同格，同值映射不被当前3覆盖。

### 11 order
旁白：把这条规则写进程序：先查再记，表里只有当前位置之前的数字，配对下标一定不同。如果先记当前的三，再查三，就会把同一格错误地用两次。
画面：第一句以已建立的前缀记录解释不变式；正文仅此一处展示if need in seen:与seen[x] = i，按先查、后记顺序强调；第二句明确“错误顺序假设 · 回看新例下标0”，清空假设表，先写3→0再查3，错误返回[0,0]并划掉；此为错误假设，不改写新例真实结果。
