这篇文章面向会写循环和数组的读者。要解决的问题不是“排出一个上课顺序”，而是**判断给定的一组先修要求能不能让全部课程都学完**。先修表里的方向容易看反；判定为什么可以化成“有没有课能上”的问题？下面把先修表画成图，再用一个四门课的示例走完全程。

## 题意与成图 {#question}

[LC.207 课程表](https://leetcode.cn/problems/course-schedule/description/)给出 `numCourses` 门课，编号 0 到 n-1；先修数组 `prerequisites` 的每一项 `[a, b]` 表示想学 a 必须先学 b。注意方向：后一个元素才是先修课，要求返回布尔值——能学完全部课程为 true，否则为 false。[^problem]

<SourceQuote sourceId="R1" supports="这条原文规定返回能否完成全部课程的判断；题解方法由后文图结构与队列推导。" />

贯穿视频和本文的主例是一个教学示例：

~~~text
numCourses = 4
prerequisites = [[1,0], [2,0], [3,1], [3,2]]
~~~

把每一项 `[a,b]` 画成一条从 b 指向 a 的箭头——**箭头方向就是“先修课指向目标课”**。四项全部画完：0 指向 1 和 2，1 和 2 都指向 3，先修表就变成一张有向图。能不能学完，取决于这张图里有没有环：顺着箭头能走回出发的课程，就意味着这几门课互相等待，谁也无法先开始。本题只问“能不能学完”，不要求输出上课顺序，所以不需要真的排出一种拓扑序列。

## 入度与队列 {#indegree}

哪门课现在就能学？**没有剩余先修要求的课**——在图上就是没有箭头指向它的课。给每门课数一下还有几条边指进来，这个数字叫入度：入度为零的课当前就能上，先放进队列。

主例的初始入度：0 号没有入边，入度 0；1、2 各有一条，入度 1；3 有两条，入度 2。所以队列里一开始只有 0。这个“先学入度为零的点、学完删去它的出边”的过程，就是拓扑排序的 Kahn 做法。[^topo]

<SourceQuote sourceId="R2" supports="Wikipedia条目Kahn's algorithm一节给出同一过程：起点集合是无入边的节点，逐个移除并删边；若剩余图仍有边则判定至少一个环。" translation="译文：若图中仍有边则返回错误（图至少含一个环），否则返回L（一个拓扑排序结果）。" />

## 沿主例学完全部课程 {#learn}

学完一门课，就把它指出去的边删掉，后续课程的入度各减一；谁的入度减到零，谁就进队列。队列不空，进度就一直推进。

<Figure src="/video-studio/episodes/course-schedule/article/01.svg" alt="四门课的先修图：零号指向一号和二号，一号二号都指向三号。零号入度为零已学完变青；一号二号入度已清零进入队列；三号入度仍为二等待。队列行从左到右为零、一、二。" caption="自制机制图：学完一门课就删掉它指出的边，入度减到零的课进入队列。" kind="diagram" />

主例的完整过程如下。每学一门，队列里的候选都在变化：

| 当前动作 | 被删的边 | 入度变化 | 队列 |
| --- | --- | --- | --- |
| 初始 | — | 0:0, 1:1, 2:1, 3:2 | [0] |
| 学 0 | 0→1、0→2 | 1、2 各减到 0 | [1, 2] |
| 学 1 | 1→3 | 3 减到 1 | [2] |
| 学 2 | 2→3 | 3 减到 0 | [3] |
| 学 3 | — | — | [] |

学完 3，已完成的门数等于课程总数 4，返回 true。每门课进出队列各一次，每条边也只删除一次。

## 换成有环的先修表 {#cycle}

把主例的最后一项 `[3,2]` 换成 `[1,3]`：边变成 0→1、1→2、2→3、3→1。1 等 3，3 等 2，2 等 1，三门课互相等。

入度统计后，仍然只有 0 入度为零。学完 0 删掉 0→1，1 的入度从 2 减到 1——之后队列就空了。**队列空了，说明剩下的每门课都还有没解除的先修。**从任意一门沿着先修边走，课程数是有限的，迟早走回已经走过的课，这条重复路径就是环。所以不是排课顺序选错了，而是这组先修要求根本无解，返回 false。

反过来也成立：只要图里没有环，有限图上总存在入度为零的点，学完它剩下的图仍然无环，队列就不会提前枯竭，最终能学完所有课。

## 边界与实现 {#edge}

三个边界都能在同一个判定里处理：

- **官方示例 2**：`numCourses = 2, [[1,0],[0,1]]`，两门课互相先修，是最短的环，入度全为 1，队列初始就是空的，返回 false。
- **先修表为空**：每门课入度都是零，全部进队列，返回 true。
- **孤立课程**：不参与任何先修关系的课入度为零，直接可学；它只影响完成门数，不影响环的判定。

~~~python
class Solution:
    def canFinish(self, numCourses: int, prerequisites: list[list[int]]) -> bool:
        targets = [[] for _ in range(numCourses)]
        indegree = [0] * numCourses
        for course, pre in prerequisites:
            targets[pre].append(course)
            indegree[course] += 1
        queue = [c for c in range(numCourses) if indegree[c] == 0]
        done = 0
        head = 0
        while head < len(queue):
            pre = queue[head]
            head += 1
            done += 1
            for course in targets[pre]:
                indegree[course] -= 1
                if indegree[course] == 0:
                    queue.append(course)
        return done == numCourses
~~~

用列表加头指针当队列，避免出队搬移；`head` 走完即队列空。每门课入队、出队各一次，每条边删一次，时间与额外空间均为 O(n + e)，e 为先修项数。判断用的是学完门数，不必真的输出上课顺序。

可直接运行的 `solution.py`、DFS 三色判环 oracle 与轨迹测试在本期制作源码中；穷举小规模先修表核对结果一致。程序一致性并不替代视频里实际动作和配音的复核。

读完后应能解释：先修项如何映射成方向正确的边；为什么入度为零的课可以先学；队列空了为什么等价于剩余课程里存在环。**入度为零就能学，删边解锁下一门；队列枯竭但课未学完，就是有环。**
