这篇文章面向会写二维数组循环的读者。面对「腐烂的橘子」，很多人第一反应是找到一个烂橘子就从它开始往外扩——但网格里一开始可能**同时存在多个烂橘子**。如果只顾着先算完一个再算下一个，时间会被算错；如果每个烂橘子各扫一遍整张网格再取最小值，又会做大量重复工作。下面用一张 3×4 双源网格走完全程，看清为什么把所有初始烂橘子一起放进队列，就能用一遍扫描同时算出每个橘子最早腐烂的分钟数。

## 题意与网格映射 {#problem}

[LC.994 腐烂的橘子](https://leetcode.cn/problems/rotting-oranges/description/)给出一个 `m × n` 的整数网格 `grid`（`1 <= m, n <= 10`，行和列均从 `0` 开始编号），每个单元格只有三种取值：`0` 表示空位，`1` 表示新鲜橘子，`2` 表示腐烂的橘子。每经过 1 分钟，所有腐烂的橘子都会同时让上下左右 4 个方向上紧邻的新鲜橘子变烂，空位 `0` 会阻断扩散，斜对角不会传染。题目要求返回全部新鲜橘子腐烂所需的最少分钟数；只要有任何新鲜橘子永远烂不到，就返回 `-1`。[^problem]

<SourceQuote sourceId="R1" supports="这条原文直接规定每分钟腐烂仅向 4 个相邻方向的新鲜橘子扩散，不跨斜对角，也是下文不可达边界的判定依据。" translation="译文：每分钟，任何与腐烂橘子在 4 个方向上相邻的新鲜橘子都会腐烂。" />

贯穿本文的主例是一张 3 行 4 列的双源教学网格：

~~~text
r\c   0   1   2   3
0:  [ 2,  1,  1,  1 ]
1:  [ 1,  0,  1,  0 ]
2:  [ 1,  1,  2,  0 ]
~~~

其中第 0 分钟已有两个烂橘子 `(0, 0)` 和 `(2, 2)`，新鲜橘子共 7 个，空位 3 个（`(1, 1)`、`(1, 3)`、`(2, 3)`）。

## 为何初始烂橘子要一起入队 {#why-multi-source}

先看为什么不能挑一个烂橘子先一路算完。在主例中，如果我们只从左上角 `(0, 0)` 单独向外扩散：

- 第 1 分钟到达 `(0, 1)`、`(1, 0)`；
- 第 2 分钟到达 `(0, 2)`、`(2, 0)`；
- 第 3 分钟才到达 `(2, 1)` 和 `(1, 2)`。

但实际上，下方的 `(2, 2)` 在第 0 分钟就已经是烂橘子，它在**第 1 分钟**就会把紧邻的 `(2, 1)` 和 `(1, 2)` 传染掉。先算完一个源点会把别的源点近在咫尺的格子算晚；如果改为对每个初始烂橘子各跑一次完整搜索、再逐格取最小分钟数，当网格里有 `k` 个初始烂橘子时，同一张网格可能被反复扫描 `k` 遍，时间退化为 `O(k · m · n)`。

把思路对齐到题目真实的物理过程：所有初始烂橘子都在**第 0 分钟同时出发**。我们要让它们同步往外迈出第 1 分钟、第 2 分钟、第 3 分钟的步子。借助先进先出（FIFO）的队列，正好可以按层组织这个同步过程：

1. 开局先把网格里全部值为 `2` 的坐标放进队列，同时数出新鲜橘子总数 `fresh = 7`。
2. 每一分钟开始前，先锁住当前队列长度 `len(queue)`，这一轮**只从队头弹出这批当前层的橘子**。
3. 它们新传染的好橘子立即改写为 `2`、`fresh` 减一，并排到队尾，留给下一分钟统一处理。

这种先完整展开当前深度层的全部节点、再进入下一深度层的做法，就是**多源广度优先搜索（多源 BFS）**。既然所有初始烂橘子都在深度 0，每推进一层就严格对应多经过 1 分钟，因此所有到最近初始烂橘子步数为 `d` 的新鲜橘子，都会恰好在第 `d` 层被第一次碰到。[^bfs]

<SourceQuote sourceId="R3" supports="广度优先搜索先完整探索当前深度的全部节点再进入下一深度层，且通常借助队列记录已遇到但尚未展开的节点；下文据此把所有初始烂橘子一并放入深度 0。" translation="译文：它从树根出发，在进入下一深度层之前先探索当前深度的全部节点。通常需要队列一类的额外内存来记录已经遇到但尚未探索的子节点。" />

在 Python 中用 `collections.deque` 实现这个队列，队尾入队 `append` 与队头出队 `popleft` 都是近似 `O(1)`，避免普通列表 `pop(0)` 带来的线性搬移开销。[^deque]

<SourceQuote sourceId="R2" supports="这条 Python 官方文档确认 collections.deque 在两端执行追加与弹出都具有近似 O(1) 性能，适合作为队列的底层容器。" translation="译文：双端队列支持线程安全、内存高效的双端追加与弹出，两个方向的性能都近似为 O(1)。" />

## 按分钟同步扩散与去重 {#step-by-step}

沿着同一张 3×4 主例逐分钟推进，可以同时看清越界/空位跳过、双源相遇去重与防多算最后一层三个关键细节：

| 阶段 | 本层锁定长度与出队顺序 | 关键检查与新腐烂 | 队列尾新增（下一层） | 剩余 `fresh` | 累计 `minutes` |
| --- | --- | --- | --- | --- | --- |
| 第 0 分钟（初始） | — | 全网扫描收集 `(0,0)`、`(2,2)` | `[(0,0), (2,2)]` | 7 | 0 |
| 第 1 分钟 | 长度 2：`(0,0)` → `(2,2)` | `(0,0)` 上/左越界跳过，染 `(1,0)`、`(0,1)`；`(2,2)` 右空位/下越界跳过，染 `(1,2)`、`(2,1)` | `[(1,0), (0,1), (1,2), (2,1)]` | 3 | 1 |
| 第 2 分钟 | 长度 4：`(1,0)` → `(0,1)` → `(1,2)` → `(2,1)` | `(1,0)` 染 `(2,0)`、`(0,1)` 染 `(0,2)`（均被 `(1,1)` 空位挡住）；`(1,2)` 查 `(0,2)`、`(2,1)` 查 `(2,0)` 均已变 `2` 直接跳过 | `[(2,0), (0,2)]` | 1 | 2 |
| 第 3 分钟 | 长度 2：`(2,0)` → `(0,2)` | `(2,0)` 四邻无新鲜；`(0,2)` 染最后一个 `(0,3)` | `[(0,3)]` | 0 | 3 |

注意第 2 分钟里的相遇瞬间：`(0, 1)` 先把 `(0, 2)` 改成了 `2`、`fresh` 减一并推入队尾；同一分钟稍后 `(1, 2)` 向上检查 `(0, 2)` 时，看到它已经是 `2`，直接跳过。**在入队那一刻就立刻把网格值从 `1` 改为 `2`**（而不是等到出队时才改），避免了同一个格子被多路重复入队和重复扣减 `fresh`；而真正保证它被记为最早腐烂分钟数的，则是多源同时入队后的按层推进顺序。

此时最后一个新鲜橘子 `(0, 3)` 刚刚变烂并进入队列，`queue` 里还有 `[(0, 3)]` 并不为空。如果外层循环只写 `while queue:`，程序就会再多跑一轮没有任何传染发生的“空扩散”，把分钟数多加 1 变成 4。把循环条件写成 `while queue and fresh > 0:`，只要所有新鲜橘子都已变烂，就立刻停止，分钟数严格等于 3。

## 不可达与关键边界 {#impossible-and-edges}

重置网格来看 3×3 的官方示例 2：`grid = [[2,1,1],[0,1,1],[1,0,1]]`。左上角 `(0, 0)` 逐分钟向上下左右扩散，前 4 分钟传染了所有可达的 5 个好橘子（第 4 分钟染到右下角 `(2, 2)` 并将其入队）。此时 `fresh` 仍为 1 且队列还有 `[(2, 2)]`，循环进入下一轮把 `(2, 2)` 出队，它四周已没有任何新鲜橘子，队列彻底变空、循环退出。左下角 `(2, 0)` 被上方 `(1, 0)` 与右侧 `(2, 1)` 两个空位 `0` 斜向隔开，腐烂不能斜着跨过空位，循环结束后 `fresh == 1 > 0`，因此返回 `-1`。

同一套代码还能无缝覆盖其他边界，不需要写额外特判分支：

- **没有新鲜橘子（官方示例 3 `[[0,2]]` 或单格 `[[0]]`/`[[2]]`）**：初始 `fresh == 0`，`while queue and fresh > 0` 一次都不执行，直接返回 `0`。
- **只有新鲜橘子、没有烂橘子（如 `[[1,0,1]]` 或 `[[1]]`）**：初始 `queue` 为空，循环不执行，末尾检测到 `fresh > 0`，返回 `-1`。
- **只有一个初始烂橘子（官方示例 1 `[[2,1,1],[1,1,0],[0,1,1]]`）**：多源退化为单源，4 分钟全部腐烂，返回 `4`。

## 收束、复杂度与代码 {#summary}

### 完整 Python 实现

下面这份实现直接复制网格副本 `state` 以避免修改调用方原输入，与本期仓库中的可执行 `solution.py` 逐行一致：

~~~python
from collections import deque


class Solution:
    def orangesRotting(self, grid: list[list[int]]) -> int:
        rows, cols = len(grid), len(grid[0])
        state = [row[:] for row in grid]
        queue = deque()
        fresh = 0
        for r in range(rows):
            for c in range(cols):
                if state[r][c] == 2:
                    queue.append((r, c))
                elif state[r][c] == 1:
                    fresh += 1
        minutes = 0
        while queue and fresh > 0:
            for _ in range(len(queue)):
                r, c = queue.popleft()
                for dr, dc in ((-1, 0), (1, 0), (0, -1), (0, 1)):
                    nr, nc = r + dr, c + dc
                    if 0 <= nr < rows and 0 <= nc < cols and state[nr][nc] == 1:
                        state[nr][nc] = 2
                        fresh -= 1
                        queue.append((nr, nc))
            minutes += 1
        return minutes if fresh == 0 else -1
~~~

### 复杂度与独立核验范围

- **时间复杂度 `O(m · n)`**：开局扫描整张网格一次；初始为 `2` 的格子在开局入队一次，初始为 `1` 的格子只会在状态从 `1` 改为 `2` 时最多入队一次，因此每个格子最多入队、出队各一次，每次最多检查 4 个邻居。
- **空间复杂度 `O(m · n)`**：状态副本 `state` 与最坏情况下（例如网格几乎全是初始烂橘子）队列占用均为 `O(m · n)`。如果调用方允许原地修改 `grid`，可省去 `state` 复制，但最坏情况下队列空间仍为 `O(m · n)`。
- **独立测试核验**：本期 `tests/test_solution.py` 将上述实现与独立的「逐源单源 BFS 取逐格最小值」oracle 交叉比对，覆盖官方三例、边界样例、8 种 `m, n ≤ 3` 且不超 6 格的小网格形状（`1×1`、`1×2`、`2×1`、`1×3`、`3×1`、`2×2`、`2×3`、`3×2`，共 1,614 组穷举网格）以及 3,000 组至 `6×6` 的随机网格，结果一致；程序测试与成片及配音验收分别独立记录。

## 小结

回到开头的问题：**为什么要先把所有烂橘子一起放进队列？**因为现实中所有初始烂橘子是在第 0 分钟同时开始向外传染的；把它们一起作为第 0 层入队，再每轮锁定 `len(queue)` 按层推进，每一层就严格等价于同步经过 1 分钟。配合「入队瞬间改为 `2`」避免重复入队和重复扣减 `fresh`，以及「`while queue and fresh > 0`」防止最后一层多算 1 分钟，整张网格只需 `O(m · n)` 时间就能得出最少分钟数，并在队列耗尽仍有 `fresh > 0` 时准确判定 `-1`。
