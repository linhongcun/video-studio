# 爬楼梯：为什么只要记住前两个数？

唯一问题：到第 n 阶的方法数，为什么可以只保留前两阶的计数？

画面约定：1920×1080、30fps，深蓝页身配青绿与金色。题目本身的楼梯是讲解主体：人物沿真实上升台阶连续移动，地面0、每步1或2阶、落脚与终点可见；先演出三种走法，再在楼梯上的最后一步位置分组。随后同一六阶楼梯承担逐阶计数和滚动变量定位，方法数与阶编号明确区分。数字只辅助实际场景，不用横排数字框代替楼梯；无无关比喻、假应用窗或装饰进度条。完整Python代码卡沿用静态5秒，提示暂停，无正文字幕。

章节：problem（01–02）→ last-step（03–07）→ rolling（08–09）→ code（10–12）。新术语“动态规划”在08第二句句首引入，画面使用真实句起点；不声称有词级识别。

### 01 problem
旁白：给你一段三阶的楼梯，每次只能上一阶或两阶，不能越过终点。请返回恰好到达终点的不同走法数量，而不是列出具体路径。
画面：首帧就是可辨认的三阶侧视楼梯，地面0为起点，第3阶为终点，人物脚部贴合台面。依次演出从地面上一阶、再上两阶到终点，保留实际走过的轨迹；标明每步只上1或2阶、不越过终点，输出要求随后明确为走法数量。

### 02 order
旁白：以三阶为例，可以一一一，也可以一二，还可以二一。顺序不同也算不同，所以这道题返回三，而不是把后两种合成一种。
画面：三座同构三阶楼梯分别对应原走法111、12、21；人物在各自楼梯上连续运动，落点分别为1/2/3、1/3、2/3。每次跨两阶只在目标阶落脚。原走法身份和位置保持，轨迹形状和落脚顺序体现不同，落定后返回3种。

### 03 last-step
旁白：题意清楚了，先看三阶的每种走法，最后一步只有上一阶、上两阶这两类。最后一步上一阶，前面就到第二阶；最后一步上两阶，前面就到第一阶。
画面：沿用刚才三条楼梯走法，不换身份或无解释重排。突出真实最后一段动作：111和21均从第2阶上一阶到3，12从第1阶上两阶到3；末步与已有前缀以颜色区分，先看到来源位置再分组。

### 04 no-overlap
旁白：到第二阶有一一和二这两种，到第一阶只有上一阶这一种。前面的每种走法接上对应的最后一步，两组既不重复也不会漏掉，相加得到三种。
画面：在同三阶楼梯上保留前缀：111的前缀11与21的前缀2都到第2阶，各接最后一阶；12的前缀1到第1阶，接最后两阶。把三条已见走法各完整还原一次，末步长度不同使两类不重不漏，再显示方法数2+1=3；数字有“种”的身份，不冒充阶号。

### 05 bases
旁白：把同样的规则用到六阶，先从最小的结果往前算。到第一阶有一种，到第二阶有两种，这两个起点可以直接数清。
画面：明确切换为六阶实际楼梯，地面与六块逐级抬升的台面位置保持。以人物实际上一阶，以及到第二阶的11/2两种路径建立1种、2种起点；方法数徽标绑定各阶立面或相邻位置，阶编号另列，尚未计算的计数显示待定。

### 06 grow
旁白：到第三阶，把第二阶的两种与第一阶的一种相加，得到三种。到第四阶，再把三和二相加，得到五种。
画面：在同一座六阶楼梯上计算第3、4阶；从物理第k-1阶上一阶、从第k-2阶上两阶的最后一步指向目标台面，前两阶已知方法数参与相加。先有两类来源和求和过程，3种、5种再落定到第3、4阶，数字不替代脚步跨度。

### 07 thirteen
旁白：到第五阶有五加三等于八种，所以第六阶的两类走法分别有八种和五种。最后上一个台阶或两个台阶，两组走法互不重复，加起来就是十三种。
画面：同一六阶楼梯上先把第5阶8种算清，再显示从第5阶上一阶到6与从第4阶上两阶到6；两条最后步动作与8种、5种来源绑定，末步只标1阶/2阶。两组计数相加后第6阶落定13种。

### 08 dynamic-programming
旁白：结果已经算出来了，接着看计算时究竟要保留多少信息。动态规划，会复用已经算出的小问题结果，而本题的下一个结果只依赖前两项。
画面：六阶楼梯和已算计数先保持，第二句实际起音时引入动态规划；明确回看“准备计算第6阶”并复位第6阶待算状态。第4阶5种、第5阶8种高亮，更早的计数淡化但真实台面保留，说明淡化的是不必保存的计数而非楼梯本身。

### 09 rolling
旁白：准备算第六阶时，两个变量分别保存第四阶的五种和第五阶的八种。先用旧值五加八算出十三，再把两个变量整体换成八和十三。
画面：prev=5锚定物理第4阶，curr=8锚定第5阶；先在独立新值位置得到13，旧值5/8保持，再整体换成8/13，连线与阶身份同步移到第5/6阶。相邻中间态不出现先覆盖一个值再错误相加。

### 10 implementation
旁白：写进程序时，先处理只有一阶或两阶的情况，再从第三阶一路算到终点。更新这一行要先算右边的旧值，再一起赋给左边，不能覆盖一个以后再相加。

### 11 boundary
旁白：每一级只计算一次，时间随台阶数线性增长，额外只用固定几个变量。只记前两项是本题依赖关系带来的结果，其他动态规划问题未必也只记两个数。
