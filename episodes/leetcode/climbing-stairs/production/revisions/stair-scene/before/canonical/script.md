# 爬楼梯：为什么只要记住前两个数？

唯一问题：到第 n 阶的方法数，为什么可以只保留前两阶的计数？

画面约定：1920×1080、30fps、干净全屏 canvas，深蓝页身配青绿与金色；题目自身的阶格和计数节点参与解释，不画人物、拟真楼梯、比喻、假应用窗或装饰进度条。先用 n=3 建立题意与最后一步分组，再在同一条六阶节点上推进 1、2、3、5、8、13；历史结果仅为解释留痕，当前滚动状态另有明确身份。正文一处关键代码，片尾独立静态完整 Python 代码卡 5 秒，提示暂停，卡区无正文字幕。

章节：problem（01–02）→ last-step（03–07）→ rolling（08–09）→ code（10–12）。新术语“动态规划”在08第二句句首引入，画面使用真实句起点；不声称有词级识别。

### 01 problem
旁白：给你一段三阶的楼梯，每次只能上一阶或两阶，不能越过终点。请返回恰好到达终点的不同走法数量，而不是列出具体路径。
画面：首帧标题“爬楼梯：一共有多少种走法？”，下方输入 n=3 的三个阶格，1阶/2阶两种合法步长，终点清楚；先呈现允许选择，再强调输出框“返回方法数”。屏幕标注输入 n=3。

### 02 order
旁白：以三阶为例，可以一一一，也可以一二，还可以二一。顺序不同也算不同，所以这道题返回三，而不是把后两种合成一种。
画面：三行路径 [1,1,1]、[1,2]、[2,1] 依句级时序依次抵达同一终点，最后两行用不同首步连线保持可区分，输出3落定；注明“示例”。

### 03 last-step
旁白：题意清楚了，先看三阶的每种走法，最后一步只有上一阶、上两阶这两类。最后一步上一阶，前面就到第二阶；最后一步上两阶，前面就到第一阶。
画面：沿用三条路径，最后一个数字用金色描边；把 [1,1]+[1]、[2]+[1] 归上组，[1]+[2] 归下组；到第2阶和第1阶的前缀与末步分开，先不显示抽象递推式。

### 04 no-overlap
旁白：到第二阶有一一和二这两种，到第一阶只有上一阶这一种。前面的每种走法接上对应的最后一步，两组既不重复也不会漏掉，相加得到三种。
画面：两组前缀2、1分别接出金色末步1、2，逐条还原刚才三条路径；最后展示2+1=3，并明确“末步不同→互不重复；末步只有1或2→覆盖全部”。

### 05 bases
旁白：把同样的规则用到六阶，先从最小的结果往前算。到第一阶有一种，到第二阶有两种，这两个起点可以直接数清。
画面：切至同一条六阶计数节点，节点上方是阶编号1..6，节点中是方法数；只有1、2落定，其余显示问号。下方保留 [1] 与 [1,1]/[2] 两个起点证据，说明它们不是猜的。

### 06 grow
旁白：到第三阶，把第二阶的两种与第一阶的一种相加，得到三种。到第四阶，再把三和二相加，得到五种。
画面：六阶节点位置稳定，第一句从第1/2阶计数合流到第3阶，1+2=3先求和再落定3；第二句从第2/3阶合流到第4阶，2+3=5先求和再落定5，旧结果转为解释留痕。

### 07 thirteen
旁白：到第五阶有五加三等于八种，所以第六阶的两类走法分别有八种和五种。最后上一个台阶或两个台阶，两组走法互不重复，加起来就是十三种。
画面：先由第3/4阶的3、5合流得到第5阶8，等8落定后才指向第6阶；第5阶8标“最后+1”，第4阶5标“最后+2”，两条合流线不混为路径本身，8+5=13后第6阶落定。

### 08 dynamic-programming
旁白：结果已经算出来了，接着看计算时究竟要保留多少信息。动态规划，会复用已经算出的小问题结果，而本题的下一个结果只依赖前两项。
画面：第一句保留六阶全体已算结果，第二句句起点引入“动态规划”；解释视图回到“准备计算第6阶”，第4阶5与第5阶8高亮，1..3阶淡化并标“解释留痕，不必保存”，第6阶待算。两个变量框与对应阶节点连线，不把整张表画成必需内存。

### 09 rolling
旁白：准备算第六阶时，两个变量分别保存第四阶的五种和第五阶的八种。先用旧值五加八算出十三，再把两个变量整体换成八和十三。
画面：prev=5明确“第4阶方法数”，curr=8明确“第5阶方法数”；先在独立新值位置算出13并停留，旧框仍为5/8，再同时改角色为prev=8（第5阶）、curr=13（第6阶）。换位中不出现混合新旧值的错误运算。

### 10 implementation
旁白：写进程序时，先处理只有一阶或两阶的情况，再从第三阶一路算到终点。更新这一行要先算右边的旧值，再一起赋给左边，不能覆盖一个以后再相加。
画面：自然转入代码章，正文唯一代码区逐步显示if n <= 2: return n、prev, curr = 1, 2、for step in range(3, n + 1):与prev, curr = curr, prev + curr；右侧用5/8→8/13对应右侧先求值、整体赋值；不是逐行口读全部程序。

### 11 boundary
旁白：每一级只计算一次，时间随台阶数线性增长，额外只用固定几个变量。只记前两项是本题依赖关系带来的结果，其他动态规划问题未必也只记两个数。
画面：已算六阶节点回收，显示时间O(n)、额外空间O(1)；仅前两项计数框保有高亮，其余为教学留痕，结论“本题：下一项只依赖前两项”居中落定，不能把本题优化泛化成所有动态规划。
