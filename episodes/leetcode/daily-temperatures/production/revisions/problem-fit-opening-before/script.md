# LC.739 每日温度：还要等几天，才会更暖？

唯一承诺：给每一天找到未来第一个严格更暖的日子，并把等待天数写回原来的那一天。

画面约定：干净深色canvas；使用连续天序的气温线、逐日温度高度与当天位置演出原题；辅助待解决区始终连回原来的天；无浏览器壳、无无关实物、无装饰进度条。画面显示“第1天”到“第8天”，程序下标从0开始，两个位置之差不变。33–36等温度为满足官方30..100约束的自选教学示例，不声称真实天气预报；不补摄氏或华氏单位。图形从28这一基准起画，并明确标示，避免暗示绝对零点。

来源：2026-10-25实际读取[官方中文题面](https://leetcode.cn/problems/daily-temperatures/description/)及[官方英文题面](https://leetcode.com/problems/daily-temperatures/description/)，访问证据见research/source-access.json。方法、证明与自选样例为本期推导，执行源为solution.py；算法段只读其真实执行trace，新04–05另读真实append/pop概念操作JSON，不将存取规则示意伪称完整解题。

本轮状态：针对用户“默认懂单调栈”的反馈，新增04、05两镜四句，原28句逐字保留。旧版真实音轨、分镜与媒体已归档revisions/stack-primer-before；本轮新增句尚未配音，当前storyboard仍是旧版14镜真实计时，等待root复用原音源并装配新时序。每镜恰好2整句；正常语速预计新增约25–30秒，真实时长和动作停留待配音后核验。片尾继续保留150帧静态完整Python，字幕与旁白在卡前结束。

## 第二章 为什么这样保存

### 03 repeat
frame：canvas
画面：先从第3天向右查看较冷的几天，再从第4天重复查看第5、6天；旧查找轨迹淡出，留下第3、4、5天的待解决标记。
旁白：接着想怎么找：每天都向后查，会反复查看相同的日子。不如按日期前进，把没等到答案的天留下。
屏幕文字：重复向后找 → 保留未解决的天

### 04 stack-basics
frame：canvas
画面：保留同一天气与第3/4/5天原位置；新辅助区先为空，第3天35、第4天31、第5天30的原日期标记依次从右侧操作端加入；第二句起音后标左栈底/右栈顶，并将最后加入的第5天30从右端取出，放在旁边暂存，不写任何等待天数。全镜持续标注“保存规则示意／先不写天数”，不是完整算法执行。
旁白：这些日子按顺序保存，只能从末尾加入，也只能从末尾取出。栈，就是后放的先取；操作的一端叫栈顶，另一端叫栈底。
屏幕文字：保存规则示意 · 先不写天数；后进先出；栈底／栈顶在第二句起音后出现

### 05 monotone
frame：canvas
画面：承接刚取出的第5天30，将同一标记从右侧暂存位置放回末尾；保留原日期连线，逐个点亮35、31、30及35≥31≥30，保持从左底到右顶的位置；第二句起音后显示“单调”并说明不升可包含相等，旁侧明确标“相等关系另例”以两个同高度30示意，不把它们加入主例。
旁白：把刚取出的第五天放回，看三十五、三十一、三十从栈底到栈顶越来越低。单调，在这里指从栈底到栈顶不升，温度相等也允许。
屏幕文字：这些待解决日的温度：35≥31≥30；相等关系另例：30＝30，也不升

### 06 order
frame：canvas
画面：承接35≥31≥30；第6天32到来，沿真实算法trace依次比较30→取出30、比较31→取出31、比较35→不够暖而停止，最后把第6天32加入栈顶，得到35≥32；每一步单独可见，原日期与温度不变，本镜不写等待天数。
旁白：新来一天，比最近留下的天更暖，就先解决它。如果还不够暖，更早留下的温度不会更低，也不能解决。
屏幕文字：32>30：取30；32>31：取31；32<35：保留35；加入32 →35≥32

### 07 name
frame：canvas
画面：承接上一镜已经得到的第3天35与第6天32，原日期、辅助位置保持不动；先回收只动末尾和温度不升两个特征，再在第二句真实起音后显示完整名称单调栈；不回滚35/31/30。
旁白：所以温度从早到晚不升，最近一天放在末尾。单调栈就这样保存下标，先检查末尾，解决后再移走。
屏幕文字：35 ≥ 32；只动栈顶＋温度不升；单调栈；保存原来的下标
