# LC.739 每日温度：还要等几天，才会更暖？

## 第二章 为什么这样保存

### 03 repeat
frame：canvas
画面：先从第3天向右查看较冷的几天，再从第4天重复查看第5、6天；旧查找轨迹淡出，留下第3、4、5天的待解决标记。
旁白：接着想怎么找：每天都向后查，会反复查看相同的日子。不如按日期前进，把没等到答案的天留下。
屏幕文字：重复向后找 → 保留未解决的天

### 04 stack-basics
frame：canvas
画面：承接保留等待的思路，第3天35已驻留，第4天31、第5天30因不够暖而依次加入；原日期连回同一气温线。首句描述走到第五天的实际等待集合。第二句以“更暖解决后移走、较凉留下”解释为什么待解决温度从早到晚不升，依次点亮35≥31≥30；不预先命名栈、不把不升当人为指定规则，也不出现栈底/栈顶。局部示意暂不写天数，下一镜用真实32验证处理方式。
旁白：走到第五天，三十五、三十一、三十都还在等更暖；把它们按日期留下。更暖会解决并移走前面的低温日，较凉就留下；因此还在等待的温度，从早到晚不升。
屏幕文字：第3、4、5天仍在等待；更暖：解决并移走；较凉：留下；35≥31≥30；等待关系示意 · 先不写天数

### 05 order
frame：canvas
画面：承接35≥31≥30；第6天32到来，沿真实算法trace依次比较30→取出30、比较31→取出31、比较35→不够暖而停止，最后把第6天32加入末尾，得到35≥32；每一步单独可见，原日期与温度不变，本镜不写等待天数。
旁白：新来一天，比最近留下的天更暖，就先解决它。如果还不够暖，更早留下的温度不会更低，也不能解决。
屏幕文字：32>30：取30；32>31：取31；32<35：保留35；加入32 →35≥32

### 06 name
frame：canvas
画面：承接35≥32及原日期，保留上一镜真实处理后的状态，不回滚35/31/30。第一句将已经看到的同端加入/取出归纳为后放先取，操作端标栈顶、另一端标栈底。第二句才回收从底到顶不升并出现完整名称单调栈；以文字明确相等也保留；后续独立相等案例再演30、30、31。名称从已有动作和关系中得出，不在题意或推导起点提前出现。
旁白：只从末尾加入和取出，后放的先取，这样的结构叫栈，末尾叫栈顶。这些等待温度从栈底到栈顶不升，所以叫单调栈；相等也保留。
屏幕文字：同端加入与取出；后放的先取；栈顶／栈底；温度不升；单调栈；相等也保留
