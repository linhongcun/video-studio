# MQ01–MQ04源码机制重制：独立审稿口径

基线923305b49cea1b18d7fc7e4dd8ac70ad830bc673；本记录仅用于新source-depth-v2修订。用户要求同时提高实现深度与易懂程度；旧片技术检查、旧冻结输入及实际观看反馈保持原身份。来源数量、方法名、模型断言数量均不作为教学深度通过条件。

配音前只检查以下六件事，不增加通用测试框架：

1. 一期一个具体问题。开头先说明谁想完成什么、遇到什么矛盾，结尾回答同一问题；按真实配音检查首2/5/15秒。问题不能只靠技术标题表达。
2. 一个事件贯穿。对象和身份在产品场景、内部图、结构中保持对应；改变情景先明确回共同前提，不能把多个分支拼成一次经历。
3. 因果真正进入正文。能沿“结构保存什么→谁在什么条件下读/改→状态怎样更新→因此产生什么结果”完整解释本期主机制。独立审读者不能借研究笔记补出脚本/分镜没有表达的关键环节。
4. 新概念随对象和动作引入。去掉源码类名、正式术语和代码后，仍能用片中对象解释原因；再将必要名称绑定对象。不做参数墙、方法巡览或先贴名词后补意义。代码可选，若展示必须对应眼前动作。
5. 一个关键条件变化足以检验理解。观众可以据前面建立的机制预测状态、结果或保证怎样变化；不机械要求制造失败，不把教学模型规则本身当作Kafka运行证据。
6. 范围有主次。正文保留回答“为什么”所需的内部结构和判断，旁支放研究/文章；不按旧两分钟机械删原因，也不把四分钟填成三堂机制课。源码事实、推导、有限教学模型、实际运行结果分别标明。

逐期记录“已核实实现依据 / 正文已兑现的因果 / 还缺的可视动作或前提 / 能力边界”，结论明确为“可进入TTS”或指出具体阻塞；最终制作裁决由根任务作出。源码与旧稿已经出现过，不自动等于本轮已审定。
