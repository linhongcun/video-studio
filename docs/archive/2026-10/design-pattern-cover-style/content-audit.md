## D01：策略模式

真实主线为原价100元的同一示例订单：选会员九折得90元，改选活动八折时重新从100元计算得80元，每次只选一种，优惠不叠加。选择方在外决定使用谁，结算按共同约定委托当前策略；约定不是运行中的独立计算节点。

建议机制图：上方 `同一订单 · 原价100元`；左侧 `结算`；右侧两张同尺寸卡片 `会员九折 / 90元`、`活动八折 / 80元`，以“择一使用”标注分支；底部 `共同约定：原价 → 应付金额`。分支图作为两种可替换实现的概览，不应两条都高亮为同次运行，也不能画90→80的串行路径。若需展示当前执行状态，只高亮会员分支，活动分支以明确备选/可换样式表达。

证据：

- `episodes/strategy-pattern/meta.json`：EP23、D01、完整标题、description中的100/90/80职责。
- `episodes-codex/strategy-pattern/script.md:5`–10：案例边界及角色；:39–53 共同约定/结构；:55–76 两次独立定价与选择职责。
- `episodes-codex/strategy-pattern/remotion/src/Cover.tsx:12`–21：旧封面原示例，不作为最新sourceTitle来源。

避免：策略=折扣、自动选择最便宜、优惠叠加、结算永远不改、90元再打八折。原 `covers.json.title` 尚为旧题句，不修改其冻结内容；sourceTitle应取当前meta。

## D02：观察者模式

当前主线是订单17的状态变化、接收者登记/退出及各自响应；MQ只在最后一段作为实践映射。订单来源维护状态和订阅关系，摘要负责显示，变化记录负责留痕；共同观察者约定是接口契约，不是独立消息中转服务。

建议机制图：左侧 `订单17 / 已付款`，分支箭头分别到右侧 `订单摘要 / 更新显示` 与 `变化记录 / 追加记录`；分支旁或底部标 `通知当前订阅者`、`先订阅，再接收变化`。这是付款后两个接收者仍登记时的静态概览；避免混用“摘要已退出”的后续状态。若要用退出状态，应仅向记录画有效箭头、摘要灰显并标“已停止接收”，但首版封面用前者更简洁。

证据：

- `episodes/observer-pattern/meta.json`：EP28、D02、当前标题与模式主线description。
- `episodes-codex/observer-pattern/script.md:3`–10：最新主线和MQ边界；:29–50：角色、订阅先于通知、各自响应；:53–66：退出后仅记录收发货通知；:77–82：唯一MQ映射镜。
- `docs/RULES.md:88`–98 与 `docs/production-memory.md` 的“D02最新方向”：模式为主体。

避免：MQ/RabbitMQ/Kafka作为封面主体、接收者同队列竞争、绝对解耦、可靠投递/顺序/异步保证、把变化记录画成消息存储或重试队列。不能同时把摘要标已停止接收又画收取发货通知。

## D03：适配器模式

当前主线是主动定义业务通知约定，适配器按约定转换请求并委托外部已有服务，把服务格式升级变化集中在接入边界。受理结果不等于送达。业务方→适配器→服务是真实调用路径，业务约定是契约而非第四个运行中转节点。

建议机制图：三节点 `发货提醒` → `适配器` → `外部服务`，中间节点标 `转换 · 委托`；上方或底部注明 `按业务通知约定`。图内可以简化为 `收件人 / 正文` → `target / body`；如采用字段映射，需要说明为教学示例，并维持真实收件人和正文值。为减少封面密度，优先三节点职责图，升级格式细节留正文。

证据：

- `episodes/adapter-pattern/meta.json`：EP31、D03、当前标题与主动边界summary。
- `episodes-codex/adapter-pattern/script.md:7`–11：四角色/三运行节点、业务先定约定、V1/V2边界；:22–44：业务约定、转换并委托；:46–62：已受理/等待回执及后来格式升级对照；:64–74：防腐作用与前提限制。
- `episodes-codex/adapter-pattern/covers.json.copy` 与 `remotion/src/Cover.tsx`：已采用三节点路由和业务边界措辞。

避免：被迫接口不匹配作为唯一动机、适配器自己执行发送、包装即适配器、适配器等同完整ACL、任何服务升级都零影响、受理即成功送达、运行中热换SDK。别用电源插头/旅行转换器作物理比喻。
