## 路径与冻结边界

Python 的 `episodes/_shared/episode_paths.py` 与站点的 `site/scripts/episode-paths.mjs` 统一定位当前实体目录，并解析原始来源记录中的旧仓库路径。旧 `references.json`、文章来源、原始源码证据、冻结清单、QA 和附录回执保持原字节；不通过改回执追认新源码为旧视频的编码输入。

`resolve_frozen_path` 仅在清单内容仍匹配迁移时记录的原 SHA 时，按清单的旧位置翻译相对路径。原期望输入 SHA 继续严格比较；新冻结使用当前真实目录。路径适配改变了可执行源码，旧冻结对这些源码失效是明确边界，后续重渲必须先审查并冻结当前输入。新增解析器也纳入新期冻结依赖。本次没有重新编码、重新审片或宣称旧 QA 已覆盖迁移后的源码。

迁移前已知 `bloom-filter/source-sha256.json` 中共享预检与渲染入口存在两条 SHA 差异，账本保留了该事实，未重写旧清单。完整密钥扫描存在原始第三方源码的五处既有标识符误报，相关文件与基线逐字节一致；本次适配不新增命中。
