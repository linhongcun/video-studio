## EP35 / LC739 每日温度 / #80

- 题意先说按日期顺序给温度；每一天问还需等几天，才第一次遇到**严格更暖**，没有则0。答案是日期距离，不是温差，也不是下一个更暖温度的值。八天样例的温度数组、日期显示、程序下标和最终答案须绑定定稿同一数据；当前不猜写尚未ready的具体数组。
- 动机应能从图中复述：逐天往后找存在重复；新来的一天能同时解决多个还在等升温的日子，所以保留未解决日期；只与符合顺序的顶部继续比较，已解决日期可移除。这些关系建立后才命名单调栈；栈里存日期/下标，温度用来比较。
- 真实过程必须包含第一次弹出和第一次不弹的原因，以及**相等温度不弹**、一次连续解决多天、较低新温度留下等待。相等的两天身份不能合并，图中原日期与待处理位置须对应。
- 每次弹出j，写回答案i-j；屏幕日期若从1起，不能算成i-j+1或用温差。当前日期只入栈一次；剩余项保持0而不是等到未给出的未来。结尾逐项答案与原八天固定日历位置对应。
- 不把暂未解决叫做永远无解；只有扫描完输入，剩余0才有最终依据。复杂度说明用每天下标至多入/出一次，不误说嵌套while必为平方。

## EP36 / LC46 全排列 / #84

- 题意说明输入元素互不相同；用所有数字各一次排成有顺序的完整结果，返回全部排列而非一个、组合或交换次数。123这个固定小例子须给出6种完整结果，顺序与程序遍历一致。
- 方法动机从逐个位置选择推得：选一个未使用数字填当前位，剩余位置按同样问题继续；一条分支结束后撤回刚才选择，才能尝试其它候选，之后才命名回溯。不能只有“用回溯”标题和现成递归过程。
- 必实际演出123保存副本→撤销3→撤销2/恢复可选状态→选择3→2得到132。路径中的数字、可用数字、used与当前调用层级身份保持；撤销不是重置整棵树或删去已保存结果。
- **首次跳过used候选**解释为当前路径已用，不能误教为全局永久用过。进入分支时置used，返回时只恢复本路径对应项；其它分支仍可再次选这个数字。
- result中完整排列是独立副本，后续path.pop或追加不改变先前123。实际片需看到123保持而132随后新增，最终6个互不重复、不缺失、每项长度3且数字各一次；不能只显示“6”计数代替结果。
- 若讲复杂度，输出复制的代价不能略去：通常时间O(n·n!)，辅助O(n)不含结果，存全部输出需O(n·n!)。用例/空输入约定以正式题面与程序为准，不据未讲输入范围临时加结论。

## EP37 / LC42 接雨水 / #86

- 本期只有前后缀最高预处理O(n)时间/O(n)额外空间这条主线；原issue旧双指针方案与最终选择的差异由PR透明说明，不在片里混入未演出的双指针循环。
- 原题单位宽度柱列/柱高、空隙及雨后水量先建立。固定样例 `[3,0,2,0,4,0,1]`，水深预期 `[0,3,1,3,0,1,0]`，总8；左盆水位3、右盆水位1。柱位置、高度与水区不随方法切换，水不能穿柱或流出边界还被计量。
- 动机从每处要被左右两侧挡住、较矮的有效挡墙限制水位推得。附近高度2不是整盆最高挡墙，因此它可以被淹1格；不能只用最近柱或把整列统一填到全局最高4。重复寻找左右最高之后才引出缓存每个位置前缀/后缀最高，不直接宣布两个数组。
- L/R**包含本柱**，必须与程序实际循环、初值和水位式一致。本例L=`[3,3,3,3,4,4,4]`、R=`[4,4,4,4,4,1,1]`，水位min(L,R)，再减本柱高度。每一步显示到底是柱号、最高高度、水位还是水深，不能身份混用。
- 两个方向的预处理有清楚重置/扫描起点；首次较低柱被跳过更新最高时说明它不能改变已有最高，而非没有检查它。合并时首尾水深0的原因和内柱高度2水深1实际可见，不把0误画成水块。
- 计量与答案逐柱绑定：3+1+3+1=8，水单位格只计空隙，保持两盆独立水面；整数8与完整Python返回一致。复杂度额外数组O(n)，不能沿用旧issue双指针O(1)空间文字。
