# 图文写作说明

规范以 [RULES 的配套图文](RULES.md#配套图文) 为准。本文说明如何在现有站点落实；起稿用 [article.mdx 模板](../episodes/_template/article.mdx)。

## 起稿与定稿

新增文章先在已有研究、制作记录或模板注释中写清六项：目标读者、必要前提、本文回答的核心问题、贯穿示例、预期得出的判断、需要另放深入层的内容。无需另建一份必交文档。按这些关系拟提纲，逐节写出「本节解决什么、下一步为什么需要它」，再展开正文。前提只交代影响当前解释的部分，不以长篇背景或范围声明挡住具体问题。

文章应能独立读懂，不能依靠读者看过视频或熟悉源码来补全主线。写完先对照开头与小结，确认回答的是同一个问题，再从头审读推导、例子与条件；需要读者自行补出的关键步骤应在定稿时补齐。结构审读在冻结前完成，检查方式见 [文稿定稿审读](qa.md#文稿定稿审读冻结前)；实际配图、阅读与导航在发布前复核。

## 阅读结构

正文在首个主要章节前，用简短引入建立具体问题、教学示例与解释方向，让读者知道读完能理解什么。导读直接写在MDX中，不能只填写frontmatter的`summary`；后者用于摘要数据，不自动成为可见正文。随后按读者需要弄清的因果或推导分节，解释适用条件与失败情景，全部必要拓展之后用小结收束，最后列「参考资料」。保留原有章节锚点、完整程序与证明，章节数及篇幅按内容决定。

每节推进一个必要问题：用同一例子展示动作或状态变化，随即解释原因以及它依赖的条件。术语和实现名称在对象与作用建立后引入，关键源码对应可以留在主线。图、解释与关键代码放在读者需要对照的位置，说明图中应看什么。短篇可在同一章内用三级标题或步骤串联动作；已有清楚推导不为统一格式改成相同的栏目。

长文明确区分主线与深入层。完整实现、一般化证明、精确变体与实验复现可以另设用途清楚的章节并提供阅读入口，核心因果、正确性依据和会改变结论的前提仍在相关正文。镜号、代码卡停留和制作检查等过程说明归入复现/工程记录的阅读层，不让它们截断第一次解释。自检有助于判断条件变化时，可放在小结前并给出解析；不把每篇文章强制变成练习册。

按题材选择推导顺序，不照搬示范标题：

| 题材 | 主线应接上的关系 |
| --- | --- |
| 原理机制 | 具体业务问题 → 结构保存什么 → 谁在什么条件下改变状态 → 成功、失败及保证的边界 |
| 算法题解 | 输入、目标与限制 → 怎样入手、为何选择这种方法 → 关键性质或不变量 → 同例完整走例 → 实现、复杂度与边界 |
| 逻辑推理 | 规则与目标 → 突破口为何成立 → 可行构造 → 本文所承诺的正确性或最优性依据；程序核验与证明分别说明 |
| 动手教程 | 目标与必要环境 → 可连续执行的操作及预期结果 → 常见失败与恢复 → 适用条件 |

换例或切换成功、失败等分支时，明确哪些初始条件重置，哪些对象与状态沿用。写作依据与来源边界见[结构调研](archive/2026-11/article-structure-research/README.md)，实际应用见[重构记录](archive/2026-11/article-structure-refactor/README.md)。

文章目录依据实际正文标题组织，目录点击定位正文；视频回看仍由既有chapter id与时码决定。新加的深入阅读、自检、小结可以进入文章目录，不为它们虚构视频章或时间。存量改稿保留原显式锚点并核对图的chapter和seekTo，不能把更换标题或改变层级当成重定视频时间的依据。

统一使用站点标题、正文、代码、提示、引用和图注样式。`Callout` 用于提示或边界，`SourceQuote` 用于真正的外部原文，避免把作者自己的提醒显示成来源证据。

## 详略与排版

判断一段应否留在主线，先检查删去后读者还能否解释下一步为何成立、判断结论何时适用。若不能，就保留在相关步骤并解释清楚；若只是完整实现、一般化证明、更多变体或制作复现，则按用途进入深入层，并从需要它的位置给出入口。不用「详见源码」替代关键因果，也不为充实篇幅追加无关背景、多解或练习。没有这类内容的短文无需硬设深入章。

代码前说明它解决什么、输入或当前状态是什么，邻近解释关键操作为何这样写，再用同一例子说明输出或状态变化。长程序先讲清关键逻辑，完整版本保留在合适的阅读层；可运行代码、教学伪代码与源码节选应标明性质，命令须有实际路径及必要环境。代码数量与篇幅由解释需要决定，不把视频正文的代码画面限制套到文章。

段落一次推进一层意思；标题表达本节解决的问题或关系，H2组织主要问题，H3承接其下步骤，不把每两句话拆成一个标题。连贯解释用段落，并列项或操作步骤用列表，同一维度的比较用表格；避免整段加粗和过长的项目清单。图前指出应观察的对象或变化，邻近文字解释它为何支持当前判断，图注补充必要条件。

复用共享样式与阅读容器，不逐篇自定字号、颜色或缩字挤内容。手机上检查长代码、英文、链接、表格和图内标注：正文不能被撑宽，确需横向查看的代码或表格应在自身容器内可操作；图片细节可通过原图入口查看。排版调整后重新检查上下文中的「上文」「下面」及图号、链接指向。

## 结尾总结

每篇在全部正文与必要拓展之后、参考资料之前设置总结模块，默认用「小结」。已有明确、完整收束的末章可保留原题与锚点，不再重复添加。程序、证明、实验范围和附录也属于需要收束的内容，不能让读者读完细节后自行猜测主旨。

总结应回答：开头的问题最后怎样解释，关键步骤为什么能得出这个结果，读者应记住什么判断及其必要条件。用连贯的短段落把分散信息接起来，尤其提炼长文的核心关系；算法说明关键排除依据或不变量，机制文章分清各项保证，推理题保留规则前提。只回收正文已经解释的内容，不在结尾引入新术语、来源或未经展开的结论，也不把小标题、复杂度和限制重新列一遍。长度随内容决定，避免用同一套句式填充每篇。

编辑复核时分别检查开头与总结是否回答同一个问题，以及结论能否由正文推出。来源、配图与构建检查通过，不等于文章已经完成这项收束；本轮存量处理见[逐篇记录](archive/2026-11/article-summaries/README.md)。

## 就近放置精确引用

先阅读原文，选取足以支持当前论点的连续语段，核对上下文、题名、署名、位置与适用版本。文稿中直接写：

```mdx
<SourceQuote sourceId="R1" supports="说明这段原文实际支持的具体论点，保留必要条件。" />
```

将组件放在相关段落后。共享组件默认用带虚线下划线的轻量「原文」按钮作为段末入口，完整原句、定位、出处、译文和编者说明在浮层中按需查看。桌面悬停可预览，点击可固定；手机点按打开。入口必须同时支持点击和键盘，不能把悬停作为唯一访问方式，也不要自动给正文整句加下划线来暗示整句都被该来源支持。

浮层一次打开一处，支持Esc及外部点击关闭，内容较长时可滚动，来源链接保持可操作。支持原生popover的浏览器在无JS时仍能点按展开；旧浏览器显示完整引用作为降级。折叠的是展示状态，原文与证据要求不变。新期继续使用上面的 `SourceQuote` 写法和现有来源JSON，由共享组件统一提供交互，无需逐篇增加脚本或改动冻结输入。

组件从同一期 `references.json` 读取原文与出处，不必在MDX重复抄写。若文章需要的视频外来源，新增 `article-sources.json`，与视频资料合并读取，id 使用 `A1` 等避免重名：

```json
{
  "schemaVersion": 1,
  "episode": "your-episode",
  "sources": [{
    "id": "A1",
    "organization": "实际发布机构",
    "title": "实际文档原题",
    "version": "实际版本，未标时说明未标",
    "url": "https://example.org/source",
    "supports": ["实际支持的具体论点"],
    "verification": {
      "status": "verified",
      "checkedAt": "实际阅读日期",
      "evidence": "episodes/request/your-episode/publication/article/source-evidence.md"
    },
    "quotation": {
      "text": "从实读文档复制的连续原文",
      "locator": "真实小标题、段落或页码",
      "evidence": "episodes/request/your-episode/publication/article/source-evidence.md"
    }
  }]
}
```

以上只是字段示例，不能作为真实来源发布。证据文件应保存实读原文及必要上下文、公开URL、实际读取日期；不能把 `supports`、搜索摘要、旧中文核验概括当作原句。固定版本链接可写 `verification.sourceUrl`。核验补充来源的机构、原题和署名，有明确个人署名才填写 `author`。引用旧证据保留历史访问日期，新增来源用本轮实际阅读日期；无需为了更换卡片样式重新访问不变的原文。

上述证据路径是仓库内的新实体路径；`Figure.src` 继续使用站点的 `/video-studio/episodes/<slug>/article/…` URL。本次目录迁移保留与既有媒体回执绑定的来源JSON字节，历史 `evidence` 路径由共享解析器映射到新文件，不能为修目录而改变原资料SHA或追认原文已重新阅读。

可用 `translation="……"` 附译文。原文不会因译文或编者解释而改写。短引只支持其中实际写出的部分：题意可说明输入与限制，不能代替算法正确性证明；教学假设不能冒充真实系统记录。

## 配图和回看

优先复用清楚的正文示意图，或从最终视频提取与邻近文字一致的关键状态。选择动作已完成、标注可读的时刻，避免空白、淡入淡出和片尾资料页。示例命令中的时间、路径都须按本期实际替换：

```sh
mkdir -p episodes/request/your-episode/publication/article
ffmpeg -ss 42.5 -i episodes/request/your-episode/publication/video.mp4 -frames:v 1 -q:v 2 episodes/request/your-episode/publication/article/01.jpg
```

```mdx
<Figure src="/video-studio/episodes/your-episode/article/01.jpg"
  alt="图中关键对象、状态和关系的准确描述"
  caption="教学示例：解释这一状态说明什么。"
  seekTo={42.5} chapter="existing-chapter-id" />
```

必须实际查看抽出的图片；图注解释图意，时间链接负责回看；图片和「查看大图」链接可打开原图，方便手机放大查看细节。自制示意图用 `figure` / `figcaption` 包裹，SVG有 `aria-label` 或 `title`，注明「示意图」以及必要的数据来源。外部图片保留来源及使用依据，不把生成图伪装成截图。所有图紧邻相关解释，宽度、留白和图注复用站点样式。

## 冻结与成片后配图

制作目录的 `article.mdx` 是编码前冻结输入。分镜和时序定稿后，先写好并启用 `Figure` 的图片路径、预定秒数、章节、图注及alt，随文章一起冻结；此时图片文件可以尚未生成，不能标记为已经看图验收。冻结前已有的 `article-sources.json` 及其原文/核验依据也纳入本期实际输入清单，因为MDX中的sourceId并不包含真正引文内容。

成片后按预定图位生成截图、实际查看并核对图意与回看时间，只增加图片文件，不修改冻结制作稿。若实际选图需要更换时间、图注或其他文稿内容，保留原制作稿和冻结清单，另存站点发布派生稿，再接入 `episodes/<series>/<slug>/publication/article.mdx`；本期记录写明制作稿SHA、发布稿SHA、实际差异与原因。成片后新增或调整的文章来源、证据和图片也保存各文件SHA，不追认为原编码输入。来源更正若影响视频内容，应按实际影响返工视频，不能只改图文记录。

## 接入与验收

最终媒体产生后补图，将发布稿、文章独有资料JSON及 `article/` 中图片与证据接入 `episodes/<series>/<slug>/publication/`。运行：

```sh
npm --prefix site run check:articles
npm --prefix site run build
```

机器检查确认正文实际调用 `SourceQuote`、短引和本地证据一致、出处字段与图片齐全；共享组件默认折叠不算缺少引用。编辑再确认论点支持关系、上下文与图意。浏览器分别查看桌面/手机、亮暗主题，核对开头与小结可见、文章目录层级和目标正确、手机折叠可用，以及代码、表格、图与长链接的可读性；目录定位正文，不改变视频播放时间。引用检查段末入口、悬停预览与点击固定、手机点按、键盘进入、Esc与外点关闭、一次一处、长面板滚动、来源链接及屏幕边界；另查无JS原生popover入口和旧浏览器完整引用降级。图片须清楚，长英文可换行，截图时间与原图入口可操作。至少一处引用与一幅图是最低线，不能代替对正文质量的判断。具体交互实现及实际验证范围见 [引用交互记录](citation-interaction/README.md)。

修改存量站点文章时记录前后全文SHA和改动范围，制作目录的冻结文章、已编码媒体、旧回执及旧冻结清单保留。站点衍生稿不是对旧渲染输入的追认；不为新增图文重渲未变视频。修改了配套讲解内容时按 [时间与版本口径](publish.md#视频时间与版本) 维护当前更新时间，保留创建和首发时间。
