# 制作记忆：EP.15 的已验证经验

更新于 2026-10-24（北京时间）。本文件供后续重制开工前阅读，保存用户偏好与实际经验。规范仍以 [RULES.md](RULES.md) 为准，流程见 [pipeline.md](pipeline.md)；不要把单期设计参数当成通用规定。

## 用户明确的质量偏好

用户在制作过程中特别强调：

1. “一定要去查阅一些核心的权威资料。”
2. “制作动画的时候一定要通俗易懂，并且尽可能好看吧。”

用户实际观看 EP.15 后认可成片，并批准“可以合并代码，部署到 GitHub 上了”。因此，后续应延续经过资料核实、容易跟上、画面清楚美观的制作方式；不能只完成技术渲染就算交付。

## 开工和内容设计

- 先对照 issue 与当前代码、已上线内容，确认实际剩余工作。未关闭的 issue 不等于全部尚未实现；本次 #91 就已有大量站点实现。
- 实际阅读核心一手资料的正文，优先官方手册、标准和原始论文。把每个关键主张对应到公开链接、访问日期及适用边界；搜索摘要、旧脚本和对话记忆不能代替依据。
- 视频保持一条主线。选一个具体问题，沿用同一组示例、同一目标，先解释基础对象，再命名术语。复杂分支留在配套文章，并保持文章与视频口径一致。
- 保留准确性边界。本次解释索引能减少无关读取，也说明小表或读取大部分记录时扫描可能更合适，没有宣称索引总更快。
- 示例明确标注；动画速度、示意行号与虚构数字不能冒充性能实测或真实物理结构。

## 通俗且美观的动画方法

- 第一帧就让标题、主体和冲突可见；一镜推进一个主要变化，让观众知道正在看哪个对象、哪里改变、为何改变。
- 保持对象位置、目标数据、颜色含义一致。用逐行高亮、范围退暗、连续引导线和结果对比解释过程；颜色用于表达含义。
- 动作顺序必须符合旁白和技术事实。本次修正为镜 04 找到目标，镜 05 继续检查剩余行，才完成全表扫描。
- 表、图和关系示意使用干净 canvas；深色底、清晰的字号层级，正文、注释与字幕分区，复杂说明不堆满画面。
- 先检查关键静帧，再渲染完整视频；编码后从实际 MP4 抽帧复核，确认首帧、关键动作、连线、字幕、结尾与封面安全区。不能仅凭源码或预览判断成片。
- 本次的 14 镜、130.8 秒、字幕 42px、订单示例与配色只是一组成功选择。下一期根据内容重新设计，不机械复制时长、镜数或页型。

## 配音、时序与冻结

- 复用仓内共享 TTS、铺轨、起音与混音脚本；保留选定 takes、最终音轨、脚本、分镜与 SHA，便于重现和追溯。原始响应、句子缓存、node_modules 与渲染中间文件不必入库。
- 先定稿旁白，再合成配音和确定实际镜长；字幕使用真实句子边界，屏幕文字与口播对齐。共享音轨放置工具应复制实体文件，避免 bundle 后相对软链失效。
- EP.15 的官方 ASR 模型下载被当时环境策略拒绝，本次仅测得句级音频边界与句首声学起音。`words.json` 明确记录无 ASR、无逐字对齐；字符所带整句区间不能用于逐字高亮或句中挂词。
- 后续重新检查 ASR 能力；不要把本次限制永久化，也不能把机器检查通过写成已完成逐字识别、读音听辨或完整人工审片。
- 用户观看并批准成片后，发布同一份文件，核对完整 SHA；不要重新请求不确定的 TTS 或重新渲染后直接替换批准版。

## 接入站点时踩过的坑

- 制作源在 `episodes-codex/<slug>/`，站点读取 `episodes/<slug>/`。复制批准资产并明确新制作入口，避免旧 `gen.py`、旧 Remotion 工程或旧 `timing.json` 被当成新片来源。
- 分镜不一定按网站文章章节分组。显式核对 `chapters.txt`、文章锚点与真实镜头起点；本次用五个章节接入，避免单 scene 分镜只生成一个章节。
- 在站点 `meta.json.finalVideoFrames` 写入实际总帧数。本次为 3924 帧，否则旧逻辑会额外计算 60 帧片尾。
- 已有冻结字幕时间时，WebVTT 优先使用有效的镜内 `from/to`，`to` 为包含的末帧，输出结束时间用 `to + 1`。不能再按字数比例重铺。缺少完整时间的旧稿保留兼容分支。
- 更新摘要、说明、重制日期与旧版标记；保留原始首发记录。只更新站点时保留历史平台链接，不能把它们说成本次重发结果。
- 构建后检查 dist 的视频与封面哈希、实际时长、全部章节与字幕边界；上线后再检查页面、视频、海报、外挂字幕和更新日志。
