# Deming 质检清单

规范以 [RULES.md](RULES.md) 为准，具体命令和阈值见 [validate.md](validate.md)。制作输入在 `episodes-codex/<slug>/`，站点副本在 `episodes/<slug>/`。按本期 README、`source-sha256.json` 和 `qa-final.md` 确认媒体身份及实际检查范围。

预检在配音、分镜冻结之后，渲染之前；成片审在渲染之后。预检不过先修正输入，再按 [pipeline.md](pipeline.md) 第 5 步重新冻结。GitHub 发布沿用 STATUS 的持续授权，平台新发另行授权。

检查已发布工程时优先只读入口，报告写入 `/tmp`；会改写分镜、音轨或冻结清单的命令用于制作阶段，不能用来掩盖校验失败。

## 预检

1. **资料与叙事。** 事实有公开出处及访问日期；从调研起维护 `references.json`，核对每项原文确实支持片中论点，文章有完整链接，正式编码前通过来源预检。开头建立具体问题和使用场景，结尾回应同一问题。算法先说明输入、合法操作、限制、目标和返回值。设计模式先讲语言无关的意图与职责。
2. **范围与导航。** 每集聚焦一个机制；多情景先建立稀疏全局关系，局部讲解能认出当前位置，切换前回到正确分叉前提，结尾回收全局。未知、拒绝与重试按真实语义区分。
3. **冻结输入。** 跑当期冻结验证器；核对 `voice.wav`、`words.json`、`storyboard.json`、脚本、参考资料清单和实际附录/正文生成源码的完整 SHA-256。`scriptSha256` 的输入定义按本期装配代码和 README，不把旁白文本哈希与整份脚本哈希混用。
4. **音轨与字幕。** 真实句子边界、总帧数和镜头区间一致；字幕逐字对应旁白，处于镜内并连续、不重叠。术语按真实起音出现，完整显示至少 63 帧。句级声学边界不冒充逐字 ASR。
5. **起音窗口。** 用分镜模式运行 `python3 episodes/_shared/label_onset_strict.py --dir EPDIR --out /tmp/label-onset-strict.txt`，不加仅列举规则起音的 `--words`。退出码为 0，报告无 FAIL、NOT FOUND、MISMATCH。已批准的镜号例外只抵消对应窗口越界，不抵消缺失或不一致；窗口为 −6..+2 帧，算法只用共享 `onset_rule.py`。
6. **文字与版式。** 按本期渲染检查入口核对文字和元素边界，无 `COPYFIT`，不自动缩字掩盖溢出。正文关键字、箭头、节点、字幕、水印互不遮挡；字宽估算不能代替实际渲染查看。
7. **机制与位置。** 箭头从调用方指向被调用方，动作、数值和状态符合旁白；成功、失败与重试不串成不真实的同一条经历。技术术语在对应对象和动作建立后引入。
8. **壳、主题与首屏。** 浏览器壳只给真网页、地址栏和 DevTools，讲解图用干净 canvas；页身按共享主题，无大面积近白底。第 0 帧是主体画面，2 秒内有标题和冲突。
9. **章节与片尾。** 新主要章节先有简短口头过渡，再展开动作。参考资料安排在主线与既有代码卡之后，默认每页5秒并提示暂停，不覆盖未结束的尾句、字幕或代码。讨论题、预告和关注句只按本期脚本出现，不编造下一期；不说「下期见」。不存在讲解价值的装饰进度条不进入成片。
10. **封面。** 三种尺寸逐份看：4:3 内容 x 315..1125、底边 y < 918，水印按尺寸规范，字不裁切、不溢出。站点 `meta.poster` 指向检查过的实际文件。
11. **专属条件。** 本期的 DevTools、正文代码、术语、示例数字、点击反馈和停留时长按脚本及 RULES 核对。不要将历史 EP.14 的镜号、组件、180–300 帧或 5152 总帧数套给新片。

当前 EP.14 可用 `check-inputs.py` 检查脚本/音轨哈希、实体音轨、帧数、字幕、术语与封面，再用 `verify-freeze.py` 只读核对冻结字节；其他期按自己的 README。各命令的写入行为见 [validate.md](validate.md)。

## 成片审

1. **实际编码。** 用该期媒体检查入口或 ffprobe 核对分辨率、帧率、帧数、音轨，完整解码无错误。最终帧数以本期片尾或代码附录实现为准，不机械要求与旁白帧数相同。
2. **响度。** 读本期 `remotion/out/mix-report.json` 或经验证的同源副本；记录 `final_LUFS` 和 `true_peak_dBTP`。目标 −16 LUFS、−2.0 dBTP，缺报告或不合格先停。
3. **封面产物。** 16:9、4:3、3:4 的 JPG 与 PNG 按本期脚本实际产物打开；核对裁切、文字和水印。不能只看 spec 或草稿文件。
4. **连续动态。** 看首屏、关键因果步骤、局部放大中间态、返回总览、情景切换、章节衔接和结尾。需要时关闭字幕看动作是否能独立表达因果；端点静帧不代替连续检查。
5. **配音。** 核对句子是否截断、读音及字幕。记录执行者、工具、取样区间和能力限制；没有完成的全片人工听辨、逐字 ASR 不能记为通过。
6. **参考资料附录。** 实际查看每页首、中、末及与正文/代码卡的衔接，核对作者或机构、资料名、版本与清单一致。检查精确首卡无原字幕残留，默认每页5秒；在原生播放器暂停/结束及手机全屏中检查提示和主要资料不被控件遮住，内嵌小窗限制如实记录。
7. **发布副本。** 将检查通过的产物接入站点后，对视频、海报、分镜、字幕相关数据核对完整 SHA-256，并通过 `npm --prefix site run check:references`。新片或旧slug重制/换片后缺资料、实际附录或相符的媒体记录即停止发布；只有未接入附录且视频SHA仍与登记基线相同的旧片可暂缓。按 [publish.md](publish.md) 构建、发版、部署，并核对线上完整媒体 SHA、字幕、章节、海报和更新日志。自动检查不代替原文阅读或实际审片。

实际编码的通用采样命令：

```sh
ffprobe -v error -select_streams v:0 \
  -show_entries stream=nb_frames,r_frame_rate,width,height -show_entries format=duration \
  -of json EPDIR/video.mp4
```

`nb_frames` 为空时加 `-count_frames` 并读 `nb_read_frames`。这项元数据检查不能代替完整解码或观看。

有反馈就按影响范围修正，重新检查受影响部分及必要上线结果；保留原检查范围，不把新源码的检查结果追认给旧视频。
