# Agent系列：开发价值复盘与重排草案

2026-10-25（北京时间）。用户观看A02/v0.59.0后明确反馈“看完好像跟没看一样”“没什么营养”，质疑系列策划，要求更有价值、信息密度更高、更贴近实际开发。本文件记录已发生的问题和新的编辑建议；不是新课程已开发、真实模型已跑通或用户已认可新方案的声明。

## 已核对的问题

目标观众原本就是会基本编程、接口和JSON的开发者。A01已讲过模型选择、程序核对权限和执行、结果回传；A02约110秒又以这条关系收尾。增量主要是一次调用的细分和权限拒绝，缺少足够独立的开发收益。

A02脚本把“真正的查询代码”和“交回模型”作为旁白动作，正文只露一次工具名/参数，关键接线没有展示。文章有更多细节，不能据此认定视频本身已教会实现。配套demo真实运行的是本地HTTP与应用分发；模型请求和最终答复均为固定fixture，无法证明真实模型怎样选工具、提参数及收到结果后继续运行。

上述结论由用户观看反馈及A01/A02实际脚本、demo审计支持。原先73个有效动态阶段、29个正式编码帧和上线检查继续作为技术/可读性证据保存，不能扩称为课程价值或用户认可。

## 策划标准调整

- 开发主线按观众新增的能力组织：实现一个功能、诊断一类故障，或作出有依据的工程选择。先写清产物、关键改动、失败对照和验收，再写标题与分镜。
- “一集一个机制”不等于“一个常识占一期”。相邻内容若不能提供独立增量，就并入同一实践；概念在用到时解释，必要先导保留为补充。
- 提高密度靠删重复叙述，增加关键接线、工程决策和可验证的前后变化。保留场景入口、理解前置和自然节奏，不靠加术语、代码墙、加速或机械拉长。
- 标为实战的模型交互要实际运行；业务数据可以合成、工具后端可以本地搭建，但固定模型响应不能作为已跑通真实Agent的证据。真实/模拟边界继续明确。
- 最小trace与结果核对从第一个可运行例子开始；系统评估可以后面展开，不能等旧A13/A14才第一次确认业务结果。
- 官方资料核对技术主张，编辑审读检查观看收益；两者分别验收。外部文档不替本项目证明某种拆课有效。

## 六个优先开发单元（建议顺序）

这是先制作可运行原型、再决定短片边界的单元草案，不是预定六支固定时长视频。

| 开发单元 | 观众应带走的能力/产物 | 片中需要出现的证据 | 旧选题对应 |
|---|---|---|---|
| 把现有订单API接成一个能跑、能停的Agent | 替换工具定义和执行函数，接通真实模型的工具调用循环 | 实际请求、工具执行、同一call_id回传及最终答复；一处漏回结果/未续跑的修复，具体错误以API实测为准 | A01必要铺垫＋A02/A04合并；A03最小参数契约随用随讲 |
| 把模型回复变成程序能用的工单草稿 | 结构化结果直接驱动预览卡，并做业务校验 | 自由文本难处理；Schema符合但订单/资格不对仍被拦下；拒绝/不完整响应按接口处理 | A03 |
| 接入公司资料，答案能找到依据 | 检索政策文档并保留版本、来源和引用 | 旧/新政策及无答案问题；区分检索没找对和模型没按证据答 | A05/A06 |
| 改了提示词，怎样知道变好了 | 用trace定位错误，用小回归集比较修改前后 | 同一输入、实际工具轨迹、可检查的业务结果和真实失败样例；不凭文案像不像完成评分 | A13/A14前移；基础记录从首单元开始 |
| 让Agent写数据，在哪一步等人批准 | 工单草稿暂停，批准后才向测试系统写入 | 拒绝零写入；批准的内容与实际提交参数一致，权限取自可信会话 | A11 |
| 写到一半进程挂了，重启怎样不重复办事 | 持久任务状态与业务去重 | 在写入后、结果记录前中断，先复现重复，再验证恢复后只有一个有效工单 | A10 |

MCP、Skills、多Agent、记忆、上下文压缩和成本优化继续保留在题库。出现跨宿主接入、复用工作方法、任务协作或具体性能问题时再立项，先比较现有方案与新增机制的实际差异，不因名词流行就各拍一期。

## A02的具体重策划方向

建议替代主题：**《把一个普通API，接成真正能用的Agent》**。开头直接给可操作的成品：输入“查一下订单8124的签收时间”，界面返回实际查询结果，并显示这次调用记录。

随后沿同一输入讲三处关键接线：工具定义让模型知道能请求什么；应用把名称/参数分发给真实函数；执行结果按调用标识提交给下一次模型请求。用实际返回说明循环何时继续、何时停止，应用另外控制步数/预算。完整工程可复现，片中必须呈现这些关键连接，不能继续全部留给文章。

加入一处与接线直接相关的故障和修复，例如漏回工具结果、没有继续请求模型。错误的具体形态由选定API实际返回决定，不提前写成必然胡编、必然死循环。缺订单号时的询问可作为小验收案例；更多分支不塞入同一短片。

当前尚未选择并运行新片的文本模型接口，现有TTS凭据及本地fixture不代表已具备真实模型推理实测。正式制作时再锁定实际可用的接口、模型与SDK版本，并保留真实运行日志。此次不请求TTS、不重渲、不改线上旧媒体。

## 本轮重新联网核验的依据

访问日期均为2026-10-25（北京时间），只采官方原始资料。

1. OpenAI，[Function calling](https://developers.openai.com/api/docs/guides/function-calling)，动态文档。已读How it works、五步调用流程和完整示例：提供工具、模型请求、应用执行、回传输出及继续请求在同一个完整例子里。支持实现关系，不证明本项目拆成几期合理。
2. OpenAI，[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)与[Retrieval](https://developers.openai.com/api/docs/guides/retrieval)，动态文档，研究代理读取正文。格式约束与内容/业务正确性要分开；检索应保留来源。这里仅设计课程，未实测新功能。
3. Anthropic，[Demystifying evals for AI agents](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)，2026-01-09。已读任务、轨迹、最终环境状态及早期评估建议。支持按实际结果验收，不引用文中案例数字作本项目指标。
4. Anthropic，[Scaling Managed Agents](https://www.anthropic.com/research/managed-agents)，2026-04-08。已读会话/运行循环/执行环境的分离、故障诊断及恢复。用作真实工程问题来源，不照搬厂商托管架构或收益。
5. LangGraph，[Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)与[Checkpointers](https://docs.langchain.com/oss/python/langgraph/checkpointers)，动态文档，研究代理读取正文。支持暂停、状态恢复及重放时副作用/幂等问题；不保证接上检查点就自动获得业务恰好执行一次。

另读OpenAI [Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)：支持早评估、任务特定用例及日志。页面同时公告独立Evals平台将于2026-10-31转只读、2026-11-30关闭；新课不以该即将退役平台的API作为默认实现依赖，评估方法与所用工具分开。
