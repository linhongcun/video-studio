## 画面

- 一条主线；机制教学每集聚焦一种实现。画面术语 2–3 个为止。DevTools 和正文代码画面合计最多 2 处，正文只突出当前步骤相关的关键行。
- 算法题解在主线讲解后附独立静态完整代码卡，供观众暂停阅读；它不计入上述正文两处代码画面的限制。程序须完整可提交，与本片解法、配套文章及实际执行源一致，整屏可读并留足停留时间。
- 必要技术名称在对应对象和动作建立后明确点出，可同时显示中文全名与通行缩写（如“CDN · 内容分发网络”），英文缩写按配音规范逐字母读。不因通俗表达省略核心名称，也不在首屏堆术语。

- 数据库整体用可辨识的数据库身份符号与库名配合；内部表格、记录、事务范围、应用和消息继续各自表达。按用户选择使用产品图标时保留素材来源、许可及真实技术边界；标记随对象缩放，不抢占数据和动作。
- 缓存、消息中间件使用可辨识的产品图标时，保留中文角色与实现示例的边界。Redis共享缓存不泛指浏览器、CDN或应用本地内存；Kafka与RabbitMQ按实际保存、消费和确认机制选用，不能因同属MQ就混用。图标只表示组件身份，业务状态、记录与可靠性保证仍分别解释。
- 视频画面内不添加与讲解无关、持续运动的装饰进度条；进度或状态变化须参与当前内容的因果解释。保留播放器供观众操作的原生进度控件。
- 不用比喻，不模拟实物设备，不给机制图套无关的应用外壳。为建立实际使用场景，可以直接展示对应功能的交互界面（如退款咨询对话）；界面操作、信息与结果必须服务本片问题，教学示例不得冒充真实服务执行。
- 题目本身已有可视场景时，直接使用其中的对象、空间和动作建立问题与推导。爬楼梯就演示人在台阶上走一阶或两阶、具体落脚和最后一步的来源；数字、计数与程序随后绑定这些对象。原题场景不是无关比喻，上条不能扩大成“不画人物或楼梯”。场景须参与因果过程，不能只在数字板背后放装饰背景。
- 内容本身是网页、地址栏或 DevTools 时用浏览器壳。讲解用的表、图、流程图用干净全屏 canvas，不套外壳。
- 演示页身深色：`pageBg` `#0F172A`，`pageInk` `#E5E7EB`，定义在 `episodes/_shared/theme/pageTheme.ts`。禁止大面积纯白页身。浏览器框和 DevTools 仍用各期 `remotion/src/theme.ts` 的 `P`。
- 封面 4:3 安全区：内容落在 x 315..1125、y < 918。`episodes/degradation/covers.json` 里对应字段是 `sizes["4x3"].centerRegion` 与 `bottom15Y`。水印走该尺寸的 `watermarkZone`。封面文字不许溢出，检查时不得出现 `COPYFIT`。
- 示例域名用 `.example`（RFC 2606）。画面上的示例数字写明「示例」。

## 开头

- 算法题解默认观众没见过原题。先用可视小例子交代输入、允许选择或操作什么、关键限制、要求找到什么，以及最终返回什么；题意建立后再进入算法。题号、标题或解法内部的悬念不能代替题意说明。开头的冲突应来自题目目标或限制，不能为满足前2秒钩子而跳过这一步。题意示例可以展示预期输出，解法结论在题意建立后展开。
- 算法题意建立后，还要展示选择方法的思考过程：从题目约束、直接尝试或可复用的信息出发，说明为何值得采取这个做法，再引出方法名称与完整步骤。介绍题意、解释现成步骤及证明步骤安全是不同检查项。无需每题套暴力对比或多解列表；遮住算法名仍应能跟着例子理解选择依据。
- 2 秒内同时给出标题和冲突。第一帧就是主体画面，不要黑屏、片头或自我介绍。
- 2–5 秒只升级这个冲突，不提前讲完答案。
- 正文兑现开头的承诺。不为留人牺牲准确。
- 视频围绕选定的讲解主线简短收束；不因配套文章有完整推导，就在片尾追加证明或口头引流。用户2026-10-25明确：P01视频讲七场安排即可，严格最少性证明留文章，视频不展示也不提及。不要把这条结尾反馈扩大成所有视频必须完整证明的要求。事实准确性继续保持，未展开的最优性不在片中另作悬念或证明承诺。
- 开头必须让观众知道这期讲什么、要解开哪个具体问题；不先连续铺范围、常识或术语。每镜服务同一问题的因果推进，结尾直接回应开头，不能用另一个问题的答案收尾。
- 面向不熟悉该技术的观众，先建立“谁在用什么功能、想完成什么事”的场景；适合时直接用对应功能的界面和交互呈现。只出现技术标题或内部流程框，不等于观众已经知道使用情境。

## 章节衔接

- 进入新的主要章节前，用简短口头过渡承接上一段，并说明接下来要看什么、为什么切到这里；不能只换章节标题就直接展开新内容。
- 先给观众理解方向，再启动本节的新动作或细节。过渡长短和说法随内容调整，不机械播章节号，也不为此增加冗长片头。

## 配音

- 音色「冰糖」（`episodes/_shared/tts/mimo_say.py`，模型 `mimo-v2.5-tts`）。
- 成片响度 −16 LUFS。混音脚本 `episodes/_shared/music/mix_bgm.py` 的 `--lufs` 默认就是 −16，真峰值目标 −2.0 dBTP。
- 起音：静音之后第一个摩擦音、爆破音或浊音，阈值 ≥ −45 dB。标签对齐到 onset −6..+2 帧。分镜里的写法是 `max(1, floor(onsetLocal) − 2) + d`，窗口 `[-6, 2]`，见 `episodes/degradation/storyboard.json` 的 `meta.onsetRule`。
- 算法实现是 `episodes/_shared/onset_rule.py`（类 `Rule`）。检查器是 `episodes/_shared/label_onset_strict.py`，只 import 这一份。冻结分镜 `meta.onsetRule.module` 与 `meta.onsetRule.checker` 仍写着仓外路径 `/workspace/video-studio/episodes-codex/_shared/onset_rule.py` 和同目录的 `label_onset_strict.py`，对应仓内这两份，不要再复制。import 见 [voice.md](voice.md) 和 [validate.md](validate.md)。
