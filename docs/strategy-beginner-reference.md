## 新版只兑现一个问题

**同样是结算，怎样替换“怎么算钱”，而让结算按相同方式使用它？**

目标观众懂基本函数调用和条件判断；不预设已经知道函数可以作为参数传递。这一前置概念在本片内用具体例子补齐。

贯穿示例只保留原价100元、会员九折90元、活动八折80元。每次从同一原价重新结算，优惠不叠加。普通价不再占一个策略位置；七五折变更、新客规则、登记表、类型系统、金额校验和其他模式辨析放配套文章。

## 八步讲解安排

| 步骤 | 观众此刻要回答的问题 | 画面及讲解重点 |
|---|---|---|
| 1. 给出问题 | 同一笔订单，变化的究竟是什么？ | 原价100元不变，会员/活动的计算办法不同。先用一句具体例子建立任务。 |
| 2. 看到原写法 | 为什么想把规则与结算分开？ | 两种办法写在结算内部，各自维护时都要进入这段代码；明确少量稳定判断本来可以直接写。 |
| 3. 定义一个策略 | “策略”在本例到底指什么？ | 单独展示会员办法：收原价，算应付价。随后给“会员定价策略”名称，再展示活动办法；先有对象再命名。 |
| 4. 先选办法 | 谁决定这次用哪种？ | 调用结算的代码先选会员，把“会员函数”交过去。选择权有明确位置，结算不会自动猜。 |
| 5. 分清办法与结果 | 交进去的是会员函数还是90元？ | 规则标签始终是名称，金额始终带元/分单位；先传函数，结算调用时才出现90元。解释函数参数。 |
| 6. 换一次办法 | 为什么结算能不改调用方式？ | 同一原价重算，仅把参数换成活动函数，得到80元；两种函数都遵守“原金额→应付金额”的约定。 |
| 7. 回看整体 | 这与普通提取函数有什么区别？ | 不仅把代码分开，还让共同流程接收并调用可替换的办法。把“选择、调用、计算”与已看过的对象一一对应。 |
| 8. 判断取舍 | 什么时候值得这样做？ | 多种算法确实需要独立替换或维护时考虑；只有几条稳定判断时可以保持直接写法。结尾回收“换办法，沿用同一调用”。 |

不是固定八镜模板。真正分镜数量、动作窗口和时长在讲稿审读后按内容确定。章节之间保留简短口头承接，当前重点每次只有一个。

## 可直接审读的旁白草案

**问题与原写法。**同样一笔一百元的订单，会员付九十元，参加活动付八十元。结算这件事没变，变化的是怎么算应付金额。最直接的写法，是在结算里面判断：会员就打九折，活动就打八折。只有这两条稳定规则时，这样写完全可以。我们现在考虑的是，两种计算办法需要各自维护、也需要按情况替换。

**先认识一个策略。**接下来，先把“怎么算”单独拿出来看。会员办法接收原价，按九折算出应付金额；活动办法也接收原价，按八折算出应付金额。在这里，一种独立的计算办法，就是一个定价策略。它们做的是同一件事，都把原金额算成应付金额，所以可以供结算选择使用。

**先传办法，再执行。**办法已经分开了，结算怎么用它呢？调用结算的代码先选好会员办法，再把这个函数交给结算。注意，交过去的是会员函数，九十元还没算出来。函数除了能被直接调用，也可以像其他参数一样传进去。结算的算价参数代表收到的函数。这里收到会员函数，调用算价参数，就是执行会员函数。这时才算出九十元，并把结果返回。

**只换一次，观察不变之处。**现在保留同一笔一百元的原价，重新计算一次。这次把活动函数交给结算。结算还是调用收到的函数，但执行的办法换了，所以返回八十元。这不是在九十元上继续打折。能这样替换，是因为两种办法的约定一致：接收原金额，返回应付金额。

**回看模式与取舍。**回头看，调用结算的代码负责选办法，结算负责调用，具体策略负责计算。把同一任务的不同办法分开，让共同流程按统一约定使用选中的一种，这就是这里的策略模式。重点不仅是多写了几个函数，还在于共同流程能接收并使用可替换的办法。规则确实需要独立变化时，这样安排有价值；规则少而稳定时，直接判断通常更省事。

## 两处核心代码怎样呈现

第一处只解释交进来的内容：

```python
checkout(10000, member)
```

旁边明确“金额单位：分；10000分=100元”。`member`没有跟括号，表示把会员函数交给结算；随后在结算内部调用收到的函数，才得到9000分。讲清这一遍后，原位置只把`member`换为`campaign`，同一原价得到8000分。

第二处才显示结算的核心逻辑摘录，逐行对应刚才的动作：

```python
def checkout(amount, pricing):
    payable = pricing(amount)
    return payable
```

明确标“核心逻辑摘录，校验见配套文章”；不冒充完整生产实现。`pricing`只是接收当前计算办法的参数名，此次传会员函数，它就代表会员函数；传活动函数，它就代表活动函数。完整示例继续使用整数分、现有校验及既有执行证据。上面的两次调用可直接对现有`demo/pricing.py`运行核对。

## 对应的简化画面

本例逐步引入原金额、结算、当前计算办法、应付结果。调用处先用短句或代码指出选择，不再常驻一个独立“调用方”大框。未选中的办法只留短名称，当前不展开其公式和完整卡片。

函数名称与金额有不同的视觉身份：函数始终显示名称，数值始终带单位；输入、计算办法、结果采用稳定颜色。解释参数时先暂停金额动画，依次突出`member`、`pricing`、`pricing(amount)`；它们指向同一个收到的函数，不画成复制出的另一套算法，也不把函数名称变成90元。

会员结果先停住，再口头说明“换活动规则，重新使用原价100元”。清空旧90元，参数改为活动函数，最后重新执行并得到80元。一次只推进一种动作；章节承接先完成，再启动新细节。
